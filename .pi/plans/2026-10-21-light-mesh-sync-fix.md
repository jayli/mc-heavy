# 光照变化的脏 section 传播修正（「灯光有边界」第二次修 + 「删灯后不变暗」）

> 日期：2026-10-21 ｜ Tier：1（调度协议 + 纯函数）｜ 触发：用户复测 v1.64 —— 「还是没有彻底修复，灯光还是有明显的边界」
> + 「把灯删除后，刚才被照亮的方块面不变暗」｜ 前序：`2026-10-21-blocklight-cross-column-fix.md`（v1.64）

## 1. 现象

- 截图 `灯光有边界2.png`（v1.64 提交后 1 分钟）：坐标 (278.5, 0, 160.0)，玩家正好站在 z=160 的 column 边界上，
  沙地上有一条**笔直、轴对齐**的明暗边界；v1.64 只修了 light **数据**，边界还在。
- 新增报告：删灯后，刚才被照亮的方块面不变暗。

## 2. 诊断：三层对照（只差一个变量逐层缩小，哪层第一次出现差异缺陷就在哪层）

脚本只在真游戏页跑（seed 6503358、用户的坐标），`window.__MC_GAME__` + 拦截 `renderWorld.uploadSection`：

| 层 | 比较 | 实测 |
|---|---|---|
| ① 数据层 | 整图参考 BFS（无区域截断）vs 每列 `light` | **0 个格子不一致**；+z 剖面 `15,14,…,1,0` 平滑越过 z=160 |
| ② 网格层 | 实际上传的 packed vs `buildSectionMesh(当前数据)` | **6 个 section 过期**：`16..18 × 9..10`，全是 `sy=1`，opaque 通道 616/956 顶点不一致 |
| ③ 画面层 | 夜景截图（放灯后 / 强制重建后 / 删灯后） | 放灯后沙地**没亮**；强制重建后亮；删灯后沙地**仍然亮**（= 用户报告的第二个症状） |

**结论：数据是对的，网格是旧的。** 这也解释了 v1.64 的 E2E 全绿却没挡住缺陷：它们只断言 `column.light`。

## 3. 根因（三处独立缺口，按发现顺序）

### ① 脏标记漏了 mesher 的真实依赖（v1.64 引入）

v1.64 的 `_onLightResult` 只给「light 字节真变了」的**同 sy** section 置脏，邻列「同 sy」。但 mesher 对 section S 的
light 依赖 = **S 自身 16³ + 六个面外各 1 格厚的 halo**（faceLight 读面外邻格；模板方块读自身格；棱/角 halo 格
只读 blocks 算 AO，不读 light）。沙滩地表在 y=-1 = `sy=1` 的**最上层**，顶面读 y=0 = `sy=2` 最底层那格；
那格变了，地面所在的 `sy=1` 没人通知。受影响列里 `sy=1` 若恰好没有非 opaque 且变亮的格，它就永远不重 mesh →
**部分列亮、部分列不亮，边界 = column 边界**；删灯同理 → 被照亮的面不变暗。
同时对 8 个邻列一律按同 sy 置脏，含根本不依赖本列 light 的对角列（多余的 mesh churn）。

### ② 在途 mesh 回包被版本协议丢弃后无人重发

`_onMeshResult` / `_processUploadQueue` 版本不符只 `return`。而该 section 的脏标记在派发前已被 `takeDirty` 消费，
同 column 的**任何**编辑（哪怕与光无关）`version++` 就能让在途结果作废 → 数据对、画面旧，**偶现**。
真游戏页确定性构造（观察到地面 section mesh 在途 → 同一同步片段内在该 column 空中放一块石头）：修①之后 3/3 仍复现
（`16,1,9` 76/1292 顶点不一致，数据层 0 差）。

### ③ light 回包不校验输入列**集合**

`enqueueLight` 对在途 column 直接跳过，理由是「回包后由版本校验再触发」；但版本校验只比对派发时已有的输入列。
在途期间 3×3 里新到达的就绪列不在 `inputs` 里 → 版本比对看不见它，而它到达时的 `enqueueLight` 又被跳过 →
该 column 永远缺它的光。纯逻辑缺口，RED 单测直接证明（回包后队列 `0,-1|1,-1|1,0|0,1|1,1`，唯独缺中心列）。
真游戏页未观测到（边走边加载 4×648 section 全一致），属于「协议上确定存在、频率很低」的一类，按协议补齐。

## 4. 方案

- `lighting.js` 新增 `lightDirtyMasks(prev,next)`（纯函数，Worker 同构）→ `{self,xm,xp,zm,zp}` 掩码：
  变化格 → 所在 section；`ly==0/15` → 下/上相邻 section；`lx/lz∈{0,15}` → 4 个**正交**邻列同 sy。
  API 里根本没有「对角列」。`scheduler._onLightResult` 按掩码置脏（`_markDirtyByMask`）。
- `scheduler._redispatchDropped(col, sy)`：两个丢弃点（`_onMeshResult` / `_processUploadQueue`）重新置脏。
- `_onLightResult` 第③层校验：3×3 内现已就绪但不在 `inputs` 的列 → 丢弃并重新入队。
- `mesher.js` 的 faceLight 采样处加耦合注释（改采样范围必须同步扩大 `lightDirtyMasks`）。

## 5. 测试（Tier 1：RED → 验证 RED → GREEN → 验证 GREEN）

单测 722 → 741（+19）：

- `test-lighting.js`（+9）：无变化 / 内部格 / ly=0 / ly=15 / 世界上下界不越界 / 四个正交方向各钉一个 / 棱角格无对角列；
  **与 mesher 交叉比对两条** —— pocket 世界（一格空气 + 六面邻格 stone，27 个边界/内部采样格）里「预测集合 == mesher
  实测变化集合」逐项相等 + 棱角格的物理含义钉死；随机稀疏世界里实测变化 ⊆ 预测（将来 mesher 改平滑光照会在这里红）。
- `test-light-writeback.js`（+10）：y=15 地面 + 灯（放灯不亮根因）/ 删灯后地面须重 mesh / 邻列只在边界层变化时置脏且
  只有 4 个正交列 / 内部变化不波及邻列 / mesh 回包过期重新置脏 + 有效回包不置脏 + 上传排队期间过期 + column 已卸载 /
  light 回包输入集合变化丢弃重排 + 一致的回包照常写回。
- E2E `tests/light-mesh-sync.spec.mjs`（+2）：夹具 = 顶面 y=79（= `sy=6` 最上层）的 32×32 整片石头地面，与地形/seed 无关；
  断言落在「上传网格 == 现算网格」；竞态用例在 `scheduler.update` / `_onLightResult` 接缝处挂钩子，确定性构造，
  并有 sanity floor（`fired === true`、litMax ≥ 12、灯下方空气格 light = 14）。

### 负向验证（逐个撤销，全部真 FAIL，且相互独立）

| 撤销 | E2E | 单测 |
|---|---|---|
| ① Y 方向传播（`ly==0/15` 不通知上下 section） | **两条都红**：`litMax=0`、5 个 section 过期，删灯后 `darkAgain=14`（= 用户的第二个症状） | 7 条红 |
| ② `_redispatchDropped` 置空 | 竞态用例红，**Y 方向用例仍绿** | 2 条红 |
| ③ 输入集合校验置空 | —（真游戏页难以构造） | 1 条红，实际队列缺 `0,0` |

每次撤销后均恢复并 `diff -q` 确认还原。

## 6. 修复后的真游戏页复核（同一批复现脚本）

- 放灯 / 删灯后过期 section：**6 → 0**；截图：放灯后沙地直接亮，删灯后沙地与石墙回到夜间暗色。
- 快速连放连删（含混入普通编辑）：间隔 40ms×4 轮 / 8ms×6 轮 / 0ms×6 轮，**0/16 轮不一致**。
- 边走边加载（约 60 格/秒穿城）4 次，每次 648 个 section：数据 0 差、网格 0 过期。
- 放灯 → 存盘 → 刷新页面（GEN 后首次 mesh 路径）：画面与「强制按当前数据重建后」的画面**逐像素相同**（差分 0），×4 次。
- `lightDirtyMasks` 主线程开销 0.02 / 0.026 / 0.043 ms（无变化 / 2000 格 / 8000 格），每次 light 写回一次、每帧至多一次。
