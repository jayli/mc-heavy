# RedCity Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把 Sakura Spawn 模型烘焙成 City 东侧的 RedCity 地标，并在 RedCity 中心出生。

**Architecture:** 离线烘焙（schematic → `redcity.json`，主线程 fetch + broadcast 给全部 Worker）→ region 布局层算落点/`baseY`/`influence`（确定性纯函数）→ GEN 阶段先整形地形（core 全深度实心 + 过渡环台阶钳制 + 吞并相交地标），再光栅化烘焙内容，最后植被按 RedCity 规则避让。全部走既有管线，不新增持久化路径。

**Tech Stack:** 纯 ES2022 ESM + JSDoc（无 TypeScript / 无 bundler）；three r185.1 WebGPU；烘焙脚本只用 node 内置模块（`fs`/`zlib`/`crypto`），**不新增依赖**；测试 Playwright + 浏览器内单测。

**Spec:** `docs/superpowers/specs/2026-10-22-redcity-design.md`（**以 §13 v1.1 为权威口径**；§1~§12 的冲突项已被 §13 逐条取代，映射关系见 §13 各小节标题）

**参考实现（已入库、已验证可复现）:** `docs/superpowers/specs/2026-10-22-redcity-appendix/`

## Global Constraints

- 引擎红线 1~12 全部沿用（见 `AGENTS.md`「不可违反的重构红线」）：数据单一权威、无预生成、重计算离开主线程、单一 meshing 管线、体素 DDA、Worker 池 + 版本协议、Worker 同构纯函数（`src/gen/**` 不得 import three）、WebGPU 唯一后端。
- `src/gen/**` 与 `src/workers/**` 是 Worker 同构层：**不得 import three、不得自建 Worker**（`npm run check:arch` 强制）。
- 依赖方向单向：`voxel ← gen ← mesh ← render`；`core/` 是装配层，依赖任何层合法。
- 纯 JavaScript ES2022 + JSDoc，禁止 TypeScript、无编译/转译、无 bundler。
- 端口 8081；Conventional Commits（`feat:` / `test:` / `chore:` / `perf:`）。
- **`CAPACITY` 是对「冻结值」的变更**（spec §13.7.5）：**U1 已批准方案 A**（148.06 → 177.53 MiB）。
  仍须先改设计文档 §4.10 与修订说明，再改代码（本仓库规则：设计先于代码）。
- 世界几何：`WORLD_MIN_Y = -32`、`WORLD_MAX_Y = 96`（上界独占）、`SEA_Y = -2`。
- RedCity 常量唯一权威 = `region-config.js`；烘焙产物记录其值，`check:data` 比对。
- 离线烘焙产物必须有输入指纹门禁（`check:data`），防静默过期（`icons` / `zombie` / `turret` / `nightsky` 四个先例）。
- **Tier 1 改动必须 TDD**（RED → 验证 RED → GREEN → 验证 GREEN）；Tier 2/3 免 TDD 流程。
- 每个任务结束必须 commit；**未获明确指令不得自动提交到远端**。

## Review Focus

以下五类问题没有单个任务的测试能直接覆盖，但最可能咬到真人用户。每个都在指定任务里加了对应测试。

1. **transparent 通道余量只剩 13%** — U3（粉色玻璃也用 `glass_block`）后稳态 reserved 261,055，
   占已批准的 300K 容量的 **87%**（A/B 实测，spec §13.5.1）。后续给 RedCity 加任何 water/glass
   都会撞破。Task 9 的预算门禁必须钉住这个数，且 Task 11 的 Tier 4 要复测。
2. **`redCity` 只走 3×3 查询域 → 世界东侧 >x=799 的部分被静默截成直边** — 60/80 个 seed 会触发。用户看到的症状是「RedCity 右边少了一条」，不像 bug 像设计。Task 5 的 T2 用越界 seed 专门钉它。
3. **植被阶段往 RedCity 里乱长** — 实测 seed=12345 有约 2,120 株植物 + 125 棵树落进岛内，48% 悬空、14% 覆盖壳体。玩家看到「塔里长出草」。Task 7 的 T4 用真实 GEN 多 seed 钉它。
4. **建筑被逐列压缩剪切变形** — 塔座周围地面起伏实测 8~23 格，逐列平移会让建筑内部错位 5~15 格。规格要求刚性平移（I5/I6），但「看起来还行」的实现很容易退化成逐列。Task 1 的 bake 单测 + Task 6 的 I5 断言钉它。
5. **出生点在塔顶 / 树冠上** — v1.0 的「上方 2 格空气」弱判据选中过 `168:2` 屋顶块。玩家一出生就掉下来或卡在屋顶。Task 8 的严格判据（上方 24 格全空）钉它。

**写盘前断言不变量**（spec §13.4.2 / §13.4.4，实现已在附录 E 的 `assertInvariants`）：

```
I1 岛外相邻 abs(Δground) ≤ 1        → stats.outsideAdjMax <= 1
I2 矩形边界一圈 ground == 0          → stats.borderNonZero === 0
I3 岛内 ground ≥ GROUND_FLOOR        → stats.groundMin >= -5
I4 烘焙期半：dyMax ≤ 预算            → stats.dyMax <= REDCITY_DY_MAX_BUDGET (87)
   （另半在 Task 3 的布局期：baseY <= REDCITY_BASE_Y_MAX 且 baseY + dyMax < 96）
I5 建筑体相邻块相对高差保持（**占比**）→ contactBreaks / verticalContacts < 0.001
I6 建筑 footprint 内 ground 极差 ≤ 1  → 逐连通体检查
```

任一不成立 → `process.exit(1)` 并打印该不变量与实测值。

⚠️ **I4 必须拆两半**：`baseY` 是布局期按 seed 算的，烘焙期不知道它。只写烘焙期那一半会漏掉
「baseY 意外变大」的情形。两半合起来才等价于完整 I4（附录 E 的 `REDCITY_DY_MAX_BUDGET` 注释）。

⚠️ **`WORLD_MAX_Y = 96` 是独占上界**（合法 y 最大 95），故预算须满足
`BASE_Y_MAX + DY_MAX_BUDGET <= 95`，**不是 `< 96` 就算对**。`assertInvariants` 里有一条
「常量自相矛盾」检查钉这条。

⚠️ **I5 的口径是占比而非绝对 0**：实测 `contactBreaks = 84 / verticalContacts = 151,392 = 0.055%`，
都发生在连通体 footprint 边缘（涂色地面与分量 S 的交界处），是刚性平移的固有产物，不是缺陷。
**写成 `contactBreaks === 0` 会让正确的实现永远 FAIL。**

export function buildRedCityLayout(seed, city) {
  const core = {
    minX: city.maxX + 1 + REDCITY_GAP,
    maxX: city.maxX + REDCITY_GAP + REDCITY_SIZE.X,
    minZ: Math.round(city.centerZ - REDCITY_SIZE.Z / 2),
    maxZ: Math.round(city.centerZ - REDCITY_SIZE.Z / 2) + REDCITY_SIZE.Z - 1,
  };
  const influence = {
    minX: core.minX - REDCITY_TRANSITION, maxX: core.maxX + REDCITY_TRANSITION,
    minZ: core.minZ - REDCITY_TRANSITION, maxZ: core.maxZ + REDCITY_TRANSITION,
  };
  const baseY = estimateBaseY(core, seed);
  return { core, influence, baseY, size: { ...REDCITY_SIZE } };
}
```

export function ringMaxDelta(edgeDistance) {
  return Math.floor(Math.max(0, REDCITY_TRANSITION - edgeDistance) / 3);
}
export function getRedCitySurfaceY(wx, wz, redCity, seed) {
  const info = getRedCityInfo(wx, wz, redCity);
  const e = Math.max(generateHeight(wx, wz, seed), SEA_Y + 1);
  if (!info) return e;
  if (info.zone === 'core') return redCity.baseY + groundAt(redCity, wx, wz);
  const d = ringMaxDelta(info.edgeDistance);
  return e + Math.max(-d, Math.min(d, redCity.baseY - e));
}
```

`groundAt` 从注入的烘焙模型读 `ground[oz*W+ox]`；模型未注入时返回 0（退化为 `baseY`），并在注释里写明这是防御路径。

export function landmarkErased(kind, center, redCity) {
  const fp = REDCITY_LANDMARK_FOOTPRINT[kind];
  if (!fp) return false;
  const b = { minX: center.cx - fp.halfX, maxX: center.cx + fp.halfX,
              minZ: center.cz - fp.halfZ, maxZ: center.cz + fp.halfZ };
  const r = redCity.influence;
  return !(b.maxX < r.minX || b.minX > r.maxX || b.maxZ < r.minZ || b.minZ > r.maxZ);
}
