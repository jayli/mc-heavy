> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把 Sakura Spawn 模型烘焙成 City 东侧的 RedCity 地标，并在 RedCity 中心出生。

**Architecture:** 离线烘焙（schematic → `redcity.json`，主线程 fetch 一次，把**原文**广播给全部 Worker）→ region 布局层算落点/`baseY`/`influence`（确定性纯函数，**随每个 `gen` 任务全局下发**，不走 3×3 查询域）→ GEN 阶段先整形地形（core 全深度实心 + 过渡环台阶钳制 + **整体**吞并相交地标），再光栅化烘焙内容（世界 y = `baseY + dy`），最后植被按 RedCity 规则避让。全部走既有管线，不新增持久化路径。

**Tech Stack:** 纯 ES2022 ESM + JSDoc（无 TypeScript / 无 bundler）；three r185.1 WebGPU；烘焙脚本只用 node 内置模块（`fs`/`zlib`/`crypto`），**不新增依赖**；测试 Playwright + 浏览器内单测。

**Spec:** `docs/superpowers/specs/2026-10-22-redcity-design.md`（**权威口径：§14（v1.2）> §13（v1.1）> §1~§12**；§14 逐条订正了 v1.1 的说法，编号 C1~C18 与下面的修订说明一一对应）

## Global Constraints

- 引擎红线 1~12 全部沿用（见 `AGENTS.md`「不可违反的重构红线」）：数据单一权威、无预生成、重计算离开主线程、单一 meshing 管线、体素 DDA、Worker 池 + 版本协议、Worker 同构纯函数（`src/gen/**` 不得 import three）、WebGPU 唯一后端。
- `src/gen/**` 与 `src/workers/**` 是 Worker 同构层：**不得 import three、不得自建 Worker**（`npm run check:arch` 强制）。
- 依赖方向单向：`voxel ← gen ← mesh ← render`；`core/` 是装配层，依赖任何层合法；**`tools/` 可以 import `src/`，反向禁止**（`src/` 不得 import `tools/`）。
- 纯 JavaScript ES2022 + JSDoc，禁止 TypeScript、无编译/转译、无 bundler。
- 端口 8081；Conventional Commits（`feat:` / `test:` / `chore:` / `perf:`）。
- **`CAPACITY` 是对「冻结值」的变更**（spec §14.7）：**U1′-a 已由用户确认**；设计先于代码——Task 0 先改设计文档，Task 8 才改代码。
- 世界几何：`WORLD_MIN_Y = -32`、`WORLD_MAX_Y = 96`（**独占**上界，合法 y 最大 95）、`SEA_Y = -2`。
- RedCity 常量唯一权威 = `region-config.js`；烘焙产物记录其值，`check:data` 比对；`tools/` 从那里 import。
- 离线烘焙产物必须有输入指纹门禁（`check:data`），防静默过期（`icons` / `zombie` / `turret` / `nightsky` 四个先例）。⚠️ 指纹**不覆盖算法**（改算法而不动参数时指纹不变）——那一类由 `tests/redcity-bake.spec.mjs` 的黄金比对兜底。

## Review Focus

以下问题没有单个任务的测试能直接覆盖，但最可能咬到真人用户。每个都在指定任务里加了对应测试。

1. **容量真的够吗（U1′）**——RedCity 不是「方块总数陡增」（出生点顶点总量只比 City 高约 6%），而是把顶点从 cutout 挪到了 opaque / transparent，而缓冲是三个通道各自一块固定容量（spec §14.7）。稳态（U1′ 容量）opaque 78.2% / cutout 25.2% / transparent 70.1%；无碰撞飞越峰值（4 个 seed × 6 路线取最大）opaque 92.4% / cutout **92.6%**（seed 12345 东南角，自然森林驱动）/ transparent 83.1%（seed 777）。余量都只有 7~17%：Task 9 的预算 spec 钉 ≤ 95% 且零扩容，**多 seed** 而不只 12345。
2. **`redCity` 只走 3×3 查询域 → 世界东侧 x>799 的部分被静默截成直边**——60/80 个 seed 会触发。用户看到的是「RedCity 右边少了一条」，不像 bug 像设计。Task 5 的单测 + Task 9 的 E2E（断言 x>799 的 core 列是 clay）钉它。
3. **植被阶段往 RedCity 里乱长 / 被吞并地标处长出悬空树**——实测 seed=12345 约 2,120 株植物 + 125 棵树落进岛内；被吞并的冰山处 60 个 seed 里 46 个出现悬空雪桦树。Task 7 用真实 GEN 多 seed 钉它。
4. **建筑被逐列压缩剪切变形**——塔座周围地面起伏实测 8~23 格，逐列平移会让建筑内部错位 5~15 格。**旧 I5 对此完全无感**（注入逐列平移后读数反而更好）；Task 2 的**严格 I5**（同一刚性分量内部保形）钉它。
5. **出生点在塔顶 / 树冠上**——v1.0 的「上方 2 格空气」弱判据选中过 `168:2` 屋顶块。Task 2 的出生点判据（上方 24 格全空 + 5×5 平整 + 不贴墙）+ Task 9 的 E2E 钉它。
6. **放挖 p95 超冻结值（R15）**——RedCity 出生点单块放/挖 p95 2.4~2.5 ms > 冻结的 2 ms。不是 bug，是出生点周围的 section 更密；用户裁定**选 A 接受**：本计划**不放宽冻结断言**，把它 pin 在 City，另立 RedCity 口径的观测用例（阈值 3.5 ms，Task 9 Step 4）。
7. **既有 spec / bench 的语义漂移**——`?spawn=city` pin 清单（Task 9）是实测出来的，不是猜的。
