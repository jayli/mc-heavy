# 左下角迷你区域地图（Minimap）实施计划

日期：2026-10-29
分级：**Tier 1**（新增机制：区域分类纯函数 + 新的数据派生口径）→ 纯函数部分按 TDD 走；
DOM/画布部分属 **Tier 4**（观感类，必须像素级实测，不能只宣称目视）。

---

## 0. 需求（用户 2026-10-29 原话）

> 我想在页面的左下角放置一张迷你的地图，地图来标明玩家所在的位置，玩家移动的时候，在地图上也随之
> 移动。迷你地图里细节不必太多，只需区分出所在的区域是什么类型的 Map 即可，比如 City、沙漠、
> 草地、高台地带、森林、沼泽、杜鹃花丛林等等。上北下南左西右东，玩家在地图的中心，用一个点来表示。

拆成可验收的四条：

1. **位置**：左下角，不进模态、不吃鼠标（`pointer-events:none`）；
2. **内容 = 区域类型**，不是地形贴图：城市 / 草地 / 森林 / 沙漠 / 沼泽 / 杜鹃丛林 /
   雪原 / 高台地带 / 水面；
3. **上北下南左西右东**：屏幕向上 = 世界 −Z（Minecraft 北），向右 = 世界 +X；
4. **玩家恒在中心，用一个点表示**；移动时地图内容随之移动（不是玩家点在图上跑）。

## 1. 现状与约束

- 区域类型全部是 **seed 的纯函数**（红线 2：世界无边界、确定性生成）→ 地图**不读 column 方块**，
  玩家飞到任何未加载的地方都能立刻画出正确的地图。这是本设计最重要的性质：它不需要 GEN，
  因此不引入任何加载依赖、也不需要第二种"地图数据"缓存。
- 判据必须**复用既有权威**（红线 1），不写第二份：
  | 区域 | 权威 |
  |---|---|
  | 城市 bounds | `city` 布局（`buildCityLayout`，主线程已有 Worker 算好的那份） |
  | 高台地带 | `isTarnZone` / `tarnZoneCenter` / `inTarnRadius`（`tarn-zone.js`） |
  | 雪原 | `getRegionSeededCenter` + `LANDMARK_OFFSET.SNOW_LAND_*`（与 `getSnowLandInfo` 包围盒同推导，单测交叉验证） |
  | 水面 | `generateHeight < SEA_Y`（与 `fillColumn` 水体判据同源） |
  | 其余 | `getBiome` |
- 主线程预算：`getBiome` 实测 26ns/次、`generateHeight` 27ns/次 → 61×61 = 3721 个样本
  ≈ **0.2ms/次重绘**。重绘节流到 10Hz（仅在移动时）→ 约 2ms/秒 ≈ 0.17% 帧预算。
- 分层：`src/ui/**` 不在 `check:arch` 的 LAYER_ORDER 里，可 import gen/render 的纯函数模块；
  分类模块本身**无 DOM、无 three**（可在浏览器单测里直接驱动）。

## 2. 设计

### 2.1 采样几何（方向由这一处定义）

- `MINIMAP_SAMPLES = 61`（**奇数**→ 中心样本恰好是玩家所在格）、`MINIMAP_BLOCK_STEP = 8`
  → 视野跨度 `(61-1)*8 = 480` 格（约 1.2 个 region，够看出区域边界）。
- 样本 `(i, j)` → 世界格 `floor(cx + (i-mid)*8)`、`floor(cz + (j-mid)*8)`，`mid = 30`。
  `j` 从 0（上）到 60（下），`j` 减小 = z 减小 = 北 ⇒ **上北下南**由这一条公式保证。
- 渲染：61×61 的 `ImageData` 直接用 CSS `image-rendering: pixelated` 放大到 **122px**
  （每个样本 2 CSS px）→ 像素风、零缩放模糊、`putImageData` 一次写入。

### 2.2 分类与配色

| kind | 颜色 (sRGB) | 判据优先级 |
|---|---|---|
| CITY | `#96928c` 灰 | ① 城市 bounds 内 |
| TARN | `#b07c3e` 赭 | ② 任一地带圆内 |
| SNOW | `#e2ecf2` 近白 | ③ 任一雪原方形内 |
| WATER | `#234e7c` 深蓝 | ④ `generateHeight < SEA_Y` |
| PLAINS | `#7cb04a` 草绿 | ⑤ `getBiome` |
| FOREST | `#2a5e34` 深绿 | ⑤ |
| AZALEA | `#b06ea8` 粉紫 | ⑤ |
| SWAMP | `#6e6438` 卡其 | ⑤ |
| DESERT | `#d6be84` 沙 | ⑤ |

每个样本按 `((wx>>3)+(wz>>3))&1` 做**世界锚定**的两级明度抖动（−10/通道）——不然城市
（bounds 可达 566 格 > 视野 480）在出生点会是**一整块死灰方框**，观感像坏了。世界锚定保证
玩家移动时纹理跟着世界走（不会爬行）。

### 2.3 玩家点

- 独立的 overlay 画布（`122*dpr`，dpr 上限 2）叠在底图上方：白色实心圆点 + 深色描边，
  **恒在画布正中**；
- 附加一条 9px 的**朝向短刺**（`yaw=0` → 屏幕向上 = 北）+ 顶部一个 `N` 字。
  （用户只要求"用一个点"，朝向刺是极小的增量，删起来是一行。）

### 2.4 重绘与节流

- 底图只在「位置变化 ≥ 0.5 格」或「城市布局引用变了」时重绘，且**最快 10Hz**；
- overlay 在位置或朝向变化（> 0.02 rad）时重绘，最快 20Hz；
- 区域上下文（城市/地带/雪原清单）按 region 窗口 key 缓存 —— 每 100+ 格才换一次，
  避免每次重绘都付 `snowLandSuppressedByTarn` 的代价。

## 4. 验证

**Tier 1（纯函数，TDD）**：`src/tests/test-minimap.js` 的 RED→GREEN + 负向验证
（把 z 映射翻成 `+`、把水面阈值改成 `>`、把 `inTarnRadius` 换成半径 0 等注入必须真 FAIL）。

**Tier 4（像素）**：`tests/minimap.spec.mjs`
1. 元素在左下角、尺寸 122px、`#hud-root` 子节点、可见；
2. 底图中心样本色 == Node 侧独立算出的「玩家所在格」颜色（出生点 CITY / 瞬移到高台地带 = TARN /
   真实沙漠点 = DESERT / 真实海面 = WATER）；
3. **上北下南**：站到城市南边界上，顶行是 CITY 而底行不是（注入 z 反向必 FAIL）；
4. 玩家点恒在 overlay 正中（中心像素近白）；
5. 移动 100+ 格后底图像素显著变化（地图随之移动），中心样本色跟着换成新位置的区域色；
6. `lastDrawMs` 有上界（防 O(n²) 退化写法）。
