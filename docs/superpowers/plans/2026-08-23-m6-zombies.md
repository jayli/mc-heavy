# M6 丧尸 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 交付受 M5 管理、可被 M4 三把枪命中、追逐玩家并在死亡/卸载时对称回收的临时丧尸。

**Architecture:** `ZombieService` 将纯状态注册为 M5 的 `zombie` type；既有 WorkerPool 每 0.05 秒以一条
`ai` RPC 返回意图，主线程继续做 60Hz 碰撞。`ZombieRenderer` 把 pose 上传到六个固定 InstancedMesh；
M4 控制器比较实体 AABB 与 DDA 方块的最近命中，绝不使用 Raycaster。

**Tech Stack:** ES2022 ESM、JSDoc、既有 WorkerPool、three.js r185.1、Playwright。

**Spec:** `docs/superpowers/specs/2026-08-23-m6-zombies-design.md`

## Global Constraints

- 依赖 M4、M5 已验收；丧尸为临时 entity，默认上限 20，不写 `entities` snapshot。
- 本 Epic 没有 `PlayerVitals`、近战、攻击冷却、玩家死亡/重生、掉落、自然刷怪或寻路网格。
- 地形读/碰撞走 typed `world.isSolid()`，地形命中走 DDA；禁止 Raycaster、主线程 BFS、每尸 Worker RPC、GLB 和每尸 Group。
- AI 只在距玩家不超过 60 格时参与，每 0.05 秒一条批量 RPC；column 卸载才销毁临时丧尸。
- 所有测试先 RED 后 GREEN；提交仅在用户明确授权时执行。

  浏览器 spec 用玩家当前位置生成合法测试 spawn，而不是绝对 `[0, cameraY, -2]`：

  ```js
  function legalSpawnNear(g, distance) {
    const p = g.player.physics.pos;
    const y0 = Math.floor(p.y);
    for (let r = distance; r <= distance + 12; r++) for (const [dx, dz] of [[r, 0], [-r, 0], [0, r], [0, -r]]) {
      for (let y = y0 - 4; y <= y0 + 4; y++) {
        const x = Math.floor(p.x) + dx, z = Math.floor(p.z) + dz;
        if (g.world.getBlockId(x, y, z) === 0 && g.world.getBlockId(x, y + 1, z) === 0 && g.world.isSolid(x, y - 1, z)) return [x + .5, y, z + .5];
      }
    }
    throw new Error('no legal zombie fixture position');
  }
  ```

  将它作为 `page.evaluate()` 内 helper 使用，断言合法 spawn 后 AI batch 可观测；不要把这个 helper 作为玩法 API。
