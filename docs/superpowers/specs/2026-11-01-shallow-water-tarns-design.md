### 2.2 「平顶」判定（R7 的依据）

「平顶」不能只看最高层数，也不能只看台面占足迹的比例 —— 实测大部分分量是**乱石堆**。
判据 = 「同高层的最大 4-连通块的列数」，以及「顶部 4 格内的列占比」。

| 分量 | 尺寸 | 格数 | 最大平顶块 | 占足迹 | 顶部 4 格内 |
|---|---|---|---|---|---|
| comp#1 | 65×56×71 | 59,760 | 193 @y12 | 4% | **1%**（塔形，非平顶） |
| comp#4 | 63×13×53 | 23,060 | **861** @y12 | 26% | 99% |
| comp#6 | 52×13×54 | 19,781 | 625 @y12 | 22% | 99% |
| comp#9 | 31×12×48 | 12,461 | **548** @y12 | 37% | 100% |
| comp#16 | 27×12×22 | 4,600 | 211 @y11 | 36% | 100% |

**4 个「平顶」候选**（comp#4/6/9/16，顶部 4 格内 ≥99% 的列）。用户选了 `comp#9`：
它是**平顶占自身足迹比例最高**（37%）且尺寸中等的一座 —— 太小的 comp#16 看不出「平顶」，
太大的 comp#4 会挤掉最大那座的空隙。

### 2.3 落点可行性（R1 / R11 的硬数据）

**天然地形不会给出浅水洼**（这条推翻了我的初版假设）：扫 3 个 seed、x∈[640,2600] ×
z∈[-900,900]（步长 60）的全部候选点，要求「湖半径 240 的圆外 60 格环带 97% 干燥」——
**零个点满足**，最高只有 84%。根因是基础地形噪声波长约 78 格、`SEA_Y = -2` 恰在中位
→ 大范围都是半湿半干。**故湖区地形必须自己整形**（§5）。

落点只需排除**固定占位物**（这与城门竞技场的「抑制型而非避让型」是同一裁定）：
城市 bounds / 地标圆 / 高台地带 / 巨型金字塔。实测 10 个 seed 全部能在城东找到合法位置
（净空按 `湖半径 + 宽缓坡半径` 计，城东距离落在 190~900 格区间）。

### 2.5 渲染预算（真实 mesher 实测，不是估算）

在 9×9 chunk 的整片平底浅水湖上跑**真实 `buildSectionMesh`**（逐 section、真实面剔除）：

| | 每 column（湖心） | 视距 8 全湖视域（289 列） | 当前上限 |
|---|---|---|---|
| opaque | 2,048 顶点 | **0.59M** | 4.275M ✅ |
| cutout | 0 | 0 | 2.20M ✅ |
| **transparent** | **1,024 顶点** | **0.296M** | **0.125M ❌** |

> ⚠️ **初版估算错了 2.4 倍**：我按「每格水面 4 顶点 × 18 万格」算得 72.4 万顶点，
> 而实际 mesher 让**湖底沙面互相剔除**、只发射湖岸一圈竖面 —— 真实值是 29.6 万。
> 这正是一条既有约束的实例：「Node 侧估算先确认口径，别用『每格都发面』的假设」。

**结论**：`CAPACITY.transparent.active` 100 → **240**（`maxVerts` 125,000 → 300,000）。
三通道静态内存 188.61 MiB → **193.62 MiB**，仍 < `m3-fullscene` 的 200 MiB 门（余量 6.4 MiB）。

## 3. 高台烘焙（`tools/bake-shallow-tarns.mjs`）

### 3.1 产物

5 个 JSON（`assets/structures/shallow_tarn_01..05.json`）+ 1 个 meta
（`shallow_tarns.meta.json`，含尺寸、格数、源方块普查、输入指纹）。

命名按**角色**而非分量序（`01` = 最高、`02` = 平顶、`03`~`05` = 中小），
这样调换选型时产物语义不变：

| 产物 | 角色 | 源分量 |
|---|---|---|
| `shallow_tarn_01` | tallest | `comp#1` |
| `shallow_tarn_02` | flat-top | `comp#9` |
| `shallow_tarn_03` | mid | `comp#10` |
| `shallow_tarn_04` | mid | `comp#12` |
| `shallow_tarn_05` | small | `comp#20` |

### 3.2 烘焙要点

- **剔除 y=0 基座**（与 Cloudland 同手法），再按 26 连通分量。
- **原点**：水平包围盒中心 `OX = x0 + floor((x1-x0)/2)`、`OZ` 同理；**y 归一化到 1**
  （最低点 = 1，满足 `rasterizeStructure` 的 `y + b.y - 1` 约定）。
- **尺寸断言**：产物 bbox 必须等于源分量 bbox（防原点算错导致整体偏移）。
- **未知源方块必须 throw**（`makeColumnSetter` 对未注册名字是**静默 return** → 那格变 air）。
- **格式**：`{version, palette, blocks: [x,y,z,paletteIndex, ...]}`（4 项 / 无朝向）。
  素材没有需要朝向的方块（无台阶/门/栅栏），**不需要 stride 5**。
- **`grass_block` 分流**（R15）在**光栅化期**做，不在烘焙期做 —— 见 §6.3 的理由。

### 3.3 指纹门禁

`tools/shallow-tarns-fingerprint.mjs` 提供 `BLOCK_MAP` / `CONTAINER_LAYER_Y` /
`PRODUCED_TARNS` / `shallowTarnInputFingerprint()`，供烘焙脚本与 `check:data` 的
`[浅水高台]` 环节共用（红线 1）。指纹覆盖 `.schem` 内容 + `BLOCK_MAP` + 五个分量的分量序。

## 4. 落点（`computeShallowWaterTarnAnchor`）

`src/gen/structures/shallow-water-tarns.js`，与 `computeArenaAnchor` 同构（纯函数 + seed 缓存）。

### 4.1 判据（全部满足）

1. **整个湖（含沙滩）都在 City 东侧**：`wx - (LAKE_RADIUS + BEACH_WIDTH) >= cityBounds.maxX`。
   ⚠️ **用硬净空半径 262，不用 `OUTER_RADIUS` 342**：缓坡只做高度插值、不把地标变成
   本地图的一部分。把缓坡算进净空会让通过率从「10 seed 全中」掉到 **0 个**（几何必然：
   半径 342 的圆面积 36.7 万格 = 2.3 个 region）。
2. **不与城市 bounds 重叠**：圆到 AABB 净距 > `CITY_TRANSITION_SIZE`。
3. **不与高台地带 / 城门竞技场重叠**（这两类必须**避让**：它们是同级别的「地基级大结构」，
   选点前就得排除）。

### 4.1b 地标：**压制**而不是避让（实施期实测的关键裁定）

`regionLandmarkCenters` 每 region 返回 2~4 个圆 + 雪原一个，而 region 边长仅 400 格；
湖硬半径 262 的面积 21.5 万格 **>** region 面积 16 万格 ⇒ 圆几乎必然压到至少一个。
实测「把地标全列进避让表」的通过率约 **0.2%**（10 seed 全部失败）——盲搜无解。

✅ 正解 = 照高台地带 `tarn ? null : …` 的手法把落点区的地标压成 null。
**唯一实现 = `shallowTarnSuppressedLandmarks(anchor, regionX, regionZ, seed)`**。

⚠️⚠️ **判据是「该地标中心是否在湖的硬半径内」，不是「本 region 是不是圆心 region」。**
湖直径 212（v2.14；初版 524）跨 1~2 个 region，按 region 判会**同时错两头**：压掉一个本来没冲突的地标，
又漏压真正冲突的那些。前者被 `test-tarn-zone.js` 的「非地带且雪原未让路的 region
逐字段零回归」当场拓到（`region(4,-1)` 的 pyramid 合法为 null，而它根本不相交于湖）。

⚠️ **`snowLand` 字段永不置 null**（6 处消费方直接解引用 `.cx`，置 null 会抛 TypeError）——
雪原的压制走 apply 阶段的跳过门，与 `snowLandSuppressedByTarn` 同手法。

### 4.2 搜索顺序（确定性）

从 `(cityBounds.maxX + 湖外缘净空, 城市 z 中线)` 开始：

```
for gap in 0 .. SHALLOW_TARN_MAX_GAP step 20:          # 向东推进
  for dz in [0, -40, 40, -80, 80, -140, 140, -200, 200]:  # 纬度小幅偏移
    候选 = (cityBounds.maxX + lakeOuter + gap, cityZCenter + dz)
    第一个满足 §4.1 全部判据的 → 返回
```

- `lakeOuter = 湖岸最大半径 + 沙滩宽 + 宽缓坡宽`（v2.16：`LAKE_RADIUS_MAX`(88.3) + 7 + 24 = **119.3**；v2.15 曾是 139.3）
  → 保证整个整形区在城东。⚠️ **必须用最大半径**（谐波上界 `LAKE_RADIUS + Σamp`），
  用名义半径会让凸出的那半边湖压进城市过渡带。
- **不判**「天然地形是浅水」—— §2.3 已证明做不到，且地形由 §5 从零整形。
- **不判**「占地内有无撒布/树/巨树/杜鹃」—— 那些由本结构反向让路（`pointContext` 的
  `kind:'none'` 一个分支覆盖全部五个下游消费者，与竞技场/金字塔同手法）。
- 缓存 64 项（`seed → anchor`），提供 `clearShallowTarnCache()` 供单测隔离。
- 搜不到返回 `null`（不阻断 GEN）。

## 5. 地形整形（`src/gen/structures/shallow-water-terrain.js`）

### 5.1 三段的几何（v2.15：边界不规则 + 接壤水系，见 §14.2 / §14.3）

| 带 | 到湖岸的距离 `e = d − R(θ)` | 地表高度 | 材质 |
|---|---|---|---|
| **湖盆** | `e ≤ 0` | 恒 `SEA_Y - 1`（= -3；顶面 -2） | `sand` |
| **沙滩** | `0 < e ≤ BEACH_WIDTH`(7) | 从 `SEA_Y-1` 线性到 `midY`（**干态 = `SEA_Y+2`**，3 格/7 格 = 0.43 格/格）| `sand` |
| **宽缓坡** | `7 < e ≤ 31` | 从 `midY` 线性插值到**平滑后的自然高度** `hS` | 天然材质；该列在水下时铺 `sand` |

`d` = 到湖心距离，`R(θ)` = 径向谐波（§14.2）。

**干湿两态**（`hS` = 半径 8 均值的自然高度）：

| 态 | 判据 | `midY` | 结果 |
|---|---|---|---|
| **干（沙滩）** | `hS ≥ 0` | `SEA_Y+2` | 与 v2.11~v2.14 **逐位相同** |
| **湿（接壤水系）** | `hS ≤ SEA_Y-1` | `hS` | 沙滩带成了**水下坡**，两侧水面直接连通 |
| 过渡 | `SEA_Y-1 < hS < 0` | `lerp(hS, SEA_Y+2, smoothstep(...))` | 海岸线附近连续过渡（无台阶） |

⚠️ **干湿判据只读平滑高度 `hS`，不读真实 `generateHeight`**：实测把真实高度掺进来
（`min(hS, hNat)`）会让沙滩端点逐格跳 1 格 → 实测出现 **2 格台阶**（seed 1 / ang 54 / d 111）；
只用 `hS` 时 7 seed × 180 方位逐格实测最大单步 **= 1**。细节见 §14.3。

水面由 `fillColumn` 的常规水体填充承担（§5.2），不需要额外写水。

### 5.2 水体为什么天然就是「一格深、水面在半格」

- 湖底**方块**在 `y = SEA_Y-1`，其顶面在 `SEA_Y`。
- `fillColumn` 的判据是 `(h, SEA_Y]` 填 `water`，这里 `h = SEA_Y-1` → **只填 `y = SEA_Y` 这一格**。
- mesher 的 `WATER_SURFACE_SINK = 0.5`：水面方块上方无覆盖时，顶面下沉 0.5 → 水面停在
  `SEA_Y + 0.5`；**与海面平面 `WATER_LEVEL_OFFSET = SEA_Y + 0.5` 严格共面**。
- ⇒ 水深 = 水面 `SEA_Y+0.5` − 湖底顶面 `SEA_Y` = **0.5 格**（R3 用户裁定），
  且与天然水湾**完全同一机制**（用户原话「那个怎么实现的你就怎么实现」）。

### 5.3 为什么缓坡不会变成断崖（实施期实测修正）

外坡用 `slopeNaturalHeight(wx, wz, seed)`：半径 8 的**均值**平滑。

- 本仓自然地形相邻高差实测：82.5% 为 0、17.1% 为 1、其余 <0.3%，**最大 11 格**。

**⚠️ 实施期发现三个必须记录的实测结论（初稿的「复用高台地带手法就够了」不成立）：**

1. **平滑高度的缓存键必须是精确坐标，不能降采样。**
   初版为性能用 `(wx >> 3, wz >> 3)` 把 8×8 格并成一格、缓存第一个落进去的列的高度
   → 同一块 64 列共享一个高度 = **8 格宽的平台**，跨块边界跳变。
   实测缓坡内最大单步 **4 格**（而平滑值本身逐格只变 1.01）。改成精确坐标后 **7 个 seed 全部 = 1**。
   ⚠️ 这类缺陷只在跨 8 格边界处出现，抽样断言很容易漏。

2. **「让缓坡末端贴合真实地形」这条路在几何上走不通。**
   自然地形本身存在 8 格海岸线断崖（实测 seed 12345 的 ang=339° 射线上
   `generateHeight` 在 1 格内从 -3 跳到 -11），而缓坡外缘（d=342）正好压在它上面。
   三条修法实测**全部更差**：

   | 修法 | 6 seed 最大单步落差 |
   |---|---|
   | 缓坡内全用平滑值，外缘直接切到原始值 | 带内 ≤1，**接缝 3** |
   | 平滑→原始权重随 t 衰减到 0 | **5~7**（把自然陡坡掺回整条缓坡）|
   | 平滑→原始只在最外 12 格过渡 | **4~8**（过渡带内撞上那条海岸线）|
   | **缓坡一平滑到底（现行）** | **≤1**（本地图范围内）|

   ⇒ 正确语义 = **「本地图自己是一块坡度可控的地，接缝处的自然落差由外边那块地承担」**。
   用户要的「有梯度」指本地图不造断崖；外面那条海岸线本来就是个崖，不是本地图造出来的。

3. **判据只能覆盖本地图范围内（`d <= OUTER_RADIUS`），不能含接缝。**
   写成「含接缝 ≤1」会永远 FAIL，且**不是实现缺陷**。

### 5.4 层序（在 `apply.js` 里的位置）

新增**阶段 2.45**：**在** 阶段 1 的地形整形（`fillColumn` 已在 Worker 入口做完）之后、
**在** 阶段 2.4 高台地带**之前**。

理由：本结构是「地基级」内容（它整形整片地表），与高台地带同级别；两者**互斥**
（落点判据 §4.1(4) 已排除），所以先后不影响结果，但放在前面能保证高台地带的
`fillTarnPlateau` 不会与本结构抢同一片地。

### 5.5 各步骤的顺序（载荷性）

1. **削平**：`targetY` 以上一律清空（含原山体）。
2. **铺地表**：按 §5.1 的带选方块。
3. **向下填实**：`WORLD_MIN_Y+1 .. targetY-1` 的空格与水体**都**填 `stone`
   （防玩家挖开掉进洞穴；与 `fillTarnPlateau` 同口径）。
   ⚠️ **只填空气是不够的**（实施期真实页面实测）：`fillColumn` 在整形前按自然地形填过整列，
   低于海平面的部分有 `water` —— 只填空气时湖底正下方会留一层天然水，实测 **492 列**中招。
4. **清空残留水体**：沙滩带以上原本低于海平面的列，其 `(targetY, SEA_Y]` 范围的水
   要显式清成 0 再按需重填，否则外围会出现「水墙」。
5. **五个高台光栅化**：`rasterizeStructure(variant, wx, lakeFloorY, wz, …)` —— 与
   `tarn-zone` 的 `plateauY` 口径一致：**最低层写成 `lakeFloorY`**（= `SEA_Y - 1`），
   高台底座正好坐在湖底方块上（占掉它自己的水格）。

## 6. 五座高台的排布与材质

### 6.1 环上落位

`computeShallowTarnLayout()`（纯函数）：

- 五座按 `max(halfX, halfZ)` 降序入环（大座先占角，与 `tarnRingMetrics` 同手法）。
- 占角 `occ_i = 2·asin(maxHalf_i / RING_RADIUS)`；缝角 `gap = (2π − Σocc) / 5`。
- **零和抖动**：每缝 `(seededRandom − 0.5) × 2 × jitterMax` 后减均值（Σ 缝角守恒）——
  否则 5 个缝整体偏一点，最后一座会绕回第一座。
- `jitterMax` **逐 seed 二分求出**（不得写死，与 `tarnJitterMax` 同一理由）：上界 =
  「相邻 AABB 真实间距仍 ≥ `SHALLOW_TARN_GAP`」的最大抖动。
- `SHALLOW_TARN_GAP = 6`（v2.13）：**= 高台地带 `TARN_GAP = 4` × 1.5**（用户明确要求的倍数）。
  它同时是抖动二分的目标值，所以改这个数会连带改间距分布。

### 6.2 y 口径

- 五座全部**轴对齐**摆放（`rasterizeStructure` 无旋转参数，与高台地带同裁定）。
- 最低层落 `lakeFloorY`（= `SEA_Y - 1`）→ 底座坐在湖底上，**不高一格、不悬空**
  （高台地带踩过「传 `plateauY+1` 让整座悬在水面上方一格」的坑，此处同口径）。

### 6.3 两种草的分块（R15）

**在光栅化期按世界坐标噪声替换**，不在烘焙期 —— 理由：

- 烘焙期决定会让草位**固定在素材坐标系里**，五座高台各自不同的偏置会让分块在
  世界里随摆放位置漂移；而噪声按**世界坐标**算，同一种草在同一片高台上连成片，
  与周围地形的关系也更自然（与高台地带的 `tarnSurfaceBlock` 用世界坐标同源）。
- 载体：新增一个 `rasterizeStructure` 之后的替换步骤（不新增机制）。

判据（与 `tarn-terrain.js` 的 `blobNoise` 同手法，**不可分离噪声**避免横平竖直的边界）：

```js
// 世界坐标低频噪声，值域 [-4, 4]，阈值 0 分成两片
const v = blobNoise(wx, wz, seed + SHALLOW_GRASS_SALT, SHALLOW_GRASS_SCALE);
// v > 0 → light_grass（浅），否则 dark_grass（深）
```

- `SHALLOW_GRASS_SCALE = 0.09`（波长约 11 格）→ 「成片」而非「逐格花斑」。
- ⚠️ **不用逐格随机**：逐格二选一是棋盘状噪点，与用户要的「成片分块」相反。
- ⚠️ **不用可分离的 `noise()`**（`sin(x)+cos(z)`，等值线必然是十字/菱形，
  会出现几十格长的水平竖直线段 —— 高台地带踩过这个坑，故复用 `blobNoise`）。

**替换范围**：只替换**素材原本是 `grass_block` 的那些格**。判断方式 = 烘焙期把
`grass_block` 映射成 **`grass`**（`GRASS_MARKER_BLOCK`，一个**已注册的真方块**），
光栅化后由 `paintShallowTarnGrass` 把每格 `grass` 刷成 `dark_grass` / `light_grass`。

⚠️ **v2.15 把「基准色 `dark_grass`」改成了「真方块标记 `light_grass`」**，理由与约束见 §14.4：
`green_wool` 现在也烘成 `dark_grass`（用户要求 moss 全部变深草），两者不可区分 →
沿用旧口径会把 moss 区也刷成浅草；而哨兵名（`GRASS_PLACEHOLDER`）会被
`makeColumnSetter` 静默 return（那格变 air）。
`grass` 是**临时标记，绝不留在最终世界里** —— E2E 断言「高台顶层不得残留 `grass`」
因此从空断言变成真门禁（刷色没跑 → 平台上出现香草方块 → 红）。

## 8. 海面平面 / 水域遮罩

### 8.1 ⚠️ 必须改：湖区要**强制渲染**水面平面（v2.14 修，用户报告「波纹没盖全」）

初稿的判断「湖底 `h = SEA_Y-1 < SEA_Y` → 遮罩自动生效」是**错的** ——
那句里的 `h` 指的是 `generateHeight`（**自然**地形高度），而整形改的是**方块**，不改噪声。
湖盆里自然高度 ≥ `SEA_Y` 的那些格子（实测 288 个采样点里 **109 个**）会被遮罩关掉平面
→ 只剩体素水的**静态顶面**（无波纹、无高光）→ 用户看到的「波纹只盖了一部分」。

**修法**（与高台地带 v1.89 之前的 `uTarnPool` 同一手法）：
- `ocean-mask.js` 新增 `inLakeCircle(x, z, lake, margin)` + 哨兵 `OCEAN_MASK_NO_LAKE`
  （`radius = 0` → 判定恒假 → 未接线时不影响任何点，与 `OCEAN_MASK_NO_CITY` 同手法）。
- `ocean.js` 新增 `uLakeCircle` uniform 与 `setLakeCircle()`。
- `Game.start()` 用 `computeShallowTarnAnchor(seed)` 的缓存结果接线（**不建第二份落点副本**）。

**三条载荷性约定**：
1. **方向与城市门控相反**：城市是「强制不渲」（压平的陆地），湖区是「强制渲」。
2. **必须 `max` 在 `mix(...)` 之后**：掺进 `nearOceanMask` 会被 `inRangeMask` 在 99~100 格外
   淡掉，而湖区需要「远近都强制」。
3. **外延 `OCEAN_MASK_OFFSET`**（与五点取样同口径）：让平面与沙滩带重叠，
   否则岸边出现一圈「体素水顶面 / 平面」的硬边界。

⚠️ 湖与城市 bounds 恒相距 40 格（落点判据的 `CITY_CLEARANCE` 保证），两个门控不会打架。

⚠️ **v2.15：`setLakeCircle` 的半径从 `LAKE_RADIUS` 改成 `SHALLOW_TARN_OUTER_RADIUS`（整形区最大半径）**。
理由：① 湖岸不再是一个圆，而 TSL 里重算谐波必然与 JS 两份实现漂移；② 门控范围放大到整形区是
**零风险**的 —— 整形区内「淹不淹」由本地图自己的 target 决定，平面（`SEA_Y+0.5`）低于地面时被
深度测试遮掉、高于地面时正好与体素水共面。干燥列的地表恒 `≥ SEA_Y`（顶面 ≥ -1 > -1.5）→
永不会出现「陆地上冒出假水面」。③ 接壤处的**水下方坡**原本落在湖缘外 3.5 格外，不放大就会
只剩体素水顶面（无波纹）—— 正是 v2.14 修过的那个缺陷形态。

### 8.1b 早期判断（已作废，保留作教训记录）

初稿写的是「`ocean-mask.js` / `ocean.js` 零改动」，理由是「湖底 `h = SEA_Y-1 < SEA_Y`
→ 遮罩自动让平面盖住湖区」。这条推理把 `h` 当成了「整形后的地表」，而它实际是
`generateHeight`（自然地形）—— **整形不改噪声**。这是一条「机制推理听起来完全合理、
但用错了变量口径」的实例（同 AGENTS.md 的「凡论证 A 与 B 等价须分别实测」）。

⚠️ **但必须验证一件事**：湖盆整平后 `generateHeight` **没有变**（它只读噪声，不看方块），
所以遮罩判据仍然按「自然地形高度」判断 —— 湖区自然地形若高于 `SEA_Y`，
遮罩会关掉水面平面，只剩体素水的顶面。

**两种可能的表现**：
- 若湖区的 `generateHeight >= SEA_Y`（多数情况，§2.3 实测湖区 60~70% 是干的）：
  **水面平面不显示**，玩家看到的是体素水方块的顶面（下沉 0.5 后与平面共面，颜色来自
  `water.png` 贴图而非 ocean.js 的着色器）。
- ⇒ **这是可接受的**：天然水湾就是这样（体素水顶面 + 无平面），用户明确要求
  「那个怎么实现的你就怎么实现」。

**结论**：`ocean-mask.js` 与 `ocean.js` **零改动**。这不引入新机制，也不破坏
「遮罩判据唯一权威」的既有约束。

### 8.2 一个必须验证的边界

湖盆边缘（沙滩带）的 `generateHeight` 可能 `< SEA_Y`（§2.3 实测外环 16% 是湿的），
此时遮罩**会**显示水面平面。若平面在沙滩上方而体素水不在，会出现「空气里有水」的假象。

**对策**（写进实现）：沙滩带整形时，把 `(targetY, SEA_Y]` 范围**显式填 `water`**（§5.5 第 4 步
反过来）—— 即保证「凡地表低于海平面的列，其上方到 `SEA_Y` 都有水方块」。这样：
- 体素水与水面平面在空间上一致（不会有「平面有、方块无」或反之）。
- 沙滩带内低于海平面的部分变成浅水（自然，符合「湖岸浅滩」）。

### 14.2 湖岸形状：径向谐波

```
R(θ) = LAKE_RADIUS + Σ Aᵢ·sin(kᵢ·θ + φᵢ + p)

  k  = [2, 3, 5, 7]          # 低阶 → 大尺度的湾与岬，不出现锯齿
  A  = [2.5, 1.9, 1.2, 0.7]  # ΣA = 6.3
  φ  = [0, 1.7, 3.4, 5.1]    # 固定相位错开 → 四条谐波不会同时见顶
  p  = seededRandom(0, 0, seed + TARN_SHAPE_SALT) · 2π   # 每个 seed 不同的朝向
```

| 常量 | 值 | 用途 |
|---|---|---|
| `LAKE_RADIUS` | **102**（名义 = 谐波均值，v2.14 是 99） | 三条带的名义边界 |
| `LAKE_SHAPE_AMP_SUM` | 6.3 | 幅度上界（用于安全下界，不靠实测值） |
| `LAKE_RADIUS_MIN` | `LAKE_RADIUS − AMP_SUM` = 75.7 | 湖岸最凹处（v2.16 起**不再是**台地在水里的构造性下界，见 §14.10）|
| `LAKE_RADIUS_MAX` | `LAKE_RADIUS + AMP_SUM` = 88.3 | 净空 / 占地 / 门控的保守上界 |
| `SHALLOW_TARN_HARD_RADIUS` | `LAKE_RADIUS_MAX + BEACH_WIDTH` = 95.3 | 落点净空 + 地标压制 |
| `SHALLOW_TARN_OUTER_RADIUS` | `HARD + SLOPE_WIDTH` = 119.3 | 整形区 / 让路判据 / 水面门控 |

**实测（10 个 seed × 360°）**：`R ∈ [95.99, 108.01]`，均值 **102.00**，std 2.87（v2.15 口径；v2.16 把名义半径收到 **82** ⇒ `R ∈ [75.7, 88.3]`，均值 82.00、极差不变 —— 见 §14.10）。
即幅度上界 6.3 下实际摆幅 ±6.0 —— 与用户选的「中等 ±6，平均 102」吻合。
水面面积 = `∫R²dθ/2` ≈ `102² + var` = 10412 vs 旧 99² = 9801 → **+6.2%**。

**台地余量**：五座最远角恒 92.4 → 最窄方位仍留 `95.99 − 92.4 = 3.59` 格水面
（旧口径岸距恒 6.6；现在是一个 **3.6 ~ 15.6** 格的范围，均值 9.6）。
单测钉的是**构造性下界** `LAKE_RADIUS_MIN (95.7) > 92.4 + 1`，不再依赖实测最小值。

**为什么是谐波而不是噪声 / 预烘焙多边形**：

| 方案 | 否决理由 |
|---|---|
| 值噪声 / Perlin（`blobNoise` 那套）| 需要在 4 个消费方（地形 / 单测 / 门控 / 将来 TSL）各算一次同样的场；谐波是**闭式**，JS 与 TSL 都能逐字同构 |
| 预烘焙多边形顶点表 | 新增一份「湖形」数据 + 必须随 seed 变 → 新增产物与指纹，而收益只是形状更自由 |
| 多个圆的并集 | 并集边界有内凹尖点（两个圆的交点），水面在那里会出现零宽窄缝，且「在不在湖内」变成 N 个判据 |

**相位按 seed**：与台地角向抖动（`SHALLOW_TARN_ANGLE_SALT`）同一口径 —— 不同世界的湖轮廓
朝向不同。**幅度上界与 seed 无关**，所以「台地在水里」的保证仍是构造性的（不依赖实测）。
salt 需在实施前**程序化扫描占用区间**（`seededRandom` 的 salt 占用表；带 `+ step` 的调用点占用区间，
grep 字面量扫不到）。

### 14.3 接壤水系：只在该接的地方去掉堤坝

**为什么需要独立规则**（不是「沙滩宽一点」能解决的）：湖底恒 `SEA_Y-1`，沙滩带必然把地表
抬到 `SEA_Y+2`，也就是**一圈恒高于水面 3.5 格的堤**。实测这个湖并不「偶尔」碰水：

| seed | 湖缘内侧 2 格已天然是水的方位 | 外带（湖缘~+31 格）低于海平面的列 |
|---|---|---|
| 12345 | **17 / 48** | 32.4%（最深 -12）|
| 1 | 22 / 48 | 42.0%（-12）|
| 424242 | 20 / 48 | 44.1%（-15）|
| 8888 | 24 / 48 | 36.3%（-15）|

⇒ 一条三分之一的湖岸线本来是海，被沙滩堤硬挡成内湖。

**规则**（`hS` = 半径 8 均值的自然高度，即既有的 `slopeNaturalHeight`，已缓存）：

```js
const lo = SEA_Y - 1;                                  // 天然水 ⟺ hS ≤ lo
const w  = smoothstep(lo, BEACH_OUTER_Y, hS);          // 0 = 全湿，1 = 全干
const endY = Math.min(BEACH_OUTER_Y, hS) * (1 - w);    // 干态 = 0（逐位等于旧行为）
const midY = clamp(endY, LAKE_FLOOR_Y - BEACH_RISE, BEACH_OUTER_Y);
// 沙滩带：LAKE_FLOOR_Y → midY（降幅封顶 BEACH_RISE = 与上坡同坡度 0.43 格/格）
// 缓坡带：midY → hS（余量摊到 24 格）
```

- **干态（`hS ≥ 0`）**：`endY = 0` ⇒ `midY = SEA_Y+2` ⇒ 三段与 v2.11~v2.14 **逐位相同**（零回归）。
- **湿态（`hS ≤ SEA_Y-1`）**：`endY = hS` ⇒ 沙滩带从湖底往下走 3 格、缓坡带继续降到自然水底。
  两侧水面在同一高度（`SEA_Y + 0.5`）连成一片，体素水与水面平面都连续。
- **过渡（`SEA_Y-1 < hS < 0`）**：`smoothstep` 连续插值 ⇒ 海岸线附近的沙滩逐格降低，无台阶。

⚠️ **干湿判据只能用平滑高度 `hS`，不能掺真实 `generateHeight`**（实测否决）：

| 判据 | 7 seed × 180 方位 × 逐格的最大单步落差 | 说明 |
|---|---|---|
| `cap = hS`（**采用**）| **1** ✅ | `hS` 逐格只变 ~0.5，`w` 与 `endY` 平滑 |
| `cap = min(hS, hNat)` | **2** ✗（seed 1 / ang 54 / d 111）| raw 高度逐格跳 1 → `w` 跳 0.39 → 端点跳 1.06 → 取整成 2 格台阶 |

那个 2 格台阶两侧的地表都**露出水面**（y = -2 → 0），是玩家走沙滩会遇到的「要跳一下」的坎 ——
正是 R18 要排除的形态。故 `hNat` 不参与判据。

**材质**：沙滩带恒 `sand`；缓坡带若该列在水下（`targetY ≤ SEA_Y-1`）也铺 `sand`
（自然水底本来就是 `sand` + `end_stone`，见 `fillColumn`），干坡保持自然地表材质。

**实测：水面连通性**（洪水填充，步长 2、范围 ±220，从湖心水格出发，只走 `targetY ≤ SEA_Y-1` 的列）：

| 状态 | 湖心水团最远到达 | 结论 |
|---|---|---|
| 修前（正圆 + 无湿态规则）| **100 格**（= 旧湖半径 99 + 1）| 4/4 seed **全部被沙滩堤坝隔断** |
| 修后 | **> 150 格**（进入大洋）| 4/4 seed **连通** |

（修后湖内 6349 个采样水格全部属于同一个连通水团，没有被残留隔离的小水洼。）

### 14.4 moss → 深草（`dark_grass`）

**草分块的载体改成真方块标记 `light_grass`**（`GRASS_MARKER_BLOCK`，实施期先误用香草 `grass` 后修正，见下表）：

⚠️ 烘焙产物里 `light_grass` 的格数恒等于素材 `grass_block` 的格数、`dark_grass` 恒等于 `green_wool`
—— 这条不变式由 §10 的两条格数关系式门禁钉住。

### 14.5 水面平面门控（`ocean.js` / `ocean-mask.js`）

`setLakeCircle` 的半径由 `LAKE_RADIUS` 改为 `SHALLOW_TARN_OUTER_RADIUS`（v2.16 = 119.3）。
**CPU 与 GPU 都零新代码**（不改 `inLakeCircle`、不改 TSL），只改接线值。

为什么这样最安全（三条）：
1. **不会漂移**：TSL 无法调 JS 函数；若在 shader 里重算谐波就是第二份实现（既有教训：
   `generateHeight` 的同构实现必须共享数值常量）。放大一个圆的半径不需要第二份实现。
2. **不会有假水面**：门控只决定「这个片元要不要画平面」，画不画得出来由深度测试裁决。
   整形区内**干燥**列的地表恒 `≥ SEA_Y`（顶面 ≥ -1 > 平面 -1.5）→ 平面永远被地面挡住。
   淹水的列其体素水面顶面恰好也是 -1.5 → 与平面共面（既有机制）。
3. **接壤处的坡面必须被覆盖**：水下方坡落在湖缘外 3.5 格之外（沙滩带 7 格 + 缓坡 24 格），
   只外延 `OCEAN_MASK_OFFSET` 会留下「体素水顶面、无波纹」的条带 —— 正是 v2.14 修过的缺陷形态。

代价：整形区保守圆比最窄方位大约 20 格，多出的部分要么是陆地（平面被遮），要么是天然水
（本来就该画）。**零观感代价**。

### 14.8 取舍记录

| 决策 | 选择 | 备选与否决理由 |
|---|---|---|
| 形状做法 | 径向谐波（4 条，k=2/3/5/7） | 噪声需多处同构；多边形表要新增产物与指纹；多圆并集有内凹尖点 |
| 幅度 | 名义 102、幅度上界 6.3 | 「强烈」（±10）会让台地角压进沙滩：最远角 92.4 + 岸距 ≈ 0；「克制」（±3）水面面积与岸距几乎不动，凹凸含蓄 |
| 干湿判据 | 只读 `hS`（半径 8 均值） | 掺 `hNat` 实测出现 2 格台阶（14.3 的表）|

### 14.9 实施期实测修正（与 §14.1~14.8 的差异，以本节为准）

实施时发现了五处「设计稿写得对、但落地要更具体」的地方：

1. **湖心必须是整数格**：`SHALLOW_TARN_HARD_RADIUS` 含谐波幅度（108.3），原公式
   `cityBounds.maxX + HARD + CLEARANCE + 1` 会给出小数湖心（实测 **714.3**）。
   台地落位、E2E 读世界、`lake-ripple.spec` 的 `Math.round(uniform.cx) === a.wx` 全按整数格断言
   → 改为 `Math.ceil(...) + 1`（取 ceil 使净空只能变严）。代价：湖心比 v2.14 东移 ~10 格。

2. **`fillShallowTarnBasin` 的裁剪必须逐列用 `e`，不能只用保守圆**：谐波内凹的方位上保守圆
   （`SHALLOW_TARN_OUTER_RADIUS`）会多出最多 `Σamp` 圈，那里的 `targetY` 就是自然高度，
   但「削平 + 铺地表」会把**自然地表材质刷成 `grass`**（沙漠里冒一圈绿）。
   → 保守圆只作廉价预筛，逐列再用 `e > BEACH + SLOPE` 精确裁。

3. **沙滩带测试口径两处修正**（`testing-policy` §2.6 ⑤ 的又一次实例）：
   - 「完全干的岸段逐格等于 v2.14 剖面」**不可断言** —— `hS` 是平滑**场**，
     同一方位内不同格子的 `w` 可以不同（实测 ang 42 的 eCell=1.24 处 hS≈−1.5 → w=0.75）。
     → 改成聚合判据：**等于干态 60.6~70.0% / 低于 30~39.4% / 高于 0%**（后者是「湿态只降不抬」的核心不变式）。
   - 「湿岸沙滩带单调下降」在**采样序列**上不成立（整数格采样偏 ~1 格 × 剖面是取整阶跃函数
     → 实测出现 −6,−5 的假信号）→ 改成「起点 = 湖底、终点不得抬升 + 全程 ≤ `SEA_Y−1` + 单步 ≤1」。

4. **外缘接缝不属于本地图范围**：湿态下接缝处「平滑值 −6 vs 自然值 −4」实测差 2 格
   （seed 12345 / ang 316 / e=31）→ 台阶判据一律采样到 `BEACH + SLOPE − 1`，
   与既有「缓坡带内单步落差」用例同口径。

5. **已知 flake（非本次改动引入）**：`tests/lake-ripple.spec.mjs` 的第 1 条（两帧像素差分）
   在本机 3 次里约 1~2 次读到 `changed = 0.0%`（阈值 0.05）。探针实测同机位
   `changed 5.3% / blue 65.7%`（与 v2.14 记录的 6.58% / 65.6% 同量级）⇒ 波纹确实在动，
   判据贴近阈值 + 截图偶发相同帧。**未改断言**（仓库规定不为 flake 放宽阈值）。

6. **草标记从 `grass` 改成 `light_grass`（用户 2026-11-02 实玩报告后的修正）**：
   带 `grass` 标记时 `paintShallowTarnGrass` 会把**普通地形的草方块**一起刷成深浅草
   （实测缓坡带 `grass=0 / light_grass=54 / dark_grass=40`）—— 因为该函数扫的是
   **整列** `[lakeFloorY, +64] × 256 格`，而缓坡带的地表材质本来就是 `grass`。
   ⇒ 标记必须满足「**只有烘焙产物才会写**」。`light_grass` 满足（自然地形 / 高台地带 / 城市 /
   植被都不写它）；代价是「刷色没跑」不再有独立可观测信号（浅色那一支的产物就是 `light_grass`），
   改由两条判据兜住：单测「每个标记格必须等于噪声指定的那一种」（深噪声格必须变 `dark_grass`）
   + Tier 4「缓坡带地表必须仍是香草 `grass` 且不得出现深浅草」。两条都已负向验证真红。

### 14.10 湖半径 102 → 82（v2.16，用户「水面还是太大」）

用户 2026-11-02 第二轮：「浅水高台地图的水面还是太大，高台离岸边有点太远，我想降低高台距离岸边的
距离，降低一半左右……只让高台离岸边的距离感觉缩短一半左右就对了」（保持不规则岸形）。

**上一轮为什么没收到位 —— 口径错了，不是数值调得不够。** v2.14/v2.15 的岸距判据是
「`R(θ) − 五座 AABB 的最远角`（**92.4**）」，据此得出「岸畔只剩 3.6~15.6 格」。但**AABB 的四个角是空的**
—— 素材是蘑菇形体（顶部宽、四角缺），拿空角当约束把水面宽度系统性估大 ~20 格。
按**真实烘焙方块**逐方位实测（v2.15 的 `LAKE_RADIUS = 102`）：水环宽 **min 29.2 / 中位 39.3 / max 49.2**
（三 seed 几乎一致）—— 所以「3.6 格」只对那一个最凹的方向成立，多数方向还隔着约 40 格水。

⇒ 口径改为**真实足迹的逐方位支撑函数** `support_v(θ)`（相对该平台足迹 bbox 中心，与
`rasterizeStructure` 的摆放中心同源）：

```
水环宽(θ) = R(θ) − max_v( dot(center_v, u) + support_v(θ) )
```

**`LAKE_RADIUS = 82`**（谐波幅度 ±6.3 不变 ⇒ `R ∈ [75.7, 88.3]`）。实测：

| | v2.15（102） | v2.16（82） |
|---|---|---|
| 水环宽 min | 29.2 | **7.6 ~ 10.9**（6 seed） |
| 水环宽 中位 | 39.3 | **19.0 ~ 19.5**（−51%） |
| 水环宽 max | 49.2 | **28.0 ~ 34.4** |
| 湖面积 | 32,685 格² | **21,124 格²**（−35%） |
| 湖直径 | ~204 | **~164** |

40 seed 抽样最紧 7.6 格（seed 167299）—— 五座仍整体被水环绕。

⚠️ **本图不再有可用的构造性下界**：素材基座半径（y≤4 层真实方块到足迹中心的最远距离）实测
**42.2**，加环半径 45 = **87.2 > 最小湖岸半径 75.7**。能容下靠的是「台地最外凸的方位恰好也是
谐波外凸的方位」（相位由 seed 决定）。故改用**抽样守门**：12 seed × 360° 的最紧水环 ≥ 6
（`test-shallow-water-tarns.js`）。**改谐波参数 / 环半径 / 湖半径都会直接抬出这条。**

⚠️ **连带改动的两处断言（都是同一口径错误，不是放宽）**：
- `tests/shallow-water-tarns.spec.mjs` 的「台地角在湖岸内」→ 改成**真实方块逐格**判
  （`y` 取该列最顶层方块且必须是台地材质）。旧写法「向下扫到非地形方块为止」的**地形清单里没有
  `grass`**，而缓坡带地表正是 `grass` → AABB 现在会稍微压到岸上，实测因此虚报 **55 格**「在岸外」，
  而真实台地方块最远半径只有 **72.5**、0 格在岸外。
- 「湖盆只有一格水」的列数下限改成**按真实采样几何派生**（圆内且不在台地 AABB 内的点 × 0.9）：
  湖缩小后台地 AABB 在采样圆里的占比从 ~30% 涨到 ~54%，旧的「圆面积一半」下限会假失败。
