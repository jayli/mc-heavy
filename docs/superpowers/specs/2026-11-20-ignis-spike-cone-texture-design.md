# 焰魔尖刺：锥面剑纹 + 水面遮挡修复（v3.24）

日期：2026-11-20
状态：代码完成，待用户实玩验收（本轮未提交）

## 1. 需求

用户原话：

> 我想给焰魔的尖刺攻击的特效中，从地表升起的尖刺的锥体表面挂上一些纹理，纹理的颜色图案类比焰魔的剑的图案贴图，可以随机一些，不要是单纯的没有纹理的锥体。

拆解成四条可验收的要求：

1. 锥体表面有**纹理**（不是纯色）；
2. 纹理的**颜色与图案**类比焰魔那把剑的贴图；
3. **可以随机**（逐根不一样）；
4. 「不要是单纯的没有纹理的锥体」—— 纹理必须**看得出来**，不能是结构上有、画面上没有。

## 2. 现状（改动前）

`src/render/spike-fx.js` 的锥体：`ConeGeometry(0.35, 1.6, 6)` + `MeshBasicMaterial`，
**无 `map`**，靠 additive 混合 + 逐实例 `instanceColor`（`(1.0, 0.45, 0.12)` × scale）做淡出。

真实 GPU 实测（不是推断）：锥体在沙地/天空前是一片 **奶油白 (240,224,208)**，
`nearWhite(>245) = 0%` 但锥体区域平均色就是这个 —— 即「一根没有纹理的亮锥」。

## 3. 三项选型裁定（ask_user_question）

| # | 问题 | 裁定 |
|---|---|---|
| ① | 加了纹理之后还该是「透亮发光锥」吗 | 先选「保持发光 + 金色纹章」，被实测推翻后改选**正常混合、纹样即主视觉** |
| ② | 纹理用什么做 | **直接复用已加载的 `assets/ignis/ignis.png`**（零新增贴图 / 零烘焙 / 零依赖） |
| ③ | 水面盖住锥体要不要一起修 | **一起修** |

## 4. 核心实测结论：additive 在亮天空前出不来金色

additive 下最终像素 = 背景 + 增益。焰魔在开阔地战斗时，锥体**上半段的背景永远是亮天空**。

逐档实算（背景 = 天空 `(169,208,219)`）：

| 增益色 | 结果像素 | 是暖色吗 |
|---|---|---|
| 改前无纹理 `(1.0, 0.45, 0.12)` | **(255, 255, 250)** | 否（奶油白） |
| 剑纹 peak `(0.62, 0.24, 0.06)` | **(255, 255, 234)** | 否 |
| 「最强对比」档 `(1.15, 0.50, 0.12)` | **(255, 255, 250)** | 否 |

深色背景（阴影/夜晚/洞穴，`(98,128,60)`）才显金。

真实 GPU 上四档参数扫描的暖色像素占比：**0 / 1.3% / 2.3% / 3.7%** —— 几乎为零。

**结论**：additive 只能给「亮度」，给不了「色相」。要让纹理承担主要视觉信息，
必须改正常混合，让背景透出来。这是物理限制，不是调参问题。

顺带一条：离线光栅化模型算出改前锥体「91% 近白」，而真实 GPU 是 `nearWhite 0%` ——
`ACESFilmicToneMapping` 在 output pass 上压缩了高亮。**离线模型不能替代 GPU 实测。**

## 5. 水面遮挡（既有缺陷，非本轮引入）

单变量对照（只改海面 `renderOrder`，量水面区域内锥体的发光增量 luma p50）：

| 海面绘制顺序 | 锥体发光增量 p50 |
|---|---|
| 后画（默认 `renderOrder = 1`） | **11.6** |
| 先画（`renderOrder = −1`） | **20.5** |

⇒ 被水色冲淡 **1.77 倍**。

根因：锥体 `depthWrite = false` + `renderOrder = 0`（默认），海面 `ocean.js:491` 是
`renderOrder = 1` 且 `depthWrite = true` ⇒ 水后画时按自己的 alpha 把锥体混掉。

修法：锥体 `renderOrder = SPARK.renderOrder`（= **3**）。与曳光（2）、本文件自己的粒子池（3）
同口径 —— `ocean.js:477` 已声明这组三重顺序是耦合约定。

## 6. 实现

### 6.1 纹理来源

剑身 UV 里**唯一 100% 不透明**的长侧嵌纹矩形：`ignis.png` 的 `[90, 128, 82, 7]`。

实测各剑身 UV 矩形的不透明率：剑身平面 `(49,74,40,13)` = **61.7%**、
侧面 `(49,114,40,13)` = **17.7%**、剑脊 `(90,128,40,7)` 与 `(131,128,40,7)` = **100.0%**。
采到有镂空的矩形会在锥面出黑洞 —— 而「锥面有纹理」这个事实仍然成立（静默失效）。

UV 子区由 `spikeTexUvRect()` **单一入口**换算，`flipY` 显式折算（图行号大 ⇒ v 小）。

### 6.2 逐根随机

四项逐实例 instanced attribute：

| 属性 | 含义 | 区间 |
|---|---|---|
| `aTexTiles` | 环绕重复份数 | `[2, 5)` 整数 |
| `aTexReps` | 纵向重复份数 | `[2, 5)` 整数 |
| `aTexPhase` | u 相位 | `[0, 1)` |
| `aTexMirror` | 左右镜像 | `0 / 1` |

抽样在 three-free 的纯函数 `spikeTexPattern(rand)` 里（Tier 1 可复现），
shader 侧只做算术 —— **不在 TSL 里再抽一次随机**（那是第二个权威）。

⚠️ 属性**必须构造时就建好**（即使走纯色回退）：缺属性时 shader 静默读全 0
⇒ 每根纹理完全一样（Storm Lance v3.20 同类坑）。

### 6.3 着色

```
surface = tex.rgb × surfaceTint
glow    = emissive × smoothstep(emissiveRamp, texLuma)
out     = vec4(surface + glow, opacity)
```

自发光只按**纹理亮度**给强度 ⇒ 暗紫底几乎不发光，金纹发光，层次不被冲平。

⚠️ 逐实例淡出仍由 three 自动乘 `instanceColor`（`setupDiffuseColor` 的
`instanceColor.mul(colorNode)`）⇒ `colorNode` 里**不得再乘一次**（否则淡出变平方衰减）。

### 6.4 容错

贴图缺失时退回 `createSpikePlainMaterial`（旧观感）。刻意**不写「无贴图兜底」的中间态** ——
那会让「贴图没加载上」和「本来就没纹理」在画面上不可分辨。

## 8. 被推翻并按新语义改写的旧断言

`ignis-spike.spec` 原本钉 `blending === AdditiveBlending`（理由「否则是不透明橙块」）。
本轮用户裁定改正常混合，该断言与新语义直接冲突。

按「新需求会推翻旧断言，要按新语义改写而不是放宽」改写为四条：

- `blending === NormalBlending`
- `textured === true`（装配层真的把贴图传进来了）
- `material.type === 'MeshBasicNodeMaterial'`（普通 Map 材质给不出色相映射）
- `renderOrder > ocean.renderOrder`

四条都比旧断言更贴近本轮真意图。

## 9. 第二轮：用户反馈「稍微有点暗」后的提亮（2026-11-20）

### 9.1 参数变更

| 常量 | 改前 | 改后 |
|---|---|---|
| `surfaceTint` | `(1.35, 0.58, 0.22)` | `(1.95, 0.88, 0.36)` |
| `emissive` | `(1.45, 0.55, 0.12)` | `(1.90, 0.78, 0.18)` |
| `emissiveRamp` | `[0.30, 0.78]` | `[0.00, 0.65]` |
| `opacity` | 0.88 | 1.0 |

### 9.2 为什么是「抬暗部」而不是「拉对比」

有两类提亮方式，实机对照后选了后者的反面：

| 方式 | mean | p10（暗部） | 评价 |
|---|---|---|---|
| 拉对比 `(1.95,0.84,0.32)` + `ramp 0.16` | 141 | **43** | 暗部更黑了，与「整体偏暗」相反 |
| **抬暗部** `(1.95,0.88,0.36)` + `ramp 0.00` | **176** | **87** | 暗部保持，整体抬起 ✅ |

`emissiveRamp[0] = 0` 是关键：原来 0.30 的下沿让暗紫底完全不发光，
归零后暗部也按纹理亮度分到一点自发光 ⇒ 整根刺一起亮起来，层次不变。

### 9.3 实测（同机位同夹具，单变量）

| | mean | p50 | p90 | 亮像素(>150) |
|---|---|---|---|---|
| 改前 | 147 | 178 | 220 | 55.1% |
| **改后** | **163** | **201** | **235** | **66.9%** |

### 9.4 测量口径的坑（本轮最大的时间浪费，必须记）

1. **「藏掉锥体」的差分掩膜在正常混合下不可靠** —— 锥体后面的水面反射会跟着变，
   掩膜把背景一起圈进来。四档参数因此读出 108/109/108 的**假结论**（看似参数无效）。
2. **「藏海面 + 天空纯色 + 高阈值」也不够** —— 沙漠沙有 26 万像素仍会淹没锥体。
3. **理论推导不能替代实测** —— 按「线性 → ACES → sRGB」手算得暗部 195 / 金部 238，
   实测只有 110~163。three 的 output pass 还有 `outputColorSpace` 等环节，
   手算管线不完整。
4. **可信口径 = 固定屏幕区域 + 同机位同夹具 + 只改一个常量**（`page.route` 换 config 模块内容，
   因为常量编译进 shader，改运行期对象无效）。

## 10. 第三轮：烧炭质感（用户 2026-11-20 定稿）

### 10.1 用户的原始描述

> 锥体太花了，纹理有点乱，而且我感觉还是不够亮，因为这个锥体要是一个被炭烧了的物体，
> 烧炭你见过吗，有黑色的暗区，但整体是红色的烧着的纹理，所以，能不能让纹理里的暗条纹
> 也变亮一些，整体呈现出一种刚从火中拿出的烧炭的感觉，再明亮一下，把纹理的暗区压住。

拆成三条：

1. **纹理太乱** ⇒ 降低重复密度；
2. **暗条纹要变亮**（暗区是「发光的暗红」而不是黑/暗紫）；
3. **整体再亮一些**。

### 10.2 关键转向：贴图只贡献亮度，色相由色阶给

前两轮的写法是 `tex.rgb × surfaceTint` —— 贴图的暗紫底 `#512930` 乘完是**近乎黑的暗紫**，
读作「脏」。这与「烧着的炭」相悖：炭的暗区**是发光的暗红**（还在高温）。

新写法：

```
lum  = tex.rgb · (0.30, 0.55, 0.15)          // 贴图只回答「这一格是暗纹还是金纹」
t    = clamp((lum − window[0]) / (window[1] − window[0]), 0, 1)
col  = charcoalRamp(t)                        // 暗红 → 橙红 → 白热
out  = col × charcoalGain
```

色相完全由 `charcoalRamp` 决定，**不再依赖背景**（这也是能继续用正常混合的前提）。

### 10.3 最终参数（用户认可）

| 常量 | 值 | 作用 |
|---|---|---|
| `charcoalRamp` | `(0.55,0.06,0.02)` / `(1.05,0.26,0.04)` / `(1.55,0.72,0.22)` | 暗红 → 橙红 → 白热 |
| `charcoalWindow` | `[0.10, 0.85]` | 亮度 → 色阶位置；下沿压住暗底 |
| `charcoalGain` | `1.35` | 整体倍率（单一旋钮） |
| `opacity` | `1.0` | 实体炭，不透背景 |
| `wrapTiles` | `[1, 3)` | 从 `[2,5)` 降下来（治「太花」） |
| `riseTiles` | `[1, 3)` | 同上 |

`charcoalWindow[0] = 0.10` 是「把暗区压住」的那个旋钮：剑纹带暗紫底的线性亮度约 0.21，
窗口从 0 起会把暗底映射到色阶最左端（整锥偏红但看不出纹理）；从 0.10 起则让暗底
落在色阶 ~0.15（暗红），金纹落在 ~1.0（白热）。

### 10.4 实机三档对照（绝对坐标 1200/1200，同机位）

| 档 | gain | mean | p10 | p50 | p90 | 暗像素% | 暖色% |
|---|---|---|---|---|---|---|---|
| **now（采用）** | 1.35 | 164 | 110 | 177 | 207 | 5.8 | 26.9 |
| brighter | 1.55 | 169 | 110 | 179 | 207 | 5.8 | 24.1 |
| hot | 1.7 | 171 | 110 | 182 | 207 | 5.8 | 22.5 |

三档差异很小（用户选「现在这版」），说明 `charcoalGain` 在 1.35~1.7 之间已经很稳，
后续微调空间不大 —— 真正的观感改善来自「贴图只给亮度 + 色阶给色相」这个结构改动。

### 10.5 探针踩坑（第三轮新增教训）

**`g._teleportTo(当前x + 1200, …)` 会让每一档落在不同地点**：上一版探针三档的坐标分别是
1483 / 2683 / 3883，画面完全不同 ⇒ 读数不可比。**多档对照必须用绝对坐标**。
