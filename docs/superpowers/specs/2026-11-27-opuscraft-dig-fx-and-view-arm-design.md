### 上游定位

OpusCraft 的粒子与手持渲染是**逐行照 vanilla 语义**写的（注释直接标 `vanilla ItemInHandRenderer` /
`vanilla ParticleEngine.destroy` / `vanilla PlayerRenderer.renderRightHand`）。所以本仓移植的是
**语义与常数**，不是它的架构组织方式 —— 与 CLAUDE.md 对 mc-lite 的定位一致
（「功能与数据来源，不是实现蓝本」）。它的 `PoseStack` / `EntityBatch` / `GL` 一律不迁。

## 1. 目标 / 非目标 / 反目标

**目标**

1. 徒手挖掉方块时有一簇**该方块颜色**的碎片洒落（当前**零特效**）。
2. 第一人称手臂 = vanilla 造型（4×12×4 像素 + 皮肤 + 袖子）+ vanilla 挥动动作。
3. 奔跑时手臂与剑有步态晃动，相位与相机晃动**同源**。
4. 地形可借鉴性有实测依据的书面结论。

**非目标**

- 不做贴图碎片 billboard、不做逐 tick 碰撞物理（用户选了复用现有池，见 §2 偏离表）。
- 不做副手（off-hand）手臂：本仓无副手槽位。
- 不做 `renderArmWithItem`（持物时的手臂）：本仓持枪/持剑时手臂隐藏，是既有互斥口径。
- 不改 pistol / mag7 / minigun 的奔跑表现（用户明确「除了卡宾枪以外的枪就先保奔跑时不晃动」）。
- 不动地形生产代码。

**反目标（技术上成立但算失败）**

- 碎片颜色与方块材质无关（退化成中性灰）—— 那是「这里播了个碎屑动画」而不是「这块石头碎了」。
- 手臂挥动只改欧拉角而不变换链 ⇒ 观感是「转了一下」而不是原版的甩臂。
- **手臂变成一块纯色板**（v3.46b 实测踩到）：去掉异色袖口后 78.6% 像素挤在同一亮度桶。
  「颜色统一」与「有立体感」必须同时成立 ⇒ 靠**灰阶面间亮度**而不是靠异色分区。
- 剑的 bob 破坏既有 8 条挥砍轨迹判据（剑柄钉在屏下 / 剑尖扫向准心 / 恰好一个位移峰）。
- 奔跑晃动新增第二份相位/幅度权威（与 `ViewBob` 漂移）。

## 2. 有意偏离表

| # | 上游做法 | 本仓做法 | 理由 |
|---|---|---|---|
| ① | `ParticleEngine.destroy`：按碰撞盒 **4×4×4 = 64 片**，每片取贴图一个随机 **4×4 texel 子区**，billboard 薄片 | 复用 `BlockHitFxRenderer` 的**实心小立方** `InstancedMesh` 池，颜色取该方块顶面 atlas **平均色** | **用户裁定**「复用现有池只加调用」。代价：看不到方块纹理。收益：零新池、零新 draw call、零回归 |
| ② | 逐 tick 物理：`dy -= 0.04·gravity`、摩擦 0.98、**落地后水平 ×0.7**、寿命 `floor(4/(rand·0.9+0.1))` tick | 现有池的抛物线 `v·t + ½gt²`（g=18）+ 末段缩零，**不撞地** | 同 ①。代价：碎片不停在地面上，落日前缩零 |
| ③ | 手臂材质吃 lightmap（`useLightmap: true`，逐方块光照） | `MeshBasicMaterial({ map })` **unlit** | 本仓全场景 unlit（`view-arm.js` v1.48 已记录的取舍）：受光材质会让肤色随日夜漂移、且比同屏方块亮一档 |
| ④ | 手臂 + 袖子是**两个 ModelPart**（袖子 `inflate 0.25`） | **合并进同一 geometry**（两组顶点、一份材质、一个 Mesh） | 本仓 WebGPU 后端 `getMaterial()` 不遍历 `geometry.groups`（`zombie-skin-texture.js` 已记）⇒ 两个 mesh 要多一份材质与一个 draw call；合并保住「camera 只增 1 个节点」的既有断言 |
| ⑤ | 皮肤是运行时逐像素绘制（`steveSkin()`，xoshiro128**） | **离线烘焙** `assets/player/skin.png` + 指纹门（mulberry32） | 本仓皮肤类素材一律烘焙 + `check:data` 守过期（`bake-zombie-skin.mjs` 是先例）。⚠️ **烘焙只是数据格式转换，不产生新美术资源** —— 配色与绘制规则逐条取自上游 |
| ⑥ | 挥动时长 `swingDuration()` = 6 tick（受 haste/挖掘疲劳影响） | 固定 **6 tick = 0.1s** | 本仓无药水效果系统 |
| ⑧ | 手臂袖子（overlay）只袖口 4 行涂实（v3.46 中间方案） | **整段透明**（= 上游真实行为）+ **灰阶面间亮度**补立体感 | **用户 2026-11-27 第二轮**：「手臂前方的蓝色部分也烘焙成跟手臂一样的色调，不然看起来感觉怪怪的」。☠️ 改完实测到**78.6% 单桶、无双峰**（v1.56 变平回归）⇒ 补 `ARM_FACE_SHADE` 灰阶系数（r=g=b，**只缩亮度不改色相**），单桶降到 39.7% / 峰距 15.2% |

## 3. A：挖块碎片（复用现有池）

### 3.1 上游语义（`src/render/particles.ts:193`）

```
blockBreak(x,y,z,state):
  对每个碰撞盒 bb：
    ix = max(2, ceil(bb宽/0.25))  // 整格 ⇒ 4
    对 a,b,c ∈ [0,ix)×[0,iy)×[0,iz)：
      d4=(a+0.5)/ix, d5=(b+0.5)/iy, d6=(c+0.5)/iz
      位置 = 块角 + (d4·宽, d5·高, d6·深)
      初速方向 = (d4−0.5, d5−0.5, d6−0.5)   ← 从块心向外
      + 随机扰动 ±0.4，归一化后 × sp·0.4，y 再 +0.1
      sp = (rand+rand+1)·0.15
```

**语义要点（本仓保留的）**：碎片**从块心向外**呈球状散开、带向上偏置。
**语义要点（本仓放弃的，见偏离 ①②）**：贴图子区、billboard、逐 tick 碰撞。

### 3.2 本仓实现

`src/render/block-hit-fx.js` 新增：

```js
export const DIG_BURST = freezeDeep({
  count: 14,            // 单格方块（1×1×1）⇒ 比丧尸（0.6×1.8×0.6，20 块）少
  size: [0.10, 0.20],   // 边长（方块=1）：比枪击碎块（0.15~0.26）小一档
  speed: [1.6, 3.4],    // 初速：比枪击（2.5~4.6）慢 —— 挖块不是被打爆
  spin: [5, 12],
});
spawnDigBurst(blockPos, colorRgb, nowMs, { count, rand } = {})
```

- **复用** `createDeathBurstSeeds`（全球面 = 上下半球各一半）/ `debrisOffset` / `debrisSizeAt`
  与同一个 `_debrisMesh` 池。**不开第二个池、不写第二套抽样数学**（红线 1）。
- 锚点 = **块心** `blockCenter(blockPos)`。⚠️ 不是 `impactPosition`（那是命中面，挖块无命中面语义）。
- ⚠️ `count ≤ IMPACT_FX.debris.maxActive`（128）—— 单测钉住，否则一次爆散自己覆盖自己。

`src/player/player.js` 的 `digBlock()`：在既有 `removed?.changes?.length > 0` 分支（播 `delete` 音效处）
**并列**加一次调用。

⚠️ **判据必须是「真删掉了」**：`editor.setBlock` 对本来就是空气的格返回零 changes。
无条件播会让「按住左键挖空气」变成连发碎屑（与音效同一条既有教训）。

颜色：`colorResolver(registry.nameOf(oldId), [0,1,0])`。
⚠️ **`oldId` 必须在删除前读**（`digBlock` 已有 `const id = this.world.getBlockId(...)`，删完再读恒为 0）。

### 3.3 接线

`game.js` 装配段已有 `blockColorResolver`（atlas 取色器）与 `blockHitFx`。挖块路径**复用同一个
resolver**，不新建、不再读一遍 2048² atlas 像素（红线 1）。

`player.js` 侧新增注入项 `blockDigFx`（形状 = `{ spawnDigBurst }`），与既有 `blockHitFx` 同手法。
缺省 null ⇒ fixture 单独构造时不出特效、不报错。

## 4. B：手臂整体照抄

### 4.1 上游几何（`src/render/model.ts:161`）

```js
right_arm = ModelPart([{ x:-3, y:-2, z:-2, w:4, h:12, d:4, u:40, v:16 }], pivot=[-5, 2, 0])
right_sleeve = ModelPart([{ ...同上, u:40, v:32, inflate:0.25 }])
```

几何单位是**像素 /16**（`bakeCube` 里 `p[0]/16`）⇒ 手臂 **0.25 × 0.75 × 0.25 格**。
本仓当前是 0.04 × 0.12 × 0.04 ⇒ **线性 6.25×**。

**六面 UV**（标准 64×64 版式，`boxFaces(u,v,w=4,h=12,d=4)`）：

| 面 | 矩形 (x,y,w,h) | 说明 |
|---|---|---|
| top (+Y) | (44, 16, 4, 4) | 肩端 |
| bottom (−Y) | (48, 16, 4, 4) | 手端 |
| right (+X) | (40, 20, 4, 12) | |
| front (−Z) | (44, 20, 4, 12) | |
| left (−X) | (48, 20, 4, 12) | |
| back (+Z) | (52, 20, 4, 12) | |

袖子层同矩形但 `v+16`（=32 起）。

### 4.2 上游挥动链（`src/render/handRenderer.ts:renderArm`，逐字）

```
f  = i                                  // 1=右手
f1 = √swing
f2 = −0.3·sin(f1·π)
f3 =  0.4·sin(f1·2π)
f4 = −0.4·sin(swing·π)
translate(f·(f2+0.64000005), f3−0.6+equip·(−0.6), f4−0.71999997)
rotY(f·45)
f5 = sin(swing²·π)
f6 = sin(f1·π)
rotY(f·f6·70)
rotZ(f·f5·(−20))
translate(f·(−1), 3.6, 3.5)
rotZ(f·120)
rotX(200)
rotY(f·(−135))
translate(f·5.6, 0, 0)
// drawArm: arm.resetPose(); xRot=0; zRot=0.1(rad)
translate(pivot/16) ; rotZ(0.1 rad)
```

**⚠️ 变换是右乘（`PoseStack` 语义）**：`M ← M · T` / `M ← M · R`。
three 的 `Matrix4.multiply(m)` 同为右乘 ⇒ 逐条 `.multiply()` 即可，**顺序不能反**。

**⚠️ `rotZ(0.1)` 的单位陷阱**：上游 `arm.zRot = 0.1` 是**弧度**（`ModelPart.translateAndRotate`
里 `pose.rotZYX(xRot,…)` 吃弧度），而 `PoseStack.rotZ(deg)` 吃**度数**。
移植时必须 `0.1 × 180/π = 5.7296°`。写死 0.1 度会让手臂几乎不外张（静默）。

### 4.4 皮肤烘焙

`tools/bake-player-skin.mjs` + `tools/player-skin-fingerprint.mjs`，照 `bake-zombie-skin.mjs` 骨架。

上游配色（`src/textures/skin.ts`）：

| 语义 | 三档（暗/中/亮） |
|---|---|
| skin | `0xa87d63` / `0xb68a6f` / `0xc49a7e` |
| shirt | `0x008080` / `0x00a0a0` / `0x00b2b2` |

绘制规则（**v3.46b 用户裁定后的最终口径**）：
- 四个侧面（right/front/left/back）：**整条 12 行都是肤色**；
  逐像素 `rand < 0.3 ? pal[randInt(3)] : pal[1]`（这条噪声规则照上游）。
- top 面（朝前的远端）与 bottom 面：**同样肤色**，noise 分别 0.25 / 0.3。
- 袖子层（v+16）：**整段透明**（= 上游真实行为）。

> ☠️☠️ **袖子层的两轮实测**：
> ① 整段 12px 涂实 ⇒ 它是 `inflate 0.25` 的**外包盒**，把下面手臂完全遮住
>   ⇒ **19550 个手臂像素全 teal、肤色 0**（一条纯青胳膊）；
> ② 只袖口 4 行涂实 ⇒ 那 4 行在几何 y 最大端，而那一端实测
>   **z=−1.095（更远）/ y=−0.438（更高）** ⇒ 屏幕上就是**朝前的远端**
>   （沿长轴探针：teal 12500 像素全在 bin 8~9）—— 用户：「看起来感觉怪怪的」。
> ⇒ 最终回到上游口径：**overlay 段不写**。几何仍保留袖子盒（48 顶点），
> 但材质必须保留 `alphaTest: 0.5` —— 否则透明像素被当成黑色实心把整条手臂盖死。

#### ☠️☠️☠️ 去掉异色区后的**变平回归**（本轮最重要的发现）

改成全肤色后，色相判据全绿，但亮度分布实测：

| 口径 | 改前（有蓝袖口） | 刚改完全肤色 | 补灰阶面间亮度后 |
|---|---|---|---|
| 最大单桶占比 | — | **78.6%** ❌ | **39.7%** ✅ |
| 第二峰占比 | — | **0** ❌ | 6.2% ✅ |
| 峰距 | — | **0** ❌ | **15.2%** ✅ |

78.6% 正是 v1.56「一个颜色、没立体感」的读数（当年修复前 78.9%）。

**根因（逐面屏幕面积探针）**：静止姿态下只有两个面可见 ——
**+Z 面积 3.57 / −X 面积 2.09**（比例 63:37），其余四面 `facing < 0` 被几何自身挡住。
两面采同一张肤色贴图 ⇒ **面间零明暗差**。

**修法**：`ARM_FACE_SHADE` 烘焙**灰阶**顶点色（r=g=b）——
顶 1.0 / +Z 0.94 / +X 0.88 / −Z 0.86 / −X 0.78 / 底 0.72。
⚠️ **灰阶是载荷性的**：用户要「跟手臂一样的色调」，任何带色偏的系数都会把肤色
拉向另一个颜色（旧版 v1.57 那套 `shadeLow/shadeHigh` 幂律重映射就改色相，本轮不重引入）。
修后实测主色 178/136/107 与 185/143/114，**R>G>B 关系逐位保持** ⇒ 仍是同一个肤色。

⇒ **教训：色相判据抓「颜色不对」，亮度分布判据抓「颜色对了但变成一块色板」，缺一不可。**

**只烘手臂两段 + overlay 两段**（4 个 UV 岛），其余 64×64 区域填透明。
理由：本仓只渲染手臂，烘全身是死像素。⚠️ 指纹只覆盖这 4 段。

产物 `assets/player/skin.png` + `skin.json`。**不放 `assets/textures/`**（会被 atlas 递归扫描）。

## 5. C：奔跑晃动（手臂 + 剑）

### 5.1 现成的线

`game.js:1844`：

```js
bobPhase: this.player.viewBob.timer,
bobAmp: this.player.viewBob.amount / 0.15,   // ← 字面量，与 BOB.intensity 构成第二份权威
```

本轮把 `/ 0.15` 改成 `/ BOB.intensity`（红线 1）。

### 5.2 上游 bob 常数（`carbine-view.js` 已移植的 `CARBINE_VIEW`）

```
x    += cos(φ) · 0.012 · amp
y    += −|sin(φ)| · 0.014 · amp
roll += sin(φ) · 0.018 · amp
```

**从 `CARBINE_VIEW` import 这三个值**，不在手臂/剑里复制字面量。

### 5.3 叠加位置

- **手臂**：叠在变换链**最外层**（`M_bob · M_arm`），相机空间平移 + 绕 Z 滚转。
- **剑**：只在 `weapon.melee` 分支，叠在挥砍矩阵 `M` 的最外层（与既有 `shift` 同层）。
  ⚠️ **不改支点补偿 `c`** ⇒ 既有 8 条挥砍轨迹断言的几何关系不变。
- **枪（pistol/mag7/minigun）**：`!weapon.melee` 分支**逐位不变**（用户明确要求）。

### 5.4 静止归零

`amp = viewBob.amount / BOB.intensity`，静止时 `amount → 0`（`releaseRetention 0.8`）⇒ bob 严格归零。
判据：静止 60 帧后手臂/剑的位置与无 bob 时**逐位相同**。
