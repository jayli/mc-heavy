# 丧尸行动拟真度（犹豫 / 后退 / 徘徊 / 速度波动 / 转身限速）设计

**状态：** 待批准（2026-11-16）
**定位：** 丧尸 AI 的增量增强，不是新 Epic。**不改 A\* 算法、不改物理、不改存档、不改渲染部件、零烘焙。**
**关联：** `2026-11-02-zombie-obstacle-avoidance-design.md`（局部避障）、
`2026-11-03-zombie-online-ai-design.md` §3.10（有界寻路）、`plans/2026-11-04-zombie-pathfinding.md`、
`docs/testing-policy.md`（分级）。

## 1. 意图与为什么

### 1.1 用户原话（2026-11-16）

> 「丧尸现在生成出来之后，行动 ai 能力比较初级，只是朝向玩家做最基础的走向动作，走向的过程中
> 有简单的绕路能力，有点傻傻的感觉。我想升级一下丧尸的 ai，基本的大方向朝着玩家运动没问题，
> 我希望丧尸的行进方向和速度更多一些灵活性，撞墙后甚至可以倒退一下，而不是挨着墙贴脸蹭墙前进，
> 也可以适当的『犹豫』一下，比如撞墙后，再比如靠近玩家后已经没有前进的路了，就『犹豫』一下，
> 暂定踱步，然后后退几步，再开始绕路或者做新的寻路的动作。总之，你考虑增加一下丧尸的 ai 行动
> 拟真度，别一股脑的面向玩家，走向玩家，显得有点太傻。」

### 1.2 现状为什么「傻」—— 实测而非推断

Node 直跑生产链路（`ZombieService.update` → `_stepNavigator` → `decideStep` → `_applyIntent`
→ `steerIntent` → `setIntent`，再 `EntityManager.update` 跑 60Hz 物理；两层都是同构纯函数，
所以这就是玩家实际走的路径）。六个场景实测：

| 场景 | 速度取值集合 | 1.5s 窗口净位移 min | >90° 方向翻转 | 平行贴墙帧的墙面间隙 | 末态 mode |
|---|---|---|---|---|---|
| A 开阔地直追 24 格 | **{0, 1.2}** | 1.78 格 | 0 | — | chasing |
| B 绕 31 格长墙（可绕） | {0, 1.2} | 1.04 格 | 0 | **恒 0.6816 格** | chasing |
| C 整图封死（不可达） | {0, 1.2} | **0.02 格** | **354 次** | 恒 0.6998 格 | **chasing** |
| D 玩家隔墙 2 格外 | {0, 1.2} | 0.85 格 | 0 | 恒 0.6816 格 | chasing |
| E 四面围死 | {0, 1.2} | 0 格 | 0（意图恒零） | — | blocked |

四条可量的根因：

1. **速度是二值的**。`_stepNavigator` 给单位向量 × `ZOMBIE.speed`，`_applyIntent` 只做上限钳制
   ⇒ 全程恒 1.2 或恒 0，没有任何中间值。
2. **朝向瞬时派生**。`setIntent` 的 `yaw = atan2(vx, vz)` ⇒ 单帧最大跳 **135°**（实测 2.3562 rad）。
3. **贴墙是「几何必然」而非 bug**。`steerIntent` 只探 **1.2 格外的落点**，从不检查身体侧面
   ⇒ 沿墙滑行时 AABB 与墙面间隙恒 **0.6816 格**，803 帧一个数都不差。它不知道自己在蹭墙。
4. **最关键：没有「走不动」的判定**。场景 C 二十秒净位移 **2.12 格**、朝向翻转 **354 次**，
   而 `mode` 始终 `chasing`、`blocked` 永不出现 —— 因为「沿墙滑行」在代码里算成功。
   **犹豫无从触发，不是因为没写犹豫，是因为没有任何信号告诉它该犹豫了。**

### 1.3 一个决定设计的几何结论（实测否掉了一条直觉方案）

直觉方案是「加侧向净空探针，离墙太近就退开」。**实测证明它没有判别力**：

| 场景 | 左净空 | 右净空 | min |
|---|---|---|---|
| 开阔地 | 1.60 | 1.60 | 1.60 |
| 贴墙滑行中段 | 0.60 | 1.60 | **0.60** |
| L 形墙角（真该退） | 0.60 | 1.60 | **0.60** |
| 1 格宽走廊（**必须能过**） | 0.10 | 0.10 | 0.10 |

「正常贴墙滑行」与「墙角卡死」的侧向净空**逐位相同**，而 1 格宽门洞的净空更小 —— 任何
「净空小于阈值就后退」的判据都会让丧尸**不敢进门**（v2.40 明确保住的语义）。
⇒ **「该不该退」只能由时间维度（走没走动）判定，不能由几何维度判定。** 这是本设计的核心取舍。

## 2. 目标 / 非目标 / 反目标

### 2.1 目标

1. 撞墙走不动时：**愣一下（0.6~1.2s）→ 踱一两步 → 后退 1~2 格 → 重新寻路**。
2. 靠近玩家但没路时同样触发（场景 D：现在是立刻全速沿墙跑 16 格，零迟疑）。
3. 真的绕不过去时：**退开后在附近徘徊等玩家**，周期性重试；玩家一露头立刻恢复追逐。
4. 速度不再是二值：巡航有慢漂移、起步有加速、转向与犹豫时更慢。**1.2 仍是硬上限。**
5. 转身有过程（限速），不再一帧甩头 135°。
6. 不再长时间平行贴墙平移。

### 2.2 非目标（明确不做）

- **不改 A\* / `planStep` / `PathCache`**：长距离可达性已经对了，本轮不碰。
- **不改共用层**：`decideStep` / `memoryFor` / `steerIntentAabb` / `zombieCollidesAt` /
  `zombieStepUpY` **签名与行为逐位不变**（焰魔与守卫共用，见 §3.2）。
- **不改物理**：重力、AABB、`tryStepUp`、`MAX_STEP`、分轴二分回退一行不动。
- **不改 `ZOMBIE` 冻结表**：`speed 1.2` / `maxActive 20` / `health 100` / AABB / `aiPeriod 0.05`
  / `perceptionRange 80` / `aiSleepDistance 60` 全部原值。
- **不做头身分离**（用户 2026-11-16 裁定「只限速转身」）：后退时整体朝向仍由速度派生，
  即丧尸会「背对玩家倒着走」而不是「盯着玩家退开」。这是本轮的已知观感取舍。
- **不做短暂冲刺**（用户裁定「1.2 仍是上限，只往下波动」）。
- **不做**：丧尸跳跃 / 爬梯 / 破坏方块 / 攻击玩家（M6 规格「不攻击玩家」仍有效）/
  丧尸之间的社交行为 / 设置面板开关 / 新增美术资源 / 烘焙。
- **不顺带修**：`computeAiUpdates`（worker 侧同构函数，现仅存形状契约用途）、感知门、排斥力。

### 2.3 反目标（做成了也算失败）

- 丧尸**不敢进 1 格宽门洞 / 2 格高走廊**（§1.3 的陷阱）。
- 正常绕墙时**频繁犹豫**，导致追不上玩家或看着像卡死。
- 犹豫/徘徊变成**永久不动**（玩家拆墙后必须恢复）。
- 焰魔或守卫的行为**发生任何变化**。
- 速度波动让丧尸**在任何一帧超过 1.2 格/秒**。

## 3. 约束

### 3.1 架构红线

- **红线 1（单一权威）**：新行为层是 `state.velocity` 的**唯一上游决策者**，链路仍是
  `_stepNavigator → 行为层 → _applyIntent → setIntent`。不新增第二份速度/朝向权威。
  行为状态存进**既有的** per-zombie `_navMemory`（`memoryFor`），它的回收已在
  `_releaseSlot` 覆盖三条路径（死亡 / column 卸载 / dispose）—— **不新建第二个 Map**。
- **红线 3 / 8（同构）**：新模块在 `src/entities/zombies/`，无 DOM、无 three、不建 Worker。
- **红线 7（版本协议）**：行为层不碰 `generation`，仍在 `_applyIntent` 校验。
- **确定性口径**：随机性走**可注入 `rng`**（默认 `Math.random`），与 `BossAgent`
  （`dragon-boss-agent.js:52` / `ignis-boss-agent.js:86` / `guardian-boss-agent.js:56`）
  **同一既有手法**。单测注入定值 rng 即可钉住具体数值。
  ⚠️ 这与 `steerIntent` 的「无 `Math.random`」约定**不冲突**：那条约定管的是**避障探针**
  （几何判定必须可复现），本轮不碰它；行为层是**决策**，与 Boss 冷却同类。
- **时间基准**：一律 `performance.now()` 口径的 `nowMs`，禁 `Date.now()`。

### 3.2 共用代码的边界（本设计最重要的约束）

`decideStep` / `memoryFor` 被三方消费（程序化核实）：

| 消费方 | 位置 |
|---|---|
| 丧尸 | `zombie-system.js:_stepNavigator` |
| 焰魔 | `ignis-system.js:25,462` |
| 末影守卫 | `guardian-system.js:26,291` |

`steerIntentAabb`  additionally 被两个 Boss Agent 直接调用（站定环 → 局部绕行 → `needsPath`
偏差判据）。它们身上压着 v2.78 / v3.09 的实测标定（站定环「不动如山」、`needsPath` 的 ~5°
阈值、招式中止门）。**故新行为一律做成丧尸专属的一层，共用层零改动。**

### 3.3 既有测试的硬约束（实测标定，不是猜）

`tests/zombies.spec.mjs` 的「v2.40 绕 3 格高短墙」用例：**5 格宽墙 / 12 秒窗口**，
判据 `crossed === true` 且 `endDist < startDist − 2`。实测降速余量：

| 速度倍率 | 路径长 | 跨墙时刻 | 判定 |
|---|---|---|---|
| 1.00（现状） | 13.9 格 | 9.2s | PASS |
| 0.90 | 12.5 格 | 10.2s | PASS |
| 0.80 | 11.0 格 | **11.5s** | PASS（贴线） |
| 0.70 | 9.6 格 | 未跨过 | **FAIL** |
| 0.60 | 8.6 格 | 未跨过 | FAIL |

叠加「一次犹豫损失 2 秒行程」后：**倍率 0.90 即 FAIL**。

⇒ **两条载荷性设计结论**：
1. **巡航倍率不得低于 0.90**（取 0.92~1.0 的慢漂移，见 §4.4），否则既有 E2E 必红。
2. **正常绕墙不得触发犹豫**。实测该夹具的窗口净位移 min = **1.066 格**，
   规划背离角 max = **31°** —— 两个触发信号的阈值都必须远离这两个值（§4.2）。

⚠️ 这两条不是「放宽断言」，是**用实测把新行为的参数约束在既有判据内**。断言一字不改。

## 4. 设计

### 4.1 分层（新增一层，不改既有三层）

```
① zombie-pathfinder.js   A* 24 格 → 下一个地标        【不动】
② zombie-navigator.js    decideStep：地标 → 8 向可走一步 【不动，Boss 共用】
③ zombie-behavior.js     【新增】丧尸专属：这一拍到底怎么走
                         · 卡住检测（时间维度）
                         · 状态机 chase → hesitate → backoff → replan → (wander)
                         · 速度包络（巡航漂移 / 起步加速 / 转向减速）
④ zombie-navigation.js   steerIntent：最后 1.2 格精细避让 【不动，Boss 共用】
⑤ zombie-system.js       物理 60Hz                      【不动】
   + setIntent 出口：转身限速（丧尸专属，见 §4.6）
```

**为什么③在②之后④之前**：②回答「哪个方向有路」，③回答「这一拍要不要走、走多快、要不要退」，
④回答「这个方向真的走得通吗」。把③放在④之后会让「后退」也被避障探针改写方向 —— 后退本身
就是「探针说走不通」的产物，再探一次会把它吞掉（v2.47 排斥力被 `steerIntent` 吞掉的同类陷阱）。

### 4.2 卡住检测（两个信号，阈值由实测定，判别力已验证）

**信号 A：滚动窗口净位移**（主信号，治场景 C/E）

维护最近 `stuckWindowSeconds = 1.5` 秒的位置环形采样，算首尾直线距离。
`< stuckDistance = 0.35 格` ⇒ 判定卡住。

实测判别力（§1.2 表）：正常三场景 min = **1.78 / 1.04 / 0.85**，既有 E2E 夹具 min = **1.066**；
卡死两场景 min = **0.02 / 0**。阈值 0.35 距最近的正常值 0.85 有 **2.4 倍**余量，
距卡死值 0.02 有 **17 倍**。

⚠️ **窗口不能取 1.0s**：实测正常绕墙的 1s min 低到 **0.501**，余量只剩 1.4 倍。
⚠️ **必须用「首尾直线距离」不是「路径长」**：场景 C 每帧都在动（路径长非零），
只有净位移能识别「原地打转」。

**信号 B：规划方向背离玩家**（辅信号，治场景 D「靠近玩家却没路」）

`decideStep` 已经返回 `plannedDirection`。当**距玩家 ≤ nearPlayerDistance = 6 格**
且规划首步与「朝玩家直线」夹角 **> awayAngleDeg = 120°** 且持续 `awayHoldSeconds = 0.8` 秒
⇒ 判定「没路了」。

实测判别力：

| 场景 | 距玩家 ≤6 格时的规划背离角 max |
|---|---|
| 既有 E2E 5 格墙（不得触发） | **31°** |
| 开阔地 | 0° |
| 绕 31 格墙（不得触发） | **74°** |
| 贴脸隔墙（该触发） | **160°** |

阈值 120° 落在 74 与 160 之间，两侧都有余量。
⚠️ **「距玩家 ≤6 格」这个门是载荷性的**：绕远墙时全程背离角可达 141°（合法绕行），
不加距离门会把正常绕墙误判成没路。
⚠️ **必须要求持续 0.8 秒**：单拍采样会被缓存命中/路径切换的瞬时值干扰。

**信号 C：`decideStep` 返回 `blocked`**（既有语义，直接进状态机，不新增判据）

### 4.3 状态机

```
        ┌──────────────────────────────────────────────┐
        │                                              │
     chase ──(信号A/B/C)──> hesitate ──> backoff ──> replan
        ↑                    愣住        后退         强制重算
        │                  0.6~1.2s     1~2格          │
        │                                              │
        └────────(重算后有路)──────────────────────────┘
                                                       │
                              (连续失败 ≥ wanderAfterAttempts=3)
                                                       ↓
                                                    wander
                                              退开后附近小幅踱步
                                              每 retrySeconds 重试寻路
                                                       │
                                            (有路 / 玩家进入视野)
                                                       ↓
                                                     chase
```

| 状态 | 行为 | 时长 / 退出条件 |
|---|---|---|
| `chase` | 照现状追（②的方向 × ③的速度包络） | 触发信号 → `hesitate` |
| `hesitate` | **零水平速度**（愣住），朝向保持不变 | `hesitateSeconds` ∈ [0.6, 1.2]（rng）→ `backoff` |
| `backoff` | 沿「背离玩家」方向走，速度 `backoffSpeedScale` × 1.2；**每步过 `steerIntent`**（退路也要能走） | 累计退够 `backoffDistance` ∈ [1.0, 2.0] 格（rng）**或**退不动（撞墙）→ `replan` |
| `replan` | 清 `PathCache` 该 id 条目 + 踱步 `paceSteps` ∈ [1,2] 步（侧向小位移） | 立即 → 下一拍按新规划：有路 `chase` / 无路计一次失败 |
| `wander` | 在**退开后的位置附近**小幅踱步（半径 `wanderRadius = 2.0` 格），周期性重试寻路 | 每 `wanderRetrySeconds = 2.0` 重试；有路 → `chase` |

**载荷性细节（每条都是已知陷阱的防线）**：

1. **`hesitate` 期间零速度 ⇒ 朝向不变**（`setIntent` 的「静止保持朝向」契约，v2.40 明载）。
   这正是「愣一下」的观感来源，不需要额外字段。
2. **`backoff` 的方向必须过避障**：背后也可能是墙。退不动时**立即结束 backoff**（不硬顶），
   否则会复现「贴墙蹭」的镜像形态。
3. **`replan` 必须清缓存**：`PathCache` 缓存可达路径 4 秒（`maxAgeMs`）。不清它，
   后退后的重算会命中旧路径 ⇒ 又走回墙边（v2.49「绕过障碍后回头」的同类根因）。
4. **失败计数只在「重算后仍无路」时 +1**，`chase` 成功走够一段距离就归零 ——
   否则玩家绕柱子跑动会让计数虚高、丧尸莫名进入徘徊。
5. **`wander` 不是「站死」**：它是小幅踱步（有位移、有步态动画），且**必然周期重试**。
   玩家拆墙后最迟 2 秒恢复（既有「拆墙后恢复 chasing」用例的语义必须保住）。
6. **状态与计时全部存 `_navMemory` 的 per-zombie 条目**，`nowMs` 驱动，不用帧计数
   （帧率无关）。`_releaseSlot` 已回收 ⇒ 无泄漏、id 复用不带上一只的记忆。
7. **`mode` 白名单扩展**：新增 `'hesitating'` / `'backing'` / `'wandering'`。
   ⚠️ `normalizeMode` 是**单一实现**（`createState` 与 `setIntent` 共用），
   漏改一处的形态是「速度位置全对、只有 mode 错」（v2.40 实测踩过）。
   ⚠️ **`'blocked'` 保留**：既有 E2E「四面围死 → mode=blocked」用例一字不改
   ⇒ 围死（信号 C，几何上零可走邻居）仍报 `blocked`，不进犹豫循环。
   **这是有意区分**：「四面全是墙」是站住，「有路但走不到玩家」才犹豫。

### 4.4 速度包络（1.2 恒为上限）

最终速度 = `方向 × ZOMBIE.speed × scale`，`scale` 由三项相乘后**钳到 [0, 1]**：

| 项 | 取值 | 依据 |
|---|---|---|
| 巡航漂移 | **0.92 ~ 1.0**，周期 3~5 秒的慢正弦（相位由 id 派生，避免全场同步） | §3.3 实测：低于 0.90 会让既有 E2E 红 |
| 起步加速 | 从静止到巡航需 `accelSeconds = 0.35` 秒线性爬升 | 「起步有过程」；0.35s × 1.2 ≈ 0.2 格损失，远在 E2E 余量内 |
| 转向减速 | 本拍方向与上拍夹角 θ ⇒ `× max(turnSlowFloor=0.7, 1 − θ/π × 0.5)` | 拐弯时慢下来更像活物；只在**转向那一拍**生效，不累积 |
| `backoff` | `backoffSpeedScale = 0.55` | 后退该比前进慢 |
| `wander` 踱步 | `wanderSpeedScale = 0.45` | 徘徊是慢速小步 |
| `hesitate` | **0** | 愣住 |

⚠️ **巡航漂移的下界 0.92 是实测约束不是审美值**（§3.3）。改它前必须重跑那条 E2E。
⚠️ **三项相乘后仍要过 `_applyIntent` 的既有钳制** —— 速度上限权威只有一处（红线 1）。
⚠️ **转向减速不得写成「每帧累乘」**：那会让丧尸在连续绕行中越来越慢直到停住
（本轮探针 probe7 第一版就踩了这个：每物理帧缩放 ⇒ 一个 AI 周期缩了 3 次，量出 0.85³=0.614）。

### 4.5 与既有行为的交互

| 场景 | 行为 | 说明 |
|---|---|---|
| 开阔地无障碍 | 巡航 0.92~1.0 倍 + 起步加速 | 逐位零回归**不再成立**（这是本改动的目的），但方向逐位不变 |
| 1 格宽门 / 2 格高走廊 | **照旧能过** | 触发判据只看时间维度，不看侧向净空（§1.3） |
| 一格台阶 | 照旧 step-up | 物理与探针均未动 |
| 四面围死（零可走邻居） | `blocked`、零速度、朝向不变 | 既有 E2E 一字不改 |
| 围死解除（拆墙） | 下一周期恢复 `chasing` | 既有用例一字不改 |
| 排斥力 | **仍在 `_stepNavigator` 合成后叠加**，行为层只缩放「导航分量」 | ⚠️ 见下方载荷性说明 |
| 玩家超 80 格 | 现状（导航仍跑，本轮不加感知门） | 不顺带改 |
| 跨 column | 不受影响 | 行为层不改 position |

⚠️⚠️ **排斥力与速度包络的顺序是载荷性的**（v2.47 实测教训的延续）：
现有链路是「导航方向 × speed + 排斥力 → `_applyIntent` 钳制 → `steerIntent`」。
本轮**速度包络只乘导航分量**，排斥力照旧全额叠加 —— 否则 20 只同点生成时排斥力被一起缩小，
「强制同点必须散开」的既有 E2E（min > 0.4、重叠对数 < 20）会红。
`hesitate` 的「零速度」同理指**导航分量为零**，排斥力仍可推开它（与 v2.40 `blocked` 的
既有语义完全一致：「不沿所请求方向前进」而非「绝对不动」）。

### 4.6 转身限速（用户裁定：只限速，不做头身分离）

在 `setIntent` 的 yaw 派生处加限速：`yaw` 朝 `atan2(vx,vz)` 每拍最多转
`turnRateDegPerSec × dt`。

实测（探针在 `setIntent` 出口限速，只用现有 `state.yaw` + 本拍 dt，**零新增字段**）：

| 限速 | 单帧最大转身 | 朝向滞后位移 max / 均值 | 90° 转身耗时 |
|---|---|---|---|
| 现状 | **135°** | 0° | 0（瞬时） |
| 360°/s | 18° | 117° / 1.2° | 0.25s |
| **540°/s** | **27°** | 108° / **0.7°** | **0.17s** |
| 720°/s | 36° | 99° / 0.5° | 0.13s |

取 **540°/s**：单帧最大 27°（对比现状 135°，改善 5 倍），平均滞后仅 0.7°
⇒ 不会出现「走左边看着右边」。

⚠️ **max 滞后 108° 出现在方向突变那一瞬**，是限速的必然代价，且只持续 ~0.17s。
⚠️ **dt 用决策周期 `ZOMBIE.aiPeriod`（0.05s）**，不用渲染帧 dt —— `setIntent` 由
20Hz 导航驱动，用帧 dt 会让限速随帧率漂移。
⚠️ **静止时不转**（`moving` 判据不变，`ZOMBIE_MOVING_EPSILON`）。
⚠️ **必须走最短弧**（`wrap` 到 ±π）：否则 yaw 从 +179° 到 −179° 会绕 358° 转一圈。
#### 4.6.1 限速接在哪里 —— 两处自我纠正（都是实测推翻的直觉）

**初稿想接 `setIntent`** → 否掉：它是通用意图写入口（物理用例、调试代码直接下令），
探针/限速长在里面会偷换「想让它走就必须能走」的语义（v2.40 已立的边界）。

**二稿想接 `_applyIntent` 并声称「既有 yaw 断言不受影响」→ 实测证伪**：
`test-zombies.js:920` 的「朝向从速度派生（移动跟随、静止保持）」用例走的**正是**
`zombies.update(aiPeriod, …)` → `_stepNavigator` → `_applyIntent` → `setIntent`
（探针实测：`_applyIntent` 调用 1 次、`setIntent` 调用 1 次）。
它只推进**一拍**就断言 `assertClose(st.yaw, atan2(vx,vz), 1e-9)`。
540°/s 下一拍只能转 27° ⇒ yaw = **0.471239** 而断言要求 **1.570796** ⇒ **必红**。

⇒ **正确落点：`_applyIntent` 内、`setIntent` 之后，作为「AI 决策路径专属的朝向后处理」**，
并**同步改写那条既有用例**：它钉的不变式是「朝向由速度派生、静止保持」，
在限速语义下该不变式的正确表述是「**朝向朝速度方向单调逼近，收敛后等于 atan2**」。
故用例改成：推进足够拍数（≥4 拍 = 0.2s）后断言 `yaw ≈ atan2`，
并**新增**一条「单拍不得超过限速上限」。

⚠️ **这是「按新裁定重标既有断言」而不是放宽**：断言仍钉同一个不变式（朝向源自速度），
只是观察窗口从 1 拍改为收敛后，且**补上了限速本身的上界断言**（旧用例对限速零判别力）。
⚠️ **`setIntent` 直接调用仍瞬时朝向** —— 通用写入口的契约一字不改，
由 §6.2 的「直接 setIntent 仍瞬时」用例守住。

## 7. 性能

新增每拍（20Hz × 20 只 = 400 次/秒）计算：环形缓冲 push/shift（≤30 项）+ 几次三角函数
+ 状态机分支。**不新增 `isSolid` 调用**（卡住检测读位置历史，不探地形）——
这是选「时间维度判据」的附带收益（几何判据每拍要多探 6~16 次 AABB）。

⚠️ `backoff`/`wander` 会调 `steerIntent`（既有成本，实测最坏 18 次 `isSolid` / 1.75µs）。
沿用既有 fps 门（`zombies.spec` 压力用例 `fps > 90`），**不新增计时断言**
（微秒级开销做计时断言只会引入 flake，testing-policy §2.5）。

**不跑 `bench --check`**：不碰 mesher / materials / render-world / scheduler / physics。

## 8. 风险与已知取舍

1. **既有 12s 绕墙 E2E 是最高风险项**（§3.3 实测余量只有 0.80 倍率）。
   巡航下界 0.92 + 「正常绕墙不触发犹豫」两条约束就是为它设的。若仍贴线 flaky，
   **停下来报告实测分布，不擅自放宽断言**（项目规则）。
2. **后退时背对玩家**（用户裁定不做头身分离）。观感是「倒着走」而非「盯着玩家退开」。
3. **转身瞬间朝向滞后最多 108° / 0.17s**（限速的必然代价，均值仅 0.7°）。
4. **徘徊可能被读成「AI 卡了」**：靠「有位移 + 有步态 + 2s 重试」缓解；
   用户已选「明显但不呆」的 0.6~1.2s 犹豫时长。
5. **速度波动让「逐位零回归」不再成立**：这是本改动的目的。共用层（②④）仍逐位零回归，
   由既有 28 + 12 条用例守住。
6. **随机性与红线 2**：世界生成确定性不受影响（行为层不参与生成）；
   丧尸是临时实体、不入存档，故 rng 不污染存档确定性。
