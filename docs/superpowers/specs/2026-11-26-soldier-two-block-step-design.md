# 士兵上台阶能力：1 格 → 2 格（3 格仍上不去）

日期：2026-11-26　范围：小型改动（4 个源文件 + 测试）

## 意图与为什么

用户 2026-11-26：「现在 soldier 掉进坑里一般情况是出不来的……我增加一下他上台阶能力，
可以上 2 级台阶，三级台阶就上不去了。」

目标是让士兵能自己走出 ≤2 格深的坑 / 走上 ≤2 格高的台，不再卡在坑底挨打或干脆不动。
**只改士兵**，丧尸 / 焰魔 / 末影守卫 / 玩家的能力一格不动（用户没要求改它们）。

## 现状（实测，不是读注释推断）

士兵的物理 / 避障 / 寻路全部转调丧尸那套共用实现，`SOLDIER.maxStep = 1.0`。
用真实 `physicsStepAabb`（平地 y<10 实心，x≥5 的列加高）跑 240 帧：

| 台阶高 | 落点 | 结论 |
|---|---|---|
| 1 格 | y 10→11，x=27.50 | 走上去 |
| 2 格 | y 恒 10，x=4.70 | 卡住 |
| 3 格 | y 恒 10，x=4.70 | 卡住 |

**关键约束**：只把 `maxStep` 改成 2.0 **完全无效**。`zombieStepUpY(y) = floor(y+0.01)+1`
恒抬 1 格，`maxStep` 只是「抬升量 ≤ maxStep」的门控 ⇒ 1.0 与 2.0 逐位等价
（`docs/pitfalls.md`「maxStep 是死值」已记；本轮复测 maxStep=2.0 时 2 格台阶仍卡在 x=4.70）。

`zombieStepUpY` 是丧尸 / 焰魔 / 守卫 / 玩家共用的唯一实现，直接改它等于给全部实体加能力。

## 方案取舍

**选定：共用层加「多级抬升解析器」，按 `box.maxStep` 决定试几级。**
从 `floor(y+0.01)+1` 逐级往上试，取第一个「AABB 不碰撞」的高度；抬升量超 `maxStep` 即停。
`maxStep=1.0` 时循环只跑一次 ⇒ 与现状**逐位等价**，丧尸 / 焰魔 / 守卫 / 玩家零回归。

四个消费点统一转调它（红线 1，一处判据只留一份）：
物理 `tryStepUpAabb`、避障探针 `probeClearAabb`、A\* 的 `standable`、士兵 `isWalkable`。
漏掉任一处的形态是「探针以为能上、物理抬不上去」或「A\* 规划得出、物理走不通」——
数值全绿，只能靠实玩发现。

否掉的两条：
- **给士兵写第二套物理**：红线 1 禁止第二份判据，必然漂移。
- **改 `zombieStepUpY` 本身**：连带改丧尸 / 焰魔 / 守卫 / 玩家，超出请求范围。

## 观感（用户裁定）

用户选「整段 2 格都缓动」。`StepLift` 的滞后上限现在写死 `MAX_LAG = 1.0`，
一次抬 2 格会被截断成「瞬时跳 1 格 + 缓动 1 格」（实测 `trigger(2)` → offset=−1）。
改为**构造参数** `new StepLift(maxLag)`，缺省仍是 1.0 ⇒ 玩家 / 丧尸 / 焰魔 / 守卫逐位不变；
士兵渲染器传 `SOLDIER.maxStep`。衰减率与归零阈值仍是全局唯一一份，不参数化。

## 目标 / 非目标 / 反目标

- 目标：士兵能上 1 格与 2 格台阶；物理、避障探针、A\*、`isWalkable` 四处口径一致。
- 非目标：不改跳跃（士兵不会跳）、不改重力 / 速度 / AABB 尺寸、不做跨层寻路。
- 反目标：3 格台阶被上去；空中贴高墙下落时被一格格「爬」上去；丧尸 / 焰魔 / 守卫 / 玩家
  的台阶能力或缓动手感发生任何变化。

## 验收判据

1. Node 单测（真实 `physicsStepAabb`，非手工调 trigger）：1 格上 / 2 格上 / 3 格卡住；
   `maxStep=1.0` 的 box 在 2 格台阶上仍卡住（零回归守卫）。
2. 探针与 A\* 与物理同口径：2 格台阶不被判 blocked、A\* 给出朝向台阶的第一步。
3. 空中贴 8 格高墙下落 `maxY` 不升高（原型已验：18.00 → 18.00）。
4. `StepLift` 缺省行为逐位不变（既有 `test-step-lift.js` 三条不改）。
5. 士兵渲染：2 格抬升后欠下 −2 偏移、~200ms 内追平、单调上升。
6. E2E（真游戏页）：士兵从 2 格深坑里自己走出来；3 格深坑里出不来。
7. 负向验证：注掉多级循环后，2 格用例必须真 FAIL。
