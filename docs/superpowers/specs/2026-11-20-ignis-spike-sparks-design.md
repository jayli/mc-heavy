# 焰魔尖刺攻击：破土火星与上浮余烬（v3.23）

> 用户 2026-11-20 需求 + 两项选型裁定。本文是设计文档（小改动档），实施与实测数据见 §6。

## 1. 意图与由来

用户原话：

> 我想让焰魔的尖刺攻击特效中，从地面升起的若干个尖刺升起的时候，带有粒子特效，
> 丰富一下视觉体验，就好像蹦出的火星一样。

**两项选型裁定**（`ask_user_question` 实测回答）：

| 问题 | 用户选择 | 被否的选项与理由 |
|---|---|---|
| 火星节奏 | **破土猛迸 + 余烬渐稀** | 「只迸一次」⇒ 保持期 700ms 里刺是静止的；「全程持续冒」⇒ 盖过刺的形体，且与法阵/火圈观感撞车 |
| 粒子构成 | **条状火星 + 少量上浮余烬** | 「只要条状」⇒ 少了烧着的碎屑慢慢飘那一层；「加烟团」⇒ 5 根刺各冒烟会糊成灰雾，且烟是非加法混合会压暗地面 |

## 2. 目标 / 非目标 / 反目标

**目标**
- 5 根火焰尖锥**破土那一瞬**迸出条状火星，出生点沿破土环分布、高度跟着升起进度上爬。
- 保持期只剩零星余烬往上飘；**尖锥开始缩回时停发**（火星跟着刺走）。
- 零新增贴图 / 零音效 / 零烘焙产物 / 零依赖。

**非目标**
- 不改尖刺的几何、伤害（18）、落点（正前方 2/4/6/8/10 格）、递延（0/50/100/150/200ms）、寿命（900ms）。
- 不改动画、AI、相机；不加面板开关。
- 不动法阵 / 火圈 / Cinder Fall / Storm Lance 的任何参数。

**反目标（做成了也算失败）**
- 常驻 draw call 增长（零活跃时三个 mesh 必须 `visible=false`）。
- 火星在延迟期内先冒出来（刺还在地里）。
- 尖锥回收时把在飞的粒子硬切掉。
- 粒子读作「爆米花 / 烟花」（圆点羽化 quad）而不是条状火星。

## 3. 现状与约束（已核实）

| 基建 | 文件 | 本轮用途 |
|---|---|---|
| 尖锥包络与池 | `render/spike-fx.js` 的 `spikeScaleAt` / `SpikeFxRenderer` | **复用同一份进度**，不另写时序 |
| 暖色 GPU 粒子 TSL | `render/fire-ring-material.js:makeSparkPass` | 结构逐字沿用（已过像素实测） |
| 火星/余烬双 pass 分工 | `render/cinder-fall-material.js:makeParticlePass` | 同上 |
| 火焰色阶 | `render/cinder-fall-config.js` 的 `colorSpark*` / `colorEmber*` | **直接引用**，不另写一套橙 |
| 地面查找 | `Game._findSigilGroundY` | 落点 y 仍由装配层给（渲染层不查体素） |

**关键约束**
- `spike-fx.js` 已 import `IGNIS_SPIKE`；新常量表若 import `spike-fx.js` 会**循环** ⇒
  `shrinkFrom` 的权威放在 three-free 的 `spike-fx-config.js`，`SPIKE_FX.shrinkFrom` 派生自它。
- 粒子必须 `THREE.Mesh` + `InstancedBufferGeometry`（`InstancedMesh` 的 instanceMatrix
  会接管 modelViewMatrix，把粒子全塌到原点 —— v3.21 实测）。
- `aSpawn` 与 `uTime` 必须同一时钟（绝对秒）。

## 4. 设计

### 4.1 新增三件（照 cinder-fall / fire-ring 的分工）

- **`render/spike-fx-config.js`**（three-free）：观感常量 + 两个纯函数
  - `spikeSparkQuotaAt(livedMs, kind)` → **累计**配额（三段：猛迸 / 渐稀 / 停）；
  - `spikeSparkSeeds(spike, progress, kind, count, rand)` → 出生数据（环上面积均匀采样）。
- **`render/spike-fx-material.js`**：`createSpikeSparkMaterial()`（条状）/
  `createSpikeEmberMaterial()`（圆点）/ `createSpikeSparkGeometry(cap)`。
  uniform **按调用闭包捕获**（v3.22 教训：模块级 `let U` 会让两个池互相覆写）。
- **`render/spike-fx.js` 扩充**：两个共享 GPU 池 + `_emitSparks` / `_decayParticles` / `reset`，
  `meshes = [cone, spark, ember]`。

### 4.2 发射逻辑（逐根按累计配额差值）

```
lived = nowMs − bornAt − delayMs          // 自「破土」起，不是自 spawn 起
want  = spikeSparkQuotaAt(lived, kind)    // 累计量
if (want > s.emitted) emit(want − s.emitted); s.emitted = want
```

- **累计差值**而不是 `ceil(rate×dt)`：后者在低速率下会因取整而永不发射或恒发射。
- 配额函数在 `lived ≥ lifeMs × shrinkFrom` 后**不再增长** ⇒ 缩回段自然停发，
  不需要另写一道「是否在缩回」的门（两处各写一份就是第二个权威）。
- 出生高度 = `y + climb(0.55) × progress × height` + 抖动 ⇒ 跟着锥面上爬，
  但主体仍贴地（`climb=1.0` 会读作「刺在喷火」而不是「破土迸火星」）。

### 4.3 观感参数（**像素实测标定，不是拍的**）

| 项 | 值 | 依据 |
|---|---|---|
| 破土速率 | 240 颗/秒 | 首版 150 在 4 格交战距离只得 193 暖色像素 ⇒ 读不出火星 |
| 保持速率 | 26 颗/秒 | 与破土段拉开 ~9 倍（「渐稀」而非匀速冒烟） |
| 火星尺寸 | 0.10 格 | 首版 0.055 只投影成 **2.3px**（实测中位数）⇒ 画面上等于没有 |
| 余烬尺寸 | 0.063 格 | 同步 ×1.8 |
| 池容量 | 768 | 单类最坏并发 = 55×5×2 = 550（两批重叠，推导见常量注释） |

**同机位单变量扫描**（密度 × 尺寸，4 格距离，冻住全部动态源）：

| 变体 | 暖色像素峰值 |
|---|---|
| 基线 150 / 0.055 | 193 |
| 尺寸 ×1.8 | 425 |
| **密度 ×1.6 + 尺寸 ×1.8（采用）** | **884** |
| ×2.2 / ×2.2 | 1655（开始糊成一片） |

## 6. 实施期实测记录（以本节为准）

### 6.1 Tier 4 夹具的五个动态源（缺一则判据零判别力）

本轮**逐个隔离实测**定位，全部是「基线自己在动」而不是生产缺陷：

| 源 | 未处理时的噪声底 | 处理手法 |
|---|---|---|
| 玩家仍在下落 | 整帧 264692 像素（camY −5.59→−7.38） | `setInterval` 钉 `physics.pos` |
| 海面波纹 | [450, 0, 450, 0, 450] 双态 | `ocean.update = (cam,dt)=>orig(cam,0)` |
| 第一人称手臂待机摆动 | [68, 0, 0, 0, 68] | `viewArm.mesh.visible=false` |
| 昼夜天空色漂移 | [450, 494, …] | `dayNight.update = ()=>{}` |
| **viewBob / stepLift 衰减** | **[30, 0, 30] 双态** | 两个 `update` 换空转 |

⚠️ **钉 `physics.pos` 不够**：相机 y 还要叠 `viewBob.offset` 与 `_stepLift.offset`
（`player.js:386`），传送后两者仍在衰减 ⇒ 相机每帧微动。这是最后一个噪声源。

另：**等 3.5s 而不是 2s**（远处 column 仍在流式上传），并加「等相邻差分为 0」的二次保险。
最终噪声底 **0~1**，有效噪声底改用**同会话零粒子对照组**自校准（`controlFloor`）。

### 6.2 判据选型的两次自我修正（都是负向验证逼出来的）

- **`/stretch/i` 零判别力**：把 `stretch` 改成常量 1 后仍全绿（变量名还在）。
  同理 `0.18` 这个字面量在同一函数里被 jitter 项用到 ⇒ 也假绿。
  改钉**表达式结构** `stretch = float(1).add(` + `length(velNow)` + `FX.sparkStretch`。
- **像素质心/顶边对「余烬往下掉」全部零判别力**（四种口径逐个实测推翻）：
  `emberRise` 改 −9.5 后像素数仍过关；改量**暖色质心**也不行 ——
  **出生高度本身随锥面上爬**（`climb × progress × height`），后期出生的余烬天然更高
  ⇒ 退化态质心仍上移（实测退化 rise **41~46px** vs 正确 **48~61px**，**分布重叠**）。
  归一化（除刺的像素高）、暖色顶边、刺尖参照三种同样重叠。
  **正解：只量粒子相对自己出生点的位移**（去掉出生高度这个混淆项）——
  读 `aOrigin/aVel/aSpawn/aLife` 四个**真实 GPU 属性**，按 shader 闭式解
  `dy = vel.y·(1−e^(−drag·t))/drag + g·t²/2` 在 CPU 侧算。
  实测正确态 minDy **+0.008~+0.028** / lateNeg **0**；退化态 **−0.66** / lateNeg **7/7** ⇒ 完全分离。
- **源码级钉常量字面量不成立**：重力/阻力/屏幕上钳都经 `P` 表取值 ⇒
  字面量根本不在 shader 源码里（实测只有 `float(P.gravity)`）。
  改为「结构存在」+ **CPU 闭式复刻运动**钉观感事实。

### 6.3 顺手修掉的既有 flaky（与本改动无关，已用 HEAD 副本核实）

`tests/ignis-spike.spec.mjs` 的「火焰尖锥真的画出来了」在 **HEAD 上连跑 3 轮 2 红**
（「寿命结束后须全部回收」读到 5）：焰魔 idle 约 1.5s 后自然起手，若那一招是尖刺攻击
就会再出 5 根。修法照 `ignis-fx.spec.mjs` 既有口径 —— 采样后钉 `attackCooldown: 999`。
**断言一字未改**，只排除「焰魔又打了一招」这个无关变量。修后 3/3 绿。

### 6.4 最终实测数据

- 噪声底 **0~1**；零粒子对照组 `controlFloor` **1**。
- 只火星峰值 **692 / 893**；只余烬峰值 **448 / 354**；两者合计 **1031 / 919**。
- 余烬相对出生点位移 minDy **+0.008~+0.028**（全为正）、后半寿命下沉数 **0**。
- 色相 **r 216.1 / g 181.8 / b 137.6**（r−g = 34.3）；近白 **76**（占 clip 0.026%）。
- 写入颗数：火星 **247** / 余烬 **81**（5 根，符合配额终值）。
