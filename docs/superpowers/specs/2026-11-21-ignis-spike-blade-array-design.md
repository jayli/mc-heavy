## 2. 现状（改动前，全部实测）

### 2.1 几何与材质

### 2.2 落点与节奏

`spikeSpawnPoints(at, yaw)`：正前方 `(−sin yaw, −cos yaw)` 上 2/4/6/8/10 格，
延迟 `i × 50ms` = 0/50/100/150/200。包络 `spikeScaleAt`：升起 180ms → 保持到寿命 70%（630ms）
→ 缩回到 900ms。

### 2.3 粒子（v3.23）

同一渲染器另带两个 GPU 池（火星条状 + 余烬圆点），容量各 768，逐根按累计配额差值发射：
每根火星 **55** 颗、余烬 **18** 颗（`burstRate 240 / trickleRate 26`，余烬 `77 / 10`）。

→ 玩家 AABB 与任一根的**那一格**重叠则扣 `IGNIS_SPIKE.damage = 18` 并 **break**（一次命中帧只扣一次）。

## 3. 剑体几何：实测推导

### 3.0 ⚠️⚠️ bind 姿态下 skinning 是恒等变换 —— 不能再乘骨骼链

实测（全部 1920 顶点）：`SkinnedMesh.applyBoneTransform(i, v)` 在 bind 姿态下与 raw 顶点
最大差 **8.882e-16** ⇒ **产物顶点已经是绝对模型坐标**（`bake-ignis.mjs` 的
「cube 顶点是绝对模型空间坐标，直接写入，不乘骨骼矩阵」）。

所以剑体几何**直接取 raw `geometry.position`**。反向验证过：手写骨骼链
（`localPosition` + `bindQuaternion` 层级累乘）再乘一次，`sword_blade` 的顶点偏 **0.466 格**
—— 正是 AGENTS.md 里守卫那条「顶点预乘 bind 世界矩阵」的**镜像坑**（守卫是 Java 局部顶点所以必须预乘，
焰魔是 Bedrock 绝对顶点所以绝不能乘）。

判据：`test-spike-blade.js` 要同时钉「与 raw 顶点逐位一致的轴置换」与「剑尖盒 bbox 落在预期区间」
—— 只钉前者拓不到「多乘了一次」，只钉后者拓不到「轴置换写错」。

### 3.1 剑的分段（从 `assets/ignis/ignis.json` 的 raw 顶点按骨骼分组求得）

沿剑轴 z 排序（越负越靠剑尖）：

| 骨骼 | 盒数 | z 区间 | 语义 |
|---|---|---|---|
| `sword_blade` | 1 | [−2.968, −2.657] | **剑尖**（宽 0.311，收细） |
| `sword`（第 3 盒） | 1 | [−2.813, −0.313] | **剑身**（宽 0.4375、厚 0.0625） |
| `sword_guard` / `sword_guard2` | 8 + 8 | [−0.719, −0.219] | 上下护手 |
| `sword_blade3` | 3 | [−0.488, +0.044] | 根部装饰 |
| `sword`（第 1/2 盒） | 2 | [−0.125, +0.750] | 剑柄 + 柄箍 |
| `sword_core` / `sword_core2` | 1 + 1 | [+0.831, +1.231] | 柄球 |

**取剑身 + 剑尖两盒**，48 顶点 / 24 三角。

⚠️ **不硬编码顶点下标**（现值 `[1248, 1296)`）—— 素材换版/烘焙顺序变了下标就漂。
稳定筛选规则（实测唯一）：
- **剑身** = `sword` 骨骼下 **z 跨度最大**的盒（2.5000，第二名 0.7500，差 **3.3 倍**）
- **剑尖** = `sword_blade` 骨骼名下的盒（只有 1 个）

实测 bbox：

```
raw bbox  min[−1.34375, 0.56875, −2.968125]  max[−1.28125, 1.00625, −0.31250]
长(z) L = 2.655625   宽(y) = 0.43750   厚(x) = 0.06250
```

### 3.2 「露出 1.6 格且护手不露」是天然成立的，不需要裁切

护手最近端 z = −0.219 ⇒ 距剑尖 **2.749** 格；根部装饰最远端 z = −0.488 ⇒ 距剑尖 **2.480** 格。
两者都 > 1.6 ⇒ **只取剑身两盒并把露出段定为 1.6 格，护手/柄/柄球一个盒都不在几何里**。

⚠️ 这不是「靠深度遮挡藏起来」——那些盒**根本不进几何**。差别在于：靠遮挡藏的话，
玩家蹲下/挖开地面/从侧面低角度看就会露出柄，而「压根不烘焙」在任何视角都成立。

### 3.3 立起变换（唯一入口，纯函数）

剑在模型里沿 **−Z** 躺着。立起需要：

```
local.x = raw.y − centerY                       // 剑面宽 → 世界 X
local.y = (maxZ − raw.z) − (L − exposeHeight)   // 剑轴 → 世界 Y，剑尖在上
local.z = raw.x − centerX                       // 剑厚 → 世界 Z
normal:  (nx, ny, nz) → (ny, −nz, nx)           // 同一轴置换，不平移
uv:      原样搬（产物 UV 已正确，见 §3.5）
index:   逐三角减区间断起点（只取两盒内部的三角）
```

法线置换的逐面验证：`+X`（厚面）→ `(0,0,1)` 世界 Z ✓；`+Y`（宽面）→ `(1,0,0)` 世界 X ✓；
`−Z`（剑尖端）→ `(0,1,0)` 世界 +Y ✓。

代入实测值（`L = 2.655625`、`exposeHeight = 1.6`）：

```
x ∈ [−0.218750, +0.218750]   y ∈ [−1.055625, +1.600000]   z ∈ [−0.031250, +0.031250]
```

⇒ 地面 y=0 处横截面 **宽 0.4375 × 厚 0.0625**（原剑尺寸，裁定②），
剑尖在 y=1.6，y<0 的 **1.055625** 格埋在地下。索引 72 个（24 三角），最大下标 47。

**为什么三轴同比例 `scale` 仍然正确**：`spikeScaleAt` 的 scale 作用于整个几何，
y 范围变成 `[−1.0556s, +1.6s]`，地面 y=0 不动 ⇒ 露出高度恰好 `1.6s`，
读作「整根从地里长出来」。与锥体 `translate(0, h/2, 0)` 同一分工。

### 3.4 朝向：宽面朝焰魔

剑宽沿 X、厚沿 Z ⇒ 宽面法线 = ±Z。实例 `rotation.y = θ` 后法线 = `(sin θ, cos θ)`。
径向 outward = `(−sin(yaw+deg), −cos(yaw+deg))` ⇒ 取 **θ = yaw + deg + π** 时法线与径向点积
恒 **+1.000**（五个方向逐一实测）。

⇒ 焰魔站在圆心看每一根剑，都看到**宽面**（金纹那一面）；玩家从焰魔背后看过去同样是宽面。
若朝向写成 `yaw + deg`（不加 π），法线朝内，看到的是同一宽面的背面 —— 因为 `DoubleSide`
画面几乎一样，**但侧面 45° 时会看到 0.0625 厚的窄边**（实测投影面积差 7.8 倍）。故朝向要钉。

### 3.5 贴图：直接用原色，删掉烧炭色阶

剑身两盒的**六个面 UV 全部 100% 不透明**（pngjs 逐面实测）：

| 面 | 剑身盒矩形 | 剑尖盒矩形 |
|---|---|---|
| +X | (131,128,171,135) | (33,5,38,10) |
| −X | (90,128,130,135) | (27,5,32,10) |
| +Y | (131,88,132,128) | (33,0,34,5) |
| −Y | (130,88,131,128) | (32,0,33,5) |
| +Z | (171,128,172,135) | (38,5,39,10) |
| −Z | (130,128,131,135) | (32,5,33,10) |

⇒ 产物 UV 已经是正确的（烘焙器 `boxUVRects` 已验），**材质只需 `map` + `alphaTest`**，
不需要 UV 重映射、不需要亮度→色阶、不需要逐根随机铺贴。

离线光栅化验证（`/tmp/blade-face.png`、`/tmp/blade-35.png`）：紫褐剑脊 + 金色嵌纹 + 两侧金边，
与焰魔手里那把逐格同源。

**这是本轮最大的减法**：`charcoalRamp` / `charcoalWindow` / `charcoalGain` / `wrapTiles` /
`riseTiles` / `textureRect` / `spikeTexUvRect` / `spikeTexPattern` / `SPIKE_TEX_ATTR`
四个 instanced 属性 + `createSpikeConeMaterial` 整个 TSL 材质，全部**删除**。
用户原话「现在的圆锥体的带有纹路的尖刺模型不要了」⇒ 不是「在锥体上换贴图」，是换几何 + 换着色口径。

⚠️ **删的是「重映射」这一层，不是「贴剑贴图」这件事**：新观感仍然是剑贴图，只是**原色直采**。
v3.24 之所以要重映射，是因为锥面 UV 与剑的 UV 语义不对应（锥面是环绕 0..1，只能取一条带）；
现在几何本身就是剑，UV 天然对齐，重映射失去存在理由。

### 3.6 混合与绘制顺序

- `blending: NormalBlending`（沿用 v3.24 裁定：additive 在亮天空前必然钳白，金纹出不来）
- `alphaTest: 0.5` + `transparent: false`？**不** —— 仍走 transparent 队列（`transparent: true`,
  `depthWrite: false`），理由：逐根淡出靠 `instanceColor`，且与自己的粒子层共存需要 depthTest 不写深度。
  ⚠️ 剑身 UV 100% 不透明 ⇒ 不需要 alphaTest 也能无黑洞，但保留 `alphaTest: 0.5` 作为
  「换素材后出现镂空」的兜底（与 `ignis-renderer` 同口径）。
- `side: DoubleSide`（0.0625 厚的薄片，单面会从侧面看穿）
- `renderOrder = SPIKE_SPARK_FX.renderOrder`（= 3，必须 > 海面 1；v3.24 实测冲淡 1.77 倍）
- `fog: false`（远处不被雾洗成天空色）

## 4. 阵列：五向 × 6 根

### 4.1 方向表（唯一权威）

```js
IGNIS_SPIKE.directionsDeg = [0, -45, 45, -90, 90]   // 前 / 左前 / 右前 / 左 / 右
IGNIS_SPIKE.count = 6                              // 每方向根数
```

**左右的归属实测**：本仓 yaw 下 `deg = −90` 的方向与模型 **+X**（`left_arm` / 盾所在侧）
点积恒 **+1.00**（yaw = 0 / 0.7 / π/2 / 2.3 四档逐一验），`deg = +90` 恒 −1.00。
示意图是从焰魔**背后上方**看（正面在上、背面在下）⇒ 图左 = 焰魔自己的左手侧 = 模型 +X ⇒ **左侧 = −90**。

⚠️ 这条不能凭直觉：`yaw + 90°` 在标准数学直觉里是「左转」，但本仓 yaw 的前向是
`(−sin, −cos)`（顺时针增长），`+90` 实际落在模型右手侧。写反的形态是**整个阵列左右镜像**，
而根数/间距/延迟/半圆轮廓**全部仍然正确**（静默失效）。判据要钉「左侧方向 · 模型左向量 > 0.9」。

### 4.2 落点与延迟

```
第 d 个方向、第 i 根：
  ang   = yaw + directionsDeg[d] × π/180
  dist  = spacing × (i + 1) = 2, 4, 6, 8, 10, 12
  x     = at.x − sin(ang) × dist
  z     = at.z − cos(ang) × dist
  delay = i × delayPerSegmentMs = 0, 50, 100, 150, 200, 250
  yaw   = ang + π            // 宽面朝焰魔（§3.4）
```

**「先内圈再外圈」天然成立**：延迟只与 i（半径序号）有关，与方向无关 ⇒ 同一半径的 5 根**同帧**破土，
读作「一圈一圈往外扩」。这与用户「先近再远」逐字一致，且**不需要新时序机制**。

实测（yaw=0，焰魔在原点）：
- 30 个落点占 **30 个互不相同的格**（`floor(x),floor(z)` 去重后仍是 30）
- 最近两点距离 **1.531 格**（左前 ↔ 左 的第一根），> 剑宽 0.4375 ⇒ 不互相穿模
- 半径档位 2/4/6/8/10/12，最远 **12 格**（原 10 格）

### 4.3 阵列范围与伤害的连带影响

伤害判据仍是「玩家 AABB 与任一根的那一格重叠 ⇒ 扣 18 并 break」。根数 5→30、扇区 0°→±90°
⇒ **命中面积显著变大**（半圆 12 格半径）。这是用户需求的直接后果（「把焰魔围成一个半圆圈」），
不是缺陷；**一次命中帧仍只扣一次 18**（break 不动）。

⚠️ 既有单测「玩家在两根之间的间隙不扣血」用的机位（z=−6.5）在新阵列下**仍不在任何刺格**
（正前方刺格 z ∈ {−2,−4,−6,−8,−10,−12}，−6.5 的 AABB 只压格 −7）⇒ 该用例语义不变。
但要复核「另两招不出尖刺」等用例的根数断言 5 → 30。

## 5. 粒子：速率÷2（不是÷6 —— 实测推翻了首版方案）

30 根各自按现速率喷 ⇒ 火星 55×30 = **1650 颗/次**（现 275），是 6 倍。

### 5.0 为何不取÷6（设计首版的错误，已实测修正）

首版打算÷6 保持总量持平。逐条跑既有断言后发现：**÷6 后每根只剩 9 颗火星**，
逐帧 16ms 的批次序列是 `[1,1,1,1,1,1,1,1,1]` ⇒ **每批恒 1 颗**，于是：

- `test-spike-sparks.js` 的「首批（破土）须多于末批（渐稀）」**直接红**（1 vs 1）；
- 那条断言是**真判别力**（它钉的正是用户裁定的「破土猛迸 + 渐稀」），不得放宽。

扇描五个档位（每档跑全部 9 条既有关系式）：

| 档 | 每根火星/余烬 | 批次序列首/末 | 9 条全过 |
|---|---|---|---|
| 现状（不降） | 55 / 18 | 4 / 1 | ✗ 池账（3300×… 超 768） |
| ÷6 | 9 / 3 | **1 / 1** | ✗ 首>末 |
| ÷4 | 13 / 4 | 1 / 1 | ✗ 首>末 |
| ÷3 | 18 / 6 | 1 / 1 | ✗ 首>末 |
| **÷2（采用）** | **27 / 9** | **2 / 1** | **✓ 全过** |

### 5.1 定稿参数

| 常量 | 现值 | 新值 | 每根颗数 |
|---|---|---|---|
| `burstRate` | 240 | **120** | 火星 55 → **27** |
| `trickleRate` | 26 | **13** | |
| `emberBurstRate` | 77 | **38.5** | 余烬 18 → **9** |
| `emberTrickleRate` | 10 | **5** | |

总量：火星 27×30 = **810 颗/次**（现 275 的 2.95 倍）—— 根数 6 倍而单根减半，
单位面积密度降到现状的一半，既不会糊成一片橙雾盖掉剑形体，也保住了单根的「猛迸→渐稀」节奏。

⚠️ **这是观感取舍，用户未明示** ⇒ 已在对话里说明。若用户要「每根都和现在一样密」，
只需还原四个速率（池容量 4096 装得下 3300）。

### 5.2 池账（关系式，不拍数）

```
每根火星 27 / 余烬 9
两刀间隔 = secondHitFrame − hitFrameSeconds = 1.225s
最长命 = 5×50 + 630 + 0.95×1.3×1000 = 2115ms > 1225 ⇒ 重叠 2 批
火星需 30 × 27 × 2 = 1620     余烬需 30 × 9 × 2 = 540
```

⇒ 现容量 768 **不够**（火星 1620）。取 **4096**（2 的幂），两池属性合计 320 KiB（现 60 KiB）。
4096 同时装得下「还原速率」那个口子（30×55×2 = 3300）。

⚠️ 容量判据仍走 `test-spike-sparks.js` 的**关系式**（`perCast × overlap ≤ capacity`），
不写死 4096 与颗数的等式 —— 改速率时关系式自动跟着算。
⚠️ `tests/ignis-spike.spec.mjs:378` 有一条 `expect(pre.capacity).toBe(768)` 的**硬值**，
要改成读常量（`SPIKE_SPARK_FX.capacity`）而不是再写一个 4096 —— 写第二份就是同一个事实两份。

### 5.3 实例池

`maxActive`：30 根 × 并发 4 招余量 = **120**（现 20）。
`instanceMatrix` 120×16×4 = 7.5 KiB，`instanceColor` 1.4 KiB ⇒ 可忽略。

⚠️ **draw call 不随根数增长**（`InstancedMesh` 一次提交），GPU 顶点缓冲也只有**一份几何**
（48 顶点，比锥体的 27 多 21）⇒ 容量预算（`gpuVertexBytes < 200 MiB`）无实质影响。

### 6.1 为什么不重烘一份「剑体产物」

会引入第二份权威：剑的顶点已经在 `ignis.json` 里，再烘一份 `spike-blade.json`
就有两份剑几何，改素材时要同步两处（红线 1）。运行期从产物取 48 个顶点 + 一次矩阵变换，
成本是**构造时一次**（不是每帧）。

### 6.2 产物拿不到时的回落（必须定，否则整层静默消失）

`game.js:802` 的 `loadIgnisAsset()` 在 try 里，失败时 `ignisRenderer = null` 而游戏继续。
剑体几何**依赖产物** ⇒ 必须定一条回落：

**决定：产物缺失时退回原来的 `ConeGeometry` 纯色锥**（`createSpikePlainMaterial` 保留）。
理由与既有容错口径一致 —— 「焰魔贴图/模型加载失败不该让尖刺整个不见」。

⚠️ 但**阵列不回落**：30 根五向落点是玩法侧常量（`IGNIS_SPIKE`），与产物无关 ⇒ 产物挂了
仍是 30 根锥体。这样「产物没加载」表现为**形状退化**而不是**招式消失**，可分辨。

⚠️ `createSpikePlainMaterial` 因此**保留**（原设计里它随剑纹材质一起删是错的），
`SPIKE_FX.color` 也保留给回落路径。Tier 1 要有一条用例钉「无 asset 时走锥体且不抛错」。
