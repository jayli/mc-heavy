# 放置就近优先（v2.25）设计说明

日期：2026-10-30　状态：**待用户确认**　规模：小改动（2 个源文件 + 测试 + 文档同步）

> **追加变更见 §10**（2026-10-30，用户）：命中 **< 15 格直接放命中面前**（对齐 mc-lite），
> 头格 / 压到身体的格保持本仓现状。§1~§9 描述的是追加前的设计，凡与 §10 冲突处以 §10 为准。

## 1. 意图与原因

用户原话：「不管十字准心方向经过多少个可放置方块的位置，总是先就近放置」。

现状在「命中」与「打空」之间有一道人为分界：

- 主射线**命中** → 一律放在命中面前一格 A（`target.prevPos`）；
- 主射线**完全打空** → 才跑 `findPlaceCell`，贴沿途最近的「看不见的侧面」格 B（v1.72，15 格）。

同一条视线，打到 40 格外放 B、打到 39 格放 A，落点随距离跳变；而且 A 在远端、B 在近端时，玩家明明擦过一个能接续的位置，却被远处的面抢走。要的是单调规则：**沿视线从近到远，第一个能放的位置就是落点，A 只是这串候选里最后一个。**

## 2. 目标 / 非目标 / 反目标

**目标**
- 单格方块的落点 = 沿视线从近到远第一个可放的候选；A 排在最后。
- 命中与打空走同一套流程（打空 = 没有 A 的特例）。

**非目标（不动）**
- B 的判据（非实心 / 有正交实心邻居 / 无实心邻居在视线前方 / 遇实心即截止）与 15 格搜索距离。
- 巢穴 / 炮塔 / 矿车：origin 仍取命中格，未命中仍不放。
- 身体守卫口径（v2.22：只拒绝与玩家 AABB 相交的**实心**方块）与 A 路径的行为。
- 命中高亮框（仍框命中块，落点可能不挨着它）、设置面板、HUD。

**反目标（技术上做到了也算失败）**
- 一次右键被「自己脑袋所在的格」或「压到身体的候选」吞掉。
- 落点越过命中格，或躲在遮挡物后面。
- 候选判据或身体守卫在 `place-ray.js` / `_placeSingle()` 之外出现第二份（红线 1）。
- 新增每帧开销（扫描只在右键 `mousedown` 时跑一次）。

## 3. 已定的规则

| 规则 | 来源 |
|---|---|
| 脑袋所在的格（= 相机所在格 = DDA 起点格）**不进候选**，对任何方块都生效；排除后再从近到远找 | 用户 |
| 候选被身体守卫拒绝 → 跳过，继续找下一个（mc-lite `doSkyPlace` 同款，现有兜底只试第一个） | 用户确认 |
| A 路径不动：实心被守卫拒、非实心（花、藤）仍可放进头格；A 被拒则不再找别处 | 用户确认 |
| 搜索止于主射线命中格（**不含**），命中格是非实心（花、藤）时同样截止 | 本文取舍：A 在命中格之前，越过它没有意义 |
| 15 格射程只约束 B；命中格再远（≤40）也可作 A | 本文取舍：沿用 v1.72 口径 |

## 4. 方案

- **方案一（选定）——候选「边扫边试」**：`place-ray.js` 提供按近→远逐个访问候选的扫描，`player.js` 把每个候选交给 `_placeSingle()`，第一个放成功的算数，最后才轮到 A。
- 方案二（弃）——命中时先用现有 `findPlaceCell` 探一个 B（跳过头格），找到放 B、找不到放 A。改动最小，但只试第一个候选：玩家身体宽 0.6，站位离视线前方那条格边界不到 0.3 时（每个方向约 30%），紧挨头格的下一格也会压到身体，那次右键整次作废（实测：天花板通道里朝 −X 看中心 x=3.10/3.25 被守卫拒、x≥3.5 才没事；朝 +X 看则 x>3.7 被拒）。这个洞今天只在打空路径上，方案二会把它带到普通右键上。

性能（Node 微基准，交替 9 轮取中位，合成单 column 世界）：无候选时两者均 1.8–4.3 µs/次；候选遍布的通道里方案二 0.41 µs、扫满版 4.93 µs。方案一做成「放成功即中止」后，常见情况与方案二持平；绝对值 ≤5 µs，仅右键触发，对照放/挖编辑路径 p95 ≈1.7 ms。

## 5. 设计

**`src/player/place-ray.js`**
- 新增并导出 `scanPlaceCells(world, origin, dir, visit, opts)`：
  - `visit(x, y, z, neighbor)`：每个候选按 DDA 顺序（近→远）调一次；返回 `true` = 已放置，立即中止遍历。
  - `opts.maxDist`（默认 `PLACE_RAY_MAX_DIST` = 15）、`opts.stopAt`（`[x,y,z]` | null：走到该格即截止，不含该格）。
  - 返回 `{ hit, placeCell?, neighbor? }`（`hit` = 某次 `visit` 返回了 true）。
  - **起点格**仍参与遮挡判据（起点是实心格 → 中止），但**不作候选**。用「是否第一次进入回调」识别，不用 `t === 0`（相机恰在格边界时下一格也可能 `t === 0`）。
- `findPlaceCell` 保留为薄包装（`visit = () => true`，取第一个候选）。既有 `place-ray:` 单测原样保留，当判据②③④的回归门。判据**只写在 `scanPlaceCells` 一处**。

**`src/player/player.js`**
- 新增 `_placeNearest(id, hit)`：`scanPlaceCells(world, 相机位置, 视线, (x,y,z) => this._placeSingle(x,y,z,id), { stopAt: hit?.blockPos ?? null })`；成功返回 true；否则有 `hit` 时再试 A（`hit.prevPos`），无 `hit` 返回 false。回调放成功后立刻中止遍历，不存在「写后读」。
- `placeBlock()` 末尾的单格放置与 `_placeByRayFallback()` 都改调 `_placeNearest`（前者传 `this.target`，后者传 null）。特殊物品两个分支、空槽 / 未知 id 守卫原样不动。
- `_placeSingle()` 不改：仍是唯一写入口 + 唯一身体守卫。

## 6. 测试（Tier 1，先红后绿）

- **单测 `test-place-ray.js`**：头格出局（背靠墙 / 天花板通道：第一个候选是头格之后的格）；候选近→远顺序；`visit` 返回 false 继续、true 立刻停（计调用次数）；`stopAt` 严格不含命中格（命中格是花、其后有候选 → 不被访问）；射程与遮挡；既有 `place-ray:` 用例保持全绿。
- **单测 `test-player-place.js`**（走真实 `placeBlock()` 全路径）：命中 + 更近 B → 放 B 不放 A；命中无 B → 放 A（与改前一致）；背靠墙远处命中 → 放 A（不被头格吞）；最近 B 被身体守卫拒 → 跳过；A 路径非实心进头格仍放行、实心被拒；打空路径回归。
- **E2E `tests/place-fallback.spec.mjs`**：用 `setTestAim → update → placeBlock`（不手塞 target）新增「命中时就近优先」与「背靠墙瞄远处不被吞」；既有第 2 条用例的标题与注释（「兜底不越过主射线命中」）已过时，改写，断言保留。
- **负向验证**：去掉头格出局 → 背靠墙用例必须 FAIL；忽略 `stopAt` → 花命中用例必须 FAIL；放回「命中即放 A」→ 就近优先用例必须 FAIL。
- **回归范围**：`npm run check`、`npm run lint`、浏览器单测（harness）、`place-fallback`，外加其余 7 个调用 `placeBlock()` 的 spec（m3-1-inventory、m3-2-orientation、minecarts、tnt、turrets、view-bob、zombie-nests）——它们走被改的路径，只在这个范围内跑，不铺全量。

## 8. 已知行为变化

- 视线擦过某方块「看不见的一面」时，落点比准心所指更近 —— **只在命中 ≥ 15 格或打空时**（见 §10）。
- 追加「近处命中直接放 A」**之前**的范围（终审评审员用真实 `Player` 实测，执行者已亲自复现；**已被 §10 的追加缩小，保留作为追加的原因**）：2 格高的空间平视略往下看地面，落点改放到「面前一格、头部高度、贴着天花板」（1×2 隧道俯角 10°~50°；宽 2 高房间 14 档里 10 档，3 高房间 0 档）；平地上紧挨一面墙走，偏航从朝墙 0.6° 到离墙约 45° 都改放到贴墙面前一格；**同一视线连点，第 2、3 次没有反应**（主射线命中刚放的那块，A 变成头格，被身体守卫拒绝）。
- **追加之后**：上述改放只剩看得很平（命中 ≥ 15 格）或打空时才出现，连点也不再无反应，实测见 §10。
- v1.72 裁定①「兜底只在完全未命中时生效」被本次取代（命中 ≥ 15 格时现在也先看候选）；其顾虑「回落会把方块放到没对准的地方」，用户已明确接受。

## 10. 追加变更（2026-10-30，用户）

用户看到 §8 的范围实测后做了两条裁定：

1. **「头格 / 压到身体的格」这条先不变** —— 保持本仓现状（候选里显式排除头格；身体守卫只拒实心），**不**对齐 mc-lite（它无显式排除、身体碰撞检查对所有方块生效，花草也不行）。用户：「我现在的实现更合理」。
2. **命中在 15 格内：直接放命中面前，不看沿途候选**，对齐 mc-lite `interact()` 的 `hits[0].distance < 15`。命中 ≥ 15 格与打空保持 §1~§7 的设计（沿视线从近到远第一个可放的候选，A 排最后）。

**实现**：`place-ray.js` 加 `PLACE_NEAR_HIT_DIST = 15`（= `PLACE_RAY_MAX_DIST`，语义不同：一个管「走哪条路」，一个管「候选搜多远」）；`player.js` 的 `_placeNearest(id, hit)` 开头：`hit && typeof hit.dist === 'number' && hit.dist < PLACE_NEAR_HIT_DIST` → 直接 `_placeSingle(...hit.prevPos, id)`，被拒即作罢（严格 `<`：命中恰为 15.0 走扫描）。`stopAt` 保留作边界保险：近处分流后，命中 ≥ 15 格时扫描范围（15 格）几乎总到不了命中格，只有命中恰为 15.0 格时 `stopAt` 才起作用，由专门用例钉住。

**追加后的范围**（真实 `Player` 实测，Node 里直接跑 `Player` + `setTestAim → placeBlock`）：
- 1×2 隧道，站格中心沿 +X 看地板：打空（俯角 0°、1°）或命中 ≥ 15 格（俯角 3°~6°，命中距离 31 / 18.6 / 15.5）才改放到面前一格（头部高度、贴天花板）；俯角 6.5°（命中 14.3 格）起直接放命中面前。
- 平地 + 身侧一面墙：同理，俯角 3°~6° 改放，7° 起直接放命中面前。
- 连点三次（看前方 5 格地板）：依次放在 (8,1,8) → (7,1,8) → (6,1,8)，沿视线向玩家一侧延伸，不再无反应。

**与 mc-lite 的对照（追加后）**：

| | mc-lite | 本仓现在 | 性质 |
|---|---|---|---|
| 命中 < 15 格 | 直接放命中面前，不看沿途候选 | 同左 | 对齐（本次追加） |
| 命中 ≥ 15 格、沿途有候选 | 放最近的候选（`doSkyPlace`） | 同左 | 一致 |
| 命中 ≥ 15 格、沿途无候选 | 什么都不放 | 放命中面前（≤ 40 格） | v1.72 用户裁定②，有意不同 |
| 打空 | `doSkyPlace` | 同左 | 一致 |
| 头格 / 压到身体的格 | 无显式排除；身体碰撞检查对所有方块生效 | 候选里显式排除头格；身体守卫只拒实心 | 用户明确保持本仓现状 |
| 巢穴 / 炮塔 / 矿车 | 候选格也交给 handler，能空中放 | 不参与，只认命中格 | v1.72，有意不同 |
| 采样 | 每 0.1 格采样，斜射可能漏格 | 体素 DDA 逐格 | 红线 6 |
| 命中时放置格怎么定 | 命中点相对方块中心偏移最大的轴 | 射线实际穿过的面 | 引擎差异，非整块方块可能不同 |

**测试变化**：玩家层单测把依赖「近处命中也走扫描」的用例改到 ≥ 15 格场景（给夹具世界加第二个 column，或用竖直视线），新增「近处命中」「恰为 15 格走扫描」「候选止于命中格（恰在 15 格边界）」；E2E 把走廊拉长到 x∈[px−2, px+19]，新增近处命中用例。负向验证：去掉近处分支 → 1 单测 + 1 E2E 红；`<` 写成 `<=` → 1 单测红；去掉 `stopAt` → 1 单测红。
