## 1. 意图与为什么

**用户要求（2026-11-17 原话）**：「生成在沙漠地带，平均三个沙漠出现一座这种高山，riser=3，
配色复用现有方块，以沙块和岩石方块为主。尽量不要跟其他建筑重叠，比如金字塔、沙漠村庄等等。
不要和空岛发生碰撞。」

上游 Tectonic 的 **Badlands Plateaus** 是 club 族在「最热档」的那一支：平顶台地 + 陡崖 + 层脊。
本轮把它的**观感语义**搬到 mc-heavy 的沙漠里，成为稀有的地标级地貌。

### 为什么这次能成，而上一次（2026-11-16）失败

上次失败的根因有两条，本设计**逐条从结构上消除**：

| 上次根因 | 本设计的处置 |
|---|---|
| **A：biome 乘性压平 × 高地形** ⇒ 跨 biome 边界造 25~35 格墙（占断崖 76.4%） | 本设计**不改 `generateHeight`**，山是 `apply.js` 的体素覆写；且落点门控要求**顶面 + 阶梯带整片 DESERT**（purity ≥ 0.85）⇒ 不存在「山跨 biome 边界」这件事 |
| **B：恶地脊固有斜率 10.5 值/coord × K=100** ⇒ 1.78 格/格 | 本设计**不搬上游样条的连续高度场**。阶梯由 `riser`/`tread` 两个整数常量定义 ⇒ 陡度 = `riser/tread`，**可证明**，与噪声无关 |

**关键发现（实测，决定了本设计的成本量级）**：本仓既有的山（冰封山峰 / 金字塔）**从来不改
`generateHeight`** —— 实测 seed 12345 冰封山窗口 121×121 里 **14.8% 的格实际地表 ≠ `generateHeight`，
最大差 24 格**，而山范围内 9409 列的自然高度最低 = 1（恒 > `SEA_Y`）。

⇒ 走同一手法的新地貌 **不动 `generateHeight`、不动 TSL 水面遮罩、不动 40 个高度消费方、
不动任何既有冻结断言**。调研报告 §5.D 列为「本次迁移最大架构决策」的 GPU 遮罩问题（167 octave/片元）
**在本需求下不存在**。

## 2. 目标 / 非目标 / 反目标

### 目标
1. 沙漠里出现平顶陡崖台地（Badlands butte 观感），**平均三个沙漠 region 一座**。
2. `riser = 3`：崖壁是真陡崖（用户裁定，**明知爬不上去**）。
3. 配色**只用现有方块**，以 `sand` + 岩石族为主，**零新增美术资源、零烘焙**。
4. 不与既有建筑重叠：金字塔 / 沙漠村庄 / 沙漠神殿 / 大竞技场 / 废弃堡垒 / 城市 / 地标。
5. **不与空岛碰撞**。
6. 世界其余部分**逐位不变**（高度、biome、既有结构锚点、既有测试冻结数字）。

### 非目标（本轮明确不做）
- **可爬性**：`riser=3` ⇒ `MAX_STEP=1.0` 走不上顶面（实测可达 **0%**，见 §5.3）。用户已裁定接受。
- **上游连续层脊纹理**：不搬 `badlands_ridge` 的样条高度场（那是上次根因 B）。
- **terracotta 族新方块**：本仓 152 个方块里一个都没有，新增需要美术资源，用户裁定复用现有。
- 全局地形替换、地形风格开关、`generateHeight` 公式改动、TSL 遮罩改动。
- 山顶植被 / 结构 / 装置（山顶是裸岩 + 沙，见 §5.5）。

### 反目标（做成了也算失败）
- 改了 `generateHeight` / `TERRAIN_HEIGHT_PARAMS` / `BIOME_PARAMS` / `ocean*.js` 任一处。
- 既有结构（大竞技场 / 废弃堡垒 / 围场 / 浅水高台 / 巨型金字塔）**召不出来**（返回 null）。
  ⚠️ 「移位」可接受，「失败」不可接受 —— 两者必须分开断言（上次复盘 §2 的教训）。
- 山顶穿进空岛，或崖壁与既有建筑穿插。
- 为了产率去放宽 `purity` 到「山跨 biome」——那会让上次的根因 A 复活。
- 拿「缺陷实测值 + 余量」当验收阈值（上次把最大跳 55 当上界，而玩家 `MAX_STEP=1.0`）。

## 3. 上游语义与本设计的对应关系

### 3.1 上游是怎么生成的（读码结论）

`region/club.json` 的 `temperature_index = 5` 分支：

```
coordinate = |ridge(x·0.25, z·0.25)|              ← ridges_folded
  0    → −0.15      0.1 → 0.04（缓坡基准）
  0.2  → badShort   0.3 → badTall
         两支都以 |badlands(x·0.35, z·0.35)| 为坐标：
           badShort: 0.45→0.05  0.60→0.15(d1.5)  0.63→0.185(d0.2)
           badTall : 0.45→0.05  0.60→0.185(d1.5) 0.63→0.50 (d0.2)
```

- **平顶**来自 `0.63` 之后 derivative 仅 0.2（近水平）。
- **陡壁**来自 `0.60→0.63`：0.03 的 coord 里升 0.315 ⇒ **斜率 10.5 值/coord**。
- 门控（`TectonicCommand.java:237` 的 `locate badlands_plateaus` 是权威定义）：
  `ti=5` × `erosion<0` × `region_selector<0` × `ridges_folded≥0.2` × `raw_continents≥0.35`。

**实测的两条硬事实**（决定了「不能直搬」）：
1. 断点 `0.63` 落在 badlands 噪声的 **p99.65**；三条门控同时成立 **0.135%**，其中真高山 **0.1%**
   ⇒ 照搬原版数值等于几乎不生成（同调研报告 §2.5 丛林柱的坑）。
2. badlands 噪声每格变化实测 **0.001692**（max 0.007461）⇒ K=100 时 **1.78 格/格**。
   且「每座山自己挑相位」也救不回来：任一 ±1200 窗口内 `rf≥0.28` 处的 badlands 可达上限
   只有 **0.145~0.752**，11 seed 里 **5 个根本达不到 0.66** ⇒ 那些 seed 的山没有顶。

### 3.2 本设计取什么、不取什么

| 上游要素 | 本设计 | 理由 |
|---|---|---|
| **平顶 + 陡崖 + 缓坡**的三段语义 | **取**，用 `Rtop / levels×riser / tread / S` 四个整数常量表达 | 陡度可证明，与噪声解耦 |
| **轮廓不是圆**（层脊的不规则边） | **取手法**，改用仓内既有 `blobNoise`（`tarn-terrain.js:203`） | 不引入新 Perlin；`blobNoise` 的存在理由正是「`noise()` 可分离 ⇒ 边界横平竖直」 |
| `badlands_ridge` 连续高度场 | **不取** | 上次根因 B |
| `ti/erosion/selector` 三层分区门控 | **不取**，换成 `getBiome==='DESERT'` + region 级搜索 | 本仓 biome 是另一套权威；上游门控极稀有 |
| terracotta 条带配色 | **不取材质，取「分层」语义** | 用岩石族三色交替制造层理（§5.4） |

## 4. 现状与约束（实测）

### 4.1 接入点：`apply.js` 阶段 1 之后、阶段 2.4 之前

`fillColumn`（自然地形）→ `carveCaves` → `applyStructuresToColumn`：
阶段 1 地形整形（城市/地标 elif 链）→ **本设计插入点** → 2.45 浅水高台 → 2.4 高台地带 → …

## 5. 设计决策（每条都有实测支撑）

### 5.1 形状：四常量定义的阶梯台地

```
H     = levels × riser                       顶面相对自然地表的高度
rt(θ) = Rtop + wobble·blobNoise(...)·0.5 + sin(3θ + seed·0.01)·wobble·0.3   顶面半径（非圆）
lift(d) =
  d ≤ rt              → H                    顶面（平）
  rt < d < rt+levels·tread → H − (⌊(d−rt)/tread⌋+1)·riser    阶梯带
  d ≥ rt+levels·tread → 0                    带外
surfaceY = 自然高 + round(lift × w)
  w = 1（d ≤ outer）；outer..outer+S 线性降到 0（缓坡）
```

**定稿常量**（`Rtop=26, levels=12, riser=3, tread=2, S=16, wobble=6`）：

| 量 | 值 | 说明 |
|---|---|---|
| `H` | **36** | 顶面比周围沙漠高 36 格（冰封山峰是 +23） |
| `RIM`（保守） | `Rtop + wobble×3 + levels×tread` = **68** | 阶梯带外缘上界 |
| `REACH`（保守） | `RIM + S` = **84** | 含缓坡的占地半径上界 |
| 实测最大外缘 | **78.7** | < REACH 84 < region 半宽 200 ⇒ **不越界** |
| 陡度 | `riser/tread` = **1.5 格/格** | 可证明；与噪声无关 |
| `blobNoise` scale | **0.09** | 直段最短档（§5.7） |

⚠️ **`REACH` 必须 ≥ 实测最大外缘**：上次台地的教训是「圆越界 ⇒ 半边永久消失」
（`TARN_ZONE_RADIUS` 注释）。这里 84 > 78.7 且远小于 200，两道都安全。

### 5.2 落点：region 内偏移搜索 + 撒布压制（**决定性对照**）

**为什么不能放 region 几何中心**：地标（金字塔/冰封山/平地/海岛）全部锚在
`getRegionSeededCenter` 附近。实测 seed 12345 前 8 个沙漠 region 的地标圆心距中心
只有 **58~240 格**、半径 15~48 ⇒ 中心放山 **11/11 seed 全 0 座**，拒绝原因 100% 是 landmark。

**为什么撒布必须压制而不是避让**（单变量对照，11 seed 合计拒绝计数）：

| 口径 | 座数 min/中位/max | 零座 seed | 沙漠/座中位 |
|---|---|---|---|
| 撒布**避让** | 0 / 1 / 3 | **3** | 33.5 |
| 撒布**压制** | 6 / 8 / 13 | **0** | 8.4 |
| 撒布压制 + 全尝试 | **16 / 27 / 39** | **0** | **2.5** |

拒绝原因分解（避让口径）：`landmark 8740 / scatter 3265 / sky 1837`。
撒布候选实测 **23.7 个/沙漠 region**（`house 690 / ship 467 / desertVillage 136 / desertPyramid 80 / tank 78 / uglyHouse 64`）
⇒ 拿它做避让等于自己堵死自己。这与 `burning-arena.js` 文件头记的坑**同源**。

**定稿落点算法**（照 `giant-pyramid` 手法）：

1. 扫描窗 = region 内缩 `min(REACH, 200−16)` = 84 ⇒ 窗 232×232，步长 `SCAN=12`。
2. 只收 `getBiome === 'DESERT'` 的点作候选。
3. 确定性乱序：`seededRandom(wx, wz, seed + SALT_ORDER)` 升序，tie 用坐标字典序。
4. 逐候选检查（**便宜的先**）：
   - **城市**：占地 AABB 与 `getCityBoundsForSeed` 相交 → 拒。
   - **地标**：与 `regionLandmarkCenters` 任一圆（半径 + REACH）相交 → 拒。
   - **空岛**：`bottomY ≤ topY` 且水平 AABB（`radius + REACH`）相交 → 拒。
     `topY` = **顶半径上界圆盘内 `max(generateHeight) + H`**（§5.6）。
   - **沙漠纯度**：`RIM` 圆盘 12 方位 × 5 环 = 60 采样，DESERT 占比 ≥ **0.85** → 否则拒。
   - **干燥**：`RIM` 圆盘步长 8 采样，任一格 `generateHeight ≤ SEA_Y` → 拒。
5. 命中即停，`maxTry = 30`。
6. **不查撒布**（改为压制，见 §5.5）。
7. 邻域范围 **3×3**（占地 84 会伸进邻居 region，必须查邻居的地标/空岛/城市）。

**产率（定稿口径，11 seed 实测）**：沙漠/座 **min 1.48 / 中位 2.06 / max 3.09**，
山总数 23~50 座（289 region 窗口），**零座 seed = 0**。
⇒ 满足用户「平均三个沙漠一座」（中位 2.06，最稀的 seed 3.09）。

⚠️ **不再叠概率抽签**：实测通过率只有 0.225~0.527，再乘 1/3 会把产率打到 8.4 座（沙漠/座 8.4）。
「三个沙漠一座」由**门控自然稀疏度**达成，不是靠抽签 —— 这与 `TARN_ZONE_CHANCE` 的口径不同，
必须在常量注释里写清，否则将来有人「补上抽签」会让山几乎消失。

### 5.3 陡度与可爬性（**验收锚的正确取法**）

**锚 = 已交付并被用户接受的冰封山峰**，不是自然沙漠。
理由：自然沙漠是「平地」的锚（>1格 0.046%），拿它判山会把任何山都判死。

| 口径（同窗口 有山/无山 单变量对照） | 最大跳 | Δ>1格% | Δ≥5格% | MAX_STEP=1 可达顶面 |
|---|---|---|---|---|
| **冰封山峰（锚）** | 4 | +1.712 | **+0** | **100%** |
| 自然沙漠（同窗口无山） | 1 | 0 | 0 | — |
| **本设计定稿（11 seed）** | **6~11** | **+1.843~2.043** | **+0（全部 11 seed）** | **0%** |

两条读法：
- **Δ≥5格 = 0**：山**没有新增任何 ≥5 格的断崖**。最大跳 6~11 **与同窗口天然沙漠的最大跳逐位相同**
  ⇒ 那些大跳是天然地形自带的，不是山造的。这正是上次复盘要求的「与块外自然地形基线同量级」。
- **MAX_STEP=1 可达 0%**：`riser=3` 的必然结果，**用户已明确裁定接受**。
  `MAX_STEP=3` 洪泛可达 **100%**（11/11 seed）⇒ 阶梯本身是连续的，没有断路。
  ⚠️ 这条要写成**正向断言**（「riser=3 时爬不上去」是预期行为），而不是当缺陷去修。

### 5.4 配色：沙 + 岩石三色层理（零新增资源）

复用现有方块（贴图均值实测自 `assets/atlas.png`）：

| 用途 | 方块 | rgb 均值 | 理由 |
|---|---|---|---|
| 顶面 | `sand` | 219,207,163 | 用户要求「以沙块为主」；与周围沙漠同色，顶面不突兀 |
| 缓坡带 | `sand` | 同上 | 接自然沙漠，无缝 |
| 崖壁层理 A | `stone` | 126,126,126 | 中性灰岩 |
| 崖壁层理 B | `cobblestone` | 125,125,125 | 粗糙质感（与 A 同亮度但纹理不同） |
| 崖壁层理 C | `stone_diorite` | 189,188,189 | **浅亮带** ⇒ 三色交替才有「层」的观感 |

**分层规则**：崖壁按**级序** `lvl = ⌊(d−rt)/tread⌋` 取 `[stone, cobblestone, stone_diorite][lvl % 3]`。
⇒ 12 级 = 4 个完整三色循环，从崖底到崖顶呈水平条带（上游 terracotta 条带的语义等价物）。

**单座方块计数（实测 seed 12345）**：占地 14960 格，
地表层 `sand_slope 7824 / cobblestone 2232 / stone 2051 / stone_diorite 1614 / sand_top 1239`；
竖直填充总量 **136983 格 ≈ 0.137M**。

⚠️ **通道预算**：全部是 `opaque` 通道方块（无 cutout）⇒ 不吃紧张的 cutout 容量
（550×3200×1.25 = 2.2M 顶点）。opaque 初始 4.275M 顶点。
**但必须 Tier 4 实测**：崖壁暴露面比平地多，`npm run bench -- --check` + `giant-tree-budget.spec.mjs` 都要跑。

### 5.5 压制：撒布 / 植被 / 巨树 / 杜鹃

照 `burning-arena` / `ruined-citadel` 的**同一手法**：

1. **`pointContext` 加一个 `kind:'none'` 分支**（`apply.js:132`）——
   一个分支同时覆盖五个下游消费者（高台让路 / 巨树 `allowedAt` / 城市树 / 普通树 / 单格植物）。
   判据转调新模块导出的 `inMesaFootprint(wx, wz, mesas)`，**不在 apply 里重写几何**（红线 1）。
2. **阶段 2.7 撒布剔除**：共用同一份 `inMesaFootprint`。
3. 山顶**不长植被**（`kind:'none'` 的自然结果）——裸岩 + 沙的 butte 观感。

⚠️ **压制粒度是「含缓坡的整个占地」**（`REACH` 圆内按真实 `rt`），不是只顶面：
缓坡的地表也被改写过，撒布/树长在上面会穿模（同 `inShallowTarnFootprint` 的理由）。

### 5.6 空岛与云：两条不同的处置

**空岛 —— 避让（运行期判据）**：
`H=36` 时顶面绝对 y 实测 **39~45**，而空岛底最低 **40** ⇒ **会重叠**，必须查。
实测不同 H 的碰撞率（rim 内逐格最高 y ≥ 40 的样本比例）：

| H | 最高 y | ≥40 样本 | 结论 |
|---|---|---|---|
| 24 | 36 | **0/110** | 结构性零碰撞 |
| 30 | 42 | 3/110 | 需避让 |
| **36** | **48** | **56/110** | **需避让** |
| 42 | 54 | 110/110 | 需避让 |

⇒ 定稿 H=36 **必须保留运行期空岛避让**。实测 365 座**撞空岛 0 座**（判据生效）。

⚠️ **`topY` 的算法是载荷性的**：
- 用「圆心自然高 + H + 8」这种拍出来的上界 ⇒ **过保守**，产率崩到 2/4/8（实测）。
- 用「顶半径上界（`Rtop+wobble×3`=44）圆盘内 `max(generateHeight) + H`」⇒ **精确且便宜**
  （只扫自然高，不算 `blobNoise`）。实测顶面圆盘内自然高极差 5~18 格，故这个上界必要。
- 成本对比：逐格扫 `surfaceY` 191 ms/seed → `natmax` 上界 **59 ms/seed**（3.2× 降本，产率反而更好）。

**云 —— 不避让，但必须明确处置**：
实测 **365/365 座顶 y ≥ 35**（云簇层），**0/365 座 ≥ 55**（单云层）。
`cloud` 是 `solid:true` ⇒ 山顶会与云簇层共处同一 y。

**处置：山优先，云让路** —— 在山的占地内跳过 `CLOUD_CLUSTER_Y` 与 `SINGLE_CLOUD_Y` 的云写入。
理由：云是装饰、山是地标；让云穿进崖壁是穿模。
⚠️ 这条要改 `writeClouds` 的调用侧（传入 mesa 布局做门控），**不改云的生成规则本身**。

### 5.7 轮廓：`blobNoise` scale = 0.09（实测选档）

| scale | 半径极差 | 最长等半径直段 |
|---|---|---|
| 0.035 | 7.4 | 13 |
| 0.06 | 19.0 | 17 |
| **0.09** | **12.8** | **10** |
| 0.13 | 20.2 | 15 |
| 0.2 | 21.4 | 9 |

取 **0.09**：直段最短（10 格）且极差 12.8 < `wobble×3 = 18`（保证 `RIM` 上界成立）。
0.2 的直段更短（9）但极差 21.4 **超出上界** ⇒ 占地会超出 `REACH`，不可取。

⚠️ 定稿口径下跨 11 seed 复核：最长直段中位 **16** / max **31** 格。
比单点样本长，但**远小于** `noise()` 可分离时的 36 格直边（tarn 的实测教训）。
若用户仍觉得直，**下一轮**再叠一层高频齿（照 `tarnIceBoundaryAt` 手法），本轮不做。

## 8. 方法论与未核边界

### 怎么核的（可复现）

1. 上游读码：按 overlay 优先级合并（`overlay.mod` → `overlay.datapack` → base `data`），
   从 `region/club` 做引用闭包，程序化扫 y 依赖（结论：**纯 2D**，11 DF / 9 octave）。
2. 数值探针复用仓库已验证的原语（`tools/tectonic-terrain-probe.mjs` 前 256 行：
   MC 口径 Improved Perlin + 端点线性外插 cubic spline + 惰性分支）。
3. **逐格**采样（步长 1）—— 上次教训：步长 3 把最大跳 30 读成 7。
4. **单变量对照**：同窗口「有山 / 无山」两侧只差山 ⇒ 增量归因明确。
5. **seed 清单 = 既有测试全集 ∪ 用户实际 seed**：程序化扫出 36 个既有 seed，
   取其中 10 个代表性的 + 用户报过的 **13344380**，共 11 个。
6. 每个判据都做过**负向验证**或**敏感性扫描**（如 `topMode` 三档、`scale` 五档、
   `riser` 1/2/3 三档、撒布避让 vs 压制）。

### 没核的（⚠️ 引用本文数字时必须带上这些边界）

- **探针不是生产实现**：Perlin permutation 用 LCG 自造（不是 MC seed 派生），
  octave 归一化用近似 `valueFactor`。⇒ 「上游稀有度 0.1%」是**数量级依据**，不是冻结基线。
  但**本设计不用上游 Perlin**（改用仓内 `blobNoise`）⇒ 定稿档的所有数字都基于真实仓内函数，可冻结。
- **未启动 Minecraft 比对原版观感**：上游语义是读码 + 探针推导，没有截图对照。
- **GPU 侧未实测**：方块计数 0.137M 是 CPU 侧统计，真实顶点量与帧时要 Tier 4。
- **浏览器/Node 一致性未验**：上次放弃时有一条「seed 987654 选址浏览器 null、Node OK」未查明。
  本轮**必须在浏览器内单测里复核同一批 seed 的落点**，不能只跑 Node。
- **`blobNoise` 直段 31 格的观感**：数值上远好于 `noise()` 的 36 格直边，但**没有用户目视确认**。
- **产率的 seed 覆盖面**：11 个 seed。既有测试有 36 个 ⇒ 落地时要扫全集复核「零座 seed = 0」。

### 上游许可

Tectonic 是 **MIT**（`build.gradle.kts:32`）。本设计**只取语义、不复制代码或数据文件**，
仍在新模块头注明来源与本设计文档路径。
