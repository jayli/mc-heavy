## 1. 意图与为什么

**用户要求（2026-11-17 原话）**：「生成在沙漠地带，平均三个沙漠出现一座这种高山，riser=3，
配色复用现有方块，以沙块和岩石方块为主。尽量不要跟其他建筑重叠，比如金字塔、沙漠村庄等等。
不要和空岛发生碰撞。」

上游 Tectonic 的 **Badlands Plateaus** 是 club 族在「最热档」的那一支：平顶台地 + 陡崖 + 层脊。
本轮把它的**观感语义**搬到 mc-heavy 的沙漠里，成为稀有的地标级地貌。

### 为什么这次能成，而上一次（2026-11-16）失败

上次失败的根因有两条，本设计**逐条从结构上消除**：

| 上次根因 | 本设计的处置 |
|---|---|
| **A：biome 乘性压平 × 高地形** ⇒ 跨 biome 边界造 25~35 格墙（占断崖 76.4%） | 本设计**不改 `generateHeight`**，山是 `apply.js` 的体素覆写；且落点门控要求**顶面 + 阶梯带整片 DESERT**（purity ≥ 0.85）⇒ 不存在「山跨 biome 边界」这件事 |
| **B：恶地脊固有斜率 10.5 值/coord × K=100** ⇒ 1.78 格/格 | 本设计**不搬上游样条的连续高度场**。阶梯由 `riser`/`tread` 两个整数常量定义，且**轮廓半径只依赖方位角 θ**（§5.1 修订）⇒ 轴向陡度上界 = `riser`，**逐格实测违例 0**（396 座 × 全窗）|

**关键发现（实测，决定了本设计的成本量级）**：本仓既有的山（冰封山峰 / 金字塔）**从来不改
`generateHeight`** —— 实测 seed 12345 冰封山窗口 121×121 里 **14.8% 的格实际地表 ≠ `generateHeight`，
最大差 24 格**，而山范围内 9409 列的自然高度最低 = 1（恒 > `SEA_Y`）。

⇒ 走同一手法的新地貌 **不动 `generateHeight`、不动 TSL 水面遮罩、不动 40 个高度消费方、
不动任何既有冻结断言**。调研报告 §5.D 列为「本次迁移最大架构决策」的 GPU 遮罩问题（167 octave/片元）
**在本需求下不存在**。

## 2. 目标 / 非目标 / 反目标

### 目标
1. 沙漠里出现平顶陡崖台地（Badlands butte 观感），**平均三个沙漠 region 一座**。
2. `riser = 3`：崖壁是真陡崖（用户裁定，**明知爬不上去**）。
3. 配色**只用现有方块**，以 `sand` + 岩石族为主，**零新增美术资源、零烘焙**。
4. 不与既有建筑重叠：金字塔 / 沙漠村庄 / 沙漠神殿 / 大竞技场 / 废弃堡垒 / 城市 / 地标。
5. **不与空岛碰撞**。
6. 世界其余部分**逐位不变**（高度、biome、既有结构锚点、既有测试冻结数字）。

### 非目标（本轮明确不做）
- **可爬性**：`riser=3` ⇒ `MAX_STEP=1.0` 走不上顶面（实测可达 **0%**，见 §5.3）。用户已裁定接受。
- **上游连续层脊纹理**：不搬 `badlands_ridge` 的样条高度场（那是上次根因 B）。
- **terracotta 族新方块**：本仓 159 个方块里一个都没有，新增需要美术资源，用户裁定复用现有。
- 全局地形替换、地形风格开关、`generateHeight` 公式改动、TSL 遮罩改动。
- 山顶植被 / 结构 / 装置（山顶是裸岩 + 沙，见 §5.5）。

### 反目标（做成了也算失败）
- 改了 `generateHeight` / `TERRAIN_HEIGHT_PARAMS` / `BIOME_PARAMS` / `ocean*.js` 任一处。
- 既有结构（大竞技场 / 废弃堡垒 / 围场 / 浅水高台 / 巨型金字塔）**召不出来**（返回 null）。
  ⚠️ 「移位」可接受，「失败」不可接受 —— 两者必须分开断言（上次复盘 §2 的教训）。
- 山顶穿进空岛，或崖壁与既有建筑穿插。
- 为了产率去放宽 `purity` 到「山跨 biome」——那会让上次的根因 A 复活。
- 拿「缺陷实测值 + 余量」当验收阈值（上次把最大跳 55 当上界，而玩家 `MAX_STEP=1.0`）。

## 3. 上游语义与本设计的对应关系

### 3.1 上游是怎么生成的（读码结论）

`region/club.json` 的 `temperature_index = 5` 分支：

```
coordinate = |ridge(x·0.25, z·0.25)|              ← ridges_folded
  0    → −0.15      0.1 → 0.04（缓坡基准）
  0.2  → badShort   0.3 → badTall
         两支都以 |badlands(x·0.35, z·0.35)| 为坐标：
           badShort: 0.45→0.05  0.60→0.15(d1.5)  0.63→0.185(d0.2)
           badTall : 0.45→0.05  0.60→0.185(d1.5) 0.63→0.50 (d0.2)
```

- **平顶**来自 `0.63` 之后 derivative 仅 0.2（近水平）。
- **陡壁**来自 `0.60→0.63`：0.03 的 coord 里升 0.315 ⇒ **斜率 10.5 值/coord**。
- 门控（`TectonicCommand.java:237` 的 `locate badlands_plateaus` 是权威定义）：
  `ti=5` × `erosion<0` × `region_selector<0` × `ridges_folded≥0.2` × `raw_continents≥0.35`。

**实测的两条硬事实**（决定了「不能直搬」）：
1. 断点 `0.63` 落在 badlands 噪声的 **p99.65**；三条门控同时成立 **0.135%**，其中真高山 **0.1%**
   ⇒ 照搬原版数值等于几乎不生成（同调研报告 §2.5 丛林柱的坑）。
2. badlands 噪声每格变化实测 **0.001692**（max 0.007461）⇒ K=100 时 **1.78 格/格**。
   且「每座山自己挑相位」也救不回来：任一 ±1200 窗口内 `rf≥0.28` 处的 badlands 可达上限
   只有 **0.145~0.752**，11 seed 里 **5 个根本达不到 0.66** ⇒ 那些 seed 的山没有顶。

### 3.2 本设计取什么、不取什么

| 上游要素 | 本设计 | 理由 |
|---|---|---|
| **平顶 + 陡崖 + 缓坡**的三段语义 | **取**，用 `Rtop / levels×riser / tread / S` 四个整数常量表达 | 陡度可证明，与噪声解耦 |
| **轮廓不是圆**（层脊的不规则边） | **取手法**，改用仓内既有 `blobNoise`（`tarn-terrain.js:203`） | 不引入新 Perlin；`blobNoise` 的存在理由正是「`noise()` 可分离 ⇒ 边界横平竖直」 |
| `badlands_ridge` 连续高度场 | **不取** | 上次根因 B |
| `ti/erosion/selector` 三层分区门控 | **不取**，换成 `getBiome==='DESERT'` + region 级搜索 | 本仓 biome 是另一套权威；上游门控极稀有 |
| terracotta 条带配色 | **不取材质，取「分层」语义** | 用岩石族三色交替制造层理（§5.4） |

## 5. 设计决策（每条都有实测支撑）

### 5.1 形状：阶梯台地（**2026-11-27 修订**）

```
H          = levels × riser                   顶面相对自然地表的高度 = 36
STAIRSteps = levels − 1                       降幅次数 = 11（← 关键：不是 12）
STAIR_DROP = STAIRSteps × riser                阶梯带总降幅 = 33
TAIL       = H − STAIR_DROP                    末级台面高 = 3（= riser，派生）
STAIR_W    = STAIRSteps × tread                阶梯带宽 = 22

rt(θ) = Rtop + wobble·blobNoise(cosθ·Rtop, sinθ·Rtop, seed+SALT+3, 0.09)·0.5
              + sin(3θ + seed·0.01)·wobble·0.3
        ↑ **采样点只依赖 θ**（单位方向 × Rtop），不依赖 (lx,lz)

lift(d, θ) =
  d ≥ REACH                  → 0        保守常量圆早退
  d ≤ rt(θ)                  → H        顶面（平）
  rt < d < rt+STAIR_W        → H − (⌊(d−rt)/tread⌋+1)·riser     阶梯带
  rt+STAIR_W ≤ d < …+SLOPE   → TAIL·(1 − (d−outer)/SLOPE)      缓坡
  d ≥ rt+STAIR_W+SLOPE       → 0
surfaceY = generateHeight + round(lift)
```

**三条载荷性约束（每条都是实测推翻原公式后加的，改回去就红）**：

1. **`rt` 只能依赖 θ，不能依赖 `(lx,lz)`**。原公式写 `blobNoise(lx, lz, …)`，
   于是同一条射线上 `rt` 也在变 ⇒ `⌊(d−rt)/tread⌋` 会**跳 2 级**。
   实测原公式：轴向 `maxΔlift = 6`（= 2×riser），**39 处违例**（368 座全扫）。
   改成 θ 采样后：`maxΔlift = 3.000`、**违例 0**（396 座 × ±70 窗逐格）。
2. **阶梯带只降 `levels−1` 次，末级留 `riser` 交给缓坡**。原公式 `H = levels×riser`
   使第 12 级 `lift = H − 12×riser = 0` ⇒ **缓坡权重段乘的恒是 0，是死代码**
   （实测：带/不带缓坡权重，11 seed 全部山**逐格 0 差异**）。山脚因此是 3 格直落。
   改成 `STAIR_W = (levels−1)×tread` 后，末级台面 = `TAIL = 3`，与缓坡起点同值 ⇒ 连续。
   ⚠️ **不能写成 `levels×tread` 再 clamp lvl**：实测那样会在 `d=39` 得 0、`d=41` 得 2.9，
   形成 **0→3 的逆跳**（先降到 0 再升回 3）。
3. **缓坡的早退门必须用真实 `outer`**（`rt+STAIR_W`），不能用常量 `REACH`。
   两者混用会算出**负 lift**（实测 `d=96.75` 处 lift = −3.121），表现为山外一圈凹坑。

**定稿常量**（`Rtop=26, levels=12, riser=3, tread=2, SLOPE=16, wobble=6`）：

| 量 | 值 | 说明 |
|---|---|---|
| `H` | **36** | 顶面比周围沙漠高 36 格（用户裁定的观感，不变）|
| `STAIR_DROP` / `TAIL` | **33 / 3** | 派生，不写字面量 |
| `STAIR_W` | `(levels−1)×tread` = **22** | 阶梯带宽 |
| `RTOP_MAX` | `Rtop + wobble×3` = **44** | `rt` 上界（理论上界 39.8，实测最大 **37.37**）|
| `RIM`（保守） | `RTOP_MAX + STAIR_W` = **66** | 阶梯带外缘上界 |
| `REACH`（保守） | `RIM + SLOPE` = **82** | 含缓坡的占地半径上界 |
| 实测最大外缘（逐格 `lift>0`） | **75.29** | < REACH 82 < region 半宽 200 ⇒ **不越界** |
| 轴向陡度上界 | **3.000**（= riser） | 实测违例 **0**；对角最大 **6**（两轴各跳一级，不得钉对角）|
| 缓坡段取整后最大轴向 Δ | **1** | 3 格 / 16 格 ⇒ 0.1875 每格 |
| `blobNoise` scale | **0.09** | §5.7 |

⚠️ **`REACH` 必须 ≥ 实测最大外缘**：上次台地的教训是「圆越界 ⇒ 半边永久消失」
（`TARN_ZONE_RADIUS` 注释）。这里 82 > 75.29 且远小于 200，两道都安全。
⚠️ **`REACH` 不要为了「贴近真实占地」而调小**：它是落点排除半径，调小会直接把产率拉高
（实测 `REACH` 84→62 时单 seed 座数 34→72），与「平均三个沙漠一座」的用户裁定相反。

### 5.2 落点：region 内偏移搜索 + 撒布压制（**决定性对照**）

**为什么不能放 region 几何中心**：地标（金字塔/冰封山/平地/海岛）全部锚在
`getRegionSeededCenter` 附近。实测 seed 12345 前 8 个沙漠 region 的地标圆心距中心
只有 **58~240 格**、半径 15~48 ⇒ 中心放山 **11/11 seed 全 0 座**，拒绝原因 100% 是 landmark。

**为什么撒布必须压制而不是避让**（拒绝原因分解，11 seed 合计）：

拒绝原因分解（避让口径）：`landmark 8740 / scatter 3265 / sky 1837`。
撒布候选实测 **23.7 个/沙漠 region**（`house 690 / ship 467 / desertVillage 136 / desertPyramid 80 / tank 78 / uglyHouse 64`）
⇒ 拿它做避让等于自己堵死自己。这与 `burning-arena.js` 文件头记的坑**同源**。
（原文那张「避让 0/1/3 座 vs 压制 6/8/13 座」对照表的绝对座数已不可复现 ——
它没写明分母与 `maxTry`；本轮改用 §5.2 末尾的定稿产率表，口径逐项写清。）

**定稿落点算法**（照 `giant-pyramid` 手法，**2026-11-27 补全避让项**）：

1. 扫描窗 = region 内缩 `min(REACH, 200−16)` = 82 ⇒ 窗 236×236，步长 `SCAN=12`。
2. 只收 `getBiome === 'DESERT'` 的点作候选。
3. 确定性乱序：`seededRandom(wx, wz, seed + SALT + 1)` 升序，tie 用坐标字典序。
4. 逐候选检查（**便宜的先**）：
   - **城市**：占地 AABB 与 `getCityBoundsForSeed` 相交（半径 `REACH`）→ 拒。
   - **地标**：与 `regionLandmarkCenters` 任一圆（半径 + `REACH`）相交 → 拒。
   - **地基级结构（新增，见下表）**：圆↔矩形最近距 ≤ `RIM` → 拒。
   - **空岛**：`bottomY ≤ topY` 且水平 AABB（`radius + REACH`）相交 → 拒。
     `topY` = **顶半径上界圆盘内 `max(generateHeight) + H`**（§5.6）。
   - **沙漠纯度**：`RIM` 圆盘 12 方位 × 5 环 = 60 采样，DESERT 占比 ≥ **0.85** → 否则拒。
   - **干燥**：`RIM` 圆盘步长 8 采样，任一格 `generateHeight ≤ SEA_Y` → 拒。
5. 命中即停，**`maxTry = 60`**（原 30；补避让后拒绝变多，30 会把 per 打到 2.06~4.67）。
6. **不查撒布**（改为压制，见 §5.5）。
7. 邻域范围 **3×3**（占地 82 会伸进邻居 region）；全局唯一结构（大竞技场/堡垒/围场/
   浅水高台/丛林要塞）的锚点是 `seed` 级纯函数，**直接调一次即可，不需扫邻域**。

#### 地基级结构避让清单（**B6 修订：原设计漏了这整张表**）

原设计只查城市/地标/空岛，并写「高台地带/浅水高台靠 purity 自然排除」。
**实测推翻**（368 座，山体 `RIM` 圆↔对方占地）：

| 结构 | 原设计 | 实测相交座数 | 权威函数 / 半宽 |
|---|---|---|---|
| **巨型金字塔** | 未提 | **78** | `computeGiantPyramidAnchor(rx,rz,seed)` / `PYRAMID_HALF=24` |

### 5.3 陡度与可爬性（**验收锚的正确取法，2026-11-27 重标**）

**锚 = 已交付并被用户接受的冰封山峰**，不是自然沙漠。
理由：自然沙漠是「平地」的锚，拿它判山会把任何山都判死。

⚠️ **口径必须写进判据，否则数字不可复现**。本轮实测证明：同一批山、同一段代码，
只改窗口半径就能让 `Δ>1格%` 从 **4.34** 变成 **1.09**（4 倍），让「最大跳相同」从 74% 变成 98%。
**定稿双口径**（均为 **4 邻域轴向**、**步长 1 逐格**、同窗口有山/无山单变量对照）：

| 口径 | 窗口 | 用途 |
|---|---|---|
| **山尺度** | 圆心 ±100 格 | 判「山本体陡不陡」—— 山占地 82，窗 201² 刚好包住它 |
| **region 尺度** | 圆心 ±200 格 | 判「山对整片地图的影响」—— 401² ≈ 一个 region |

**实测表**（11 seed × 前 3 座 = 33 座；定稿列为 396 座全扫）：

| 量 | 冰封山（锚）±100 | 冰封山 ±200 | **本设计 ±100** | **本设计 ±200** |
|---|---|---|---|---|
| `Δ>1格%` | 0.46~1.42 | 0.116~0.357 | **3.92~4.63** | **0.98~1.16** |
| 新增 ≥5 格跳（绝对数） | **27**（33 座） | **27** | **24**（396 座） | **24** |
| 最大跳与自然相同 | 19/33 | 33/33 | **310/396** | **387/396** |
| 最大跳范围 | 3~11 | 5~11 | **4~14** | **7~14** |
| `MAX_STEP=1` 可达顶面 | — | — | **0%**（11/11） | |
| `MAX_STEP=3` 可达顶面 | — | — | **100%**（11/11） | |

（本设计列的 `Δ>1格%` / 新增≥5格 / 最大跳均为 **396 座全扫**；锚列为 **33 座**。
33 座子样本的 `Δ>1格%` 是 ±100 **3.92~4.69**（中位 4.34）/ ±200 **0.98~1.18**（中位 1.09），
与全扫略有出入 —— **断言一律用全扫值**，子样本只作数量级参考。）

**三条读法（每条都推翻了原文的一个断言）**：

1. **`新增≥5格 = 0` 是错的，连锚自己都做不到**。同口径实测冰封山 33 座就有 **27 处**。
   本设计 396 座 **24 处** ⇒ **每座密度 0.061，低于锚的 0.818（低 13 倍）**。
   ⇒ 判据改成**密度不高于锚**，而不是钉 0。
   机制已逐格定位：46/48 处是「自然跳 4 + 缓坡 lift 跳 0.06~0.19，取整后凑成 5」，
   2/48 处是「自然跳 4 + 阶梯跳 3 同向」。前者是 `round()` 的必然结果，不是几何缺陷。
2. **`最大跳逐位相同` 只在 region 尺度近似成立**（387/396 = 97.7%），山尺度只有 78%。
   超出那 9 处的机制：自然跳 1 + 阶梯跳 3 = 4（例 seed 12345 的 (−49,8)）。
   ⇒ 判据改成**「最大跳超出 ≤ riser」+ 「≥95% 的座逐位相同」**，不钉全量相等。
3. **`MAX_STEP=1` 可达 0%** 是 `riser=3` 的必然结果，**用户已明确裁定接受**。
   `MAX_STEP=3` 洪泛可达 **100%**（11/11）⇒ 阶梯本身连续，没有断路。
   ⚠️ 这条要写成**正向断言**（「riser=3 时爬不上去」是预期行为），而不是当缺陷去修。

### 5.5 压制：撒布 / 植被 / 巨树 / 杜鹃

1. **`pointContext` 加一个 `kind:'none'` 分支**（`apply.js` 的 `pointContext`，**现位 257 行**；

2. **阶段 2.7 撒布剔除**：共用同一份 `inMesaFootprint`。
3. 山顶**不长植被**（`kind:'none'` 的自然结果）——裸岩 + 沙的 butte 观感。

### 5.6 空岛与云：两条不同的处置

**空岛 —— 避让（运行期判据）**：
`H=36` 时顶面绝对 y 实测 **40~45**（396 座逐格），而空岛底最低 **40** ⇒ **会重叠**，必须查。
定稿口径下实测 **396 座撞空岛 0 座**（判据生效）。

⚠️ **`topY` 的算法是载荷性的**：
- 用「圆心自然高 + H + 8」这种拍出来的上界 ⇒ **过保守**，会白白拒掉合法落点。
- 用「顶半径上界（`RTOP_MAX`=44）圆盘内 `max(generateHeight) + H`」⇒ **精确且便宜**
  （只扫自然高，不算 `blobNoise`）。实测：**上界失效 0 次**，最大 gap **4**（33 座）。
- 步长 3 扫圆盘（与 `giant-pyramid` 的 `FOOTPRINT_STEP` 同手法）。

**云 —— 不避让，但必须明确处置**：
顶面绝对 y 实测 **40~45** ⇒ **全部 ≥ `CLOUD_CLUSTER_Y`(35)**，**全部 < `SINGLE_CLOUD_Y`(55)**。
`cloud` 是 `solid:true`（实测 `opaqueTable=1`）⇒ 山顶会与云簇层共处同一 y。

**处置：山优先，云让路** —— 在山的占地内跳过 `CLOUD_CLUSTER_Y` 与 `SINGLE_CLOUD_Y` 的云写入。
理由：云是装饰、山是地标；让云穿进崖壁是穿模。
⚠️ 实现上要改 **`applySkyStructures` 加一个可选 `skipAt(wx,wz)`**，并在其内部传给
`writeClouds` → `writeSingleCloudLayer` / `writeCloudClusters` **两个函数**（原文只说「改调用侧」，
但 `writeClouds` 是个转发层，不动它就传不下去）。**不改云的生成规则本身**。
⚠️ 高台地带的 4 朵巨型云（`apply.js` 阶段 2.4 的 `tarnLayout.clouds`，`TARN_CLOUD_MIN_Y=54`）
**不在本门控范围**：它们是 JSON 产物、且山已避让地带圆（§5.2）⇒ 几何上不可能重叠。

### 5.7 轮廓：`blobNoise` scale = 0.09（**2026-11-27 重标直段口径**）

⚠️ **原文的「最长等半径直段」口径无判别力**：`rt` 现在只依赖 θ（§5.1），
沿一条射线 θ 恒定 ⇒ `rt` 恒定 ⇒ 「沿轴最长等半径段」恒为窗宽（实测 100），钉它没意义。

**定稿口径 = 顶面边界的最长轴向直线段**：取「`lift === H` 且 4 邻域里有 `lift < H`」的格
（= 真实崖顶边缘），沿 x / z 方向数最长连续 run。这才是玩家看到的「边直不直」。

| 方案 | 顶面边界最长直线段 min/中位/max |
|---|---|
| 原公式（`rt` 依赖 (lx,lz)） | 10 / 16 / **26** |
| **定稿（`rt` 只依赖 θ，scale 0.09）** | — / — / **21**（33 座）|

定稿的顶半径极差实测 **10.94~20.97**（256 方位），`rt` 全局范围 **14.77~37.37**
（理论上界 `Rtop + wobble×4×0.5 + wobble×0.3 = 39.8` < `RTOP_MAX = 44`）⇒ `RIM` 上界成立。

⚠️ **scale 不要再调大**：实测 0.13 时对角 `maxΔlift` 从 3 涨到 5.5（轮廓变陡）；
0.06 时顶面边界直段反而变长。若用户实玩仍觉得直，**下一轮**再叠高频齿
（照 `tarnIceBoundaryAt` 手法），本轮不做。

## 8. 方法论与未核边界

### 怎么核的（可复现）

1. 上游读码：按 overlay 优先级合并（`overlay.mod` → `overlay.datapack` → base `data`），
   从 `region/club` 做引用闭包，程序化扫 y 依赖（结论：**纯 2D**，11 DF / 9 octave）。
2. 数值探针复用仓库已验证的原语（`tools/tectonic-terrain-probe.mjs` 前 256 行：
   MC 口径 Improved Perlin + 端点线性外插 cubic spline + 惰性分支）。
3. **逐格**采样（步长 1）—— 上次教训：步长 3 把最大跳 30 读成 7。
4. **单变量对照**：同窗口「有山 / 无山」两侧只差山 ⇒ 增量归因明确。
5. **seed 清单 = 既有测试全集 ∪ 用户实际 seed**：程序化扫出 36 个既有 seed，
   取其中 10 个代表性的 + 用户报过的 **13344380**，共 11 个。
6. 每个判据都做过**负向验证**或**敏感性扫描**（如 `topMode` 三档、`scale` 五档、
   `riser` 1/2/3 三档、撒布避让 vs 压制）。

### 没核的（⚠️ 引用本文数字时必须带上这些边界）

- **探针不是生产实现**：上游部分的 Perlin permutation 用 LCG 自造（不是 MC seed 派生），
  octave 归一化用近似 `valueFactor`。⇒ 「上游稀有度 0.1%」是**数量级依据**，不是冻结基线。
  但**本设计不用上游 Perlin**（改用仓内 `blobNoise`）⇒ 定稿档的所有数字都基于真实仓内函数，可冻结。
- **未启动 Minecraft 比对原版观感**：上游语义是读码 + 探针推导，没有截图对照。
- **GPU 侧未实测**：方块计数 0.159M 是 CPU 侧统计，真实顶点量与帧时要 Tier 4。
- **浏览器/Node 一致性未验**：上次放弃时有一条「seed 987654 选址浏览器 null、Node OK」未查明。
  本轮**必须在浏览器内单测里复核同一批 seed 的落点**，不能只跑 Node。
- **顶面边界直段 21 格的观感**：数值上优于原公式的 26 格，但**没有用户目视确认**。
- **产率的 seed 覆盖面**：11 个 seed。既有测试有 36 个 ⇒ 落地时要扫全集复核「零座 seed = 0」。
- **本轮新增：缓坡与阶梯接缝的 `round()` 行为**。实测缓坡段取整后最大轴向 Δ = 1，
  但「自然跳 4 + 缓坡 0.19」会凑成 5（§5.3）。这是 `round` 的必然结果，**不得靠改取整方式消除**
  （改成 `floor` 会把山顶整体降 1 格，违反 H=36）。
- **本轮新增：`structure-gen` genP95 的增量未测**。§5.8 的「依赖已被预热」是推论（依据是
  `computeRegionLayout` 本就调那些函数），**不是实测**。Task 3 Step 5 必须真跑。
