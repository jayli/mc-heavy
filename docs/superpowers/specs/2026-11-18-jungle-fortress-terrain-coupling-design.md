## 0. 一句话

把 v3.13 的「占地 161×155 整片削平（挖 17.7 万格）+ 16 格缓坡」换成
**「地形一格不改 + 结构整体抬到占地 75 分位高度（8/8 seed 恒为 y=9）+ 底面悬空处补同族石墩」**，

## 2. 调研结论（上游语义，全部读源码 + 看官方截图核实）

### 2.1 原版确实是「建筑嵌进起伏地形」，不是压平

`fortress_jungle.json`（`common/src/main/resources/data/repurposed_structures/worldgen/structure/`）：

```json
"terrain_adaptation": "none",
"start_height": { "type": "minecraft:uniform", "min_inclusive": {"absolute": 56}, "max_inclusive": {"absolute": 65} },
"project_start_to_heightmap": 缺省,
"burying_type": 缺省,
"liquid_settings": "ignore_waterlogging"
```

逐条含义（对照 `GenericJigsawStructure.java`）：

| 字段 | 语义 | 后果 |
|---|---|---|
| `terrain_adaptation: none` | **不做 beard / 不削地形** | 地形保持自然起伏，结构直接插进去 |
| `start_height` uniform[56,65] | 起始件 y 在 **海平面(63) −7 ~ +2** 随机 | 结构地板可能低于地表 ⇒ **下半截埋土里** |
| 无 `project_start_to_heightmap` | 不贴高度图 | 落位与地形高度**无关** |
| 无 `burying_type` | 不做 LOWEST_CORNER / AVERAGE_LAND 偏移 | 不刻意埋也不刻意架高 |
| 全族 17 片 `projection: rigid` | 件与件**刚性对齐** | 整个要塞是一个刚体，不逐件贴地 |

⇒ **原版就是「一个刚性大建筑，随机高度插进起伏地形，低处埋、高处露」**。
官方截图 `images/FortressJungle{,2,3,4,Combined}.png` 逐张核实：城墙下半截埋在草坡里、
上半截露出、树从墙脚长出来、地形明显起伏（不是平地）。

### 2.2 支撑柱是原版语义，不是我们发明的

`processor_list/fortresses/jungle_main.json` 的 `pillar_processor`：

```json
{ "processor_type": "repurposed_structures:pillar_processor",
  "direction": "down",
  "pillar_trigger_and_replacements": [{"trigger": {"id": "minecraft:red_stained_glass"},
                                       "replacement": {"id": "minecraft:stone_bricks"}}] }
```

`PillarProcessor.java`：红玻璃格 → 石砖，并**向下逐格补柱**直到
`getFirstLandYFromPos`（第一个非空气/非水/非可替换方块）⇒ **补到真实地形表面**。
`pillar_length` 缺省 1000（不限长）。

17 片 nbt 逐片普查：**红玻璃全部在件局部 y=0**（`/tmp/jf-nbt-census.json`），
共 7311 格（旋转后），是「墙脚支撑柱的根」。

⇒ **v3.13 把柱补到 `floorRow` 是因为当时地形被压平了**；地形不压平时，
柱就该补到**逐列自然地表**（正是本设计的墩）。

### 2.3 Tectonic 不改结构-地形关系

`tectonic` 全仓 72 个 Java 文件，与结构相关的 mixin 只有 `StructurePieceMixin.java`
（**只把海底遗迹下移 `monumentOffset`**）。地形全部写在 105 个 density_function JSON 里，
**没有任何「为结构压平地形」的逻辑**。⇒ 原版 + Tectonic 的组合仍是「建筑嵌进起伏地形」。

（Tectonic 的丛林地貌本身起伏更大：`region/heart/jungle_pillar` 是拔地百格的石柱，
但门控通过率 0.0035%，极稀有 —— 见 `docs/tectonic-terrain-migration-survey.md` §2.5。
本设计**不迁地形公式**，只用现有 FOREST 的 16 格起伏。）

### 2.4 本仓产物的竖直构成（实测，决定「地下部分」到底是什么）

产物 `jungle_fortress.json`：81238 格 / 159×33×155 / floorRow=13 / 归一化 ny∈[1,33]。
以地板层 dy = ny − 13 为基准：

| 段 | 实心格 | air 格 | 性质 |
|---|---|---|---|
| dy ≤ −7 | 2391 | 0 | **深基座**（纯基座 1994 + 房间外壳 397；center_room 等件的 y0 红玻璃根 + 柱） |
| dy −6..−1 | 29157 | 1594 | **地下层主体**（纯基座 28233 + 房间外壳 924 + 房间内腔 1594） |
| dy 0 | 4989 | 255 | 地板层（255 格 air 是门洞/通道口） |
| dy 1..20 | 29165 | 13942 | 地上建筑 |

地下 air 1594 格的连通簇分析（3D 洪泛）：**10 簇 / 486 列**，最大簇 1046 格
（x[35,78] dy[−6,−1] z[−58,8]）。其中 **1017 格上方有顶盖（封闭房间）/ 577 格直通天空（露天竖井/天井）**。

⇒ **「地下部分」= 30227 格纯基座/柱 + 1321 格房间外壳 + 1017 格封闭房间内腔**。
基座是实心的，露出来就是「建筑的高台基」；房间内腔露出来就是「露天坑/天井」。

### 2.5 为什么不能「逐件贴地」（实测否决）

用真实拼装器 `assembleJungleFortress()` 取 193 件的连接口（`target==='connection'`，
共 458 个口 / **195 条共址反向接缝**），逐件按占地中位自然高度贴地后：

| 接缝错位量 | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 9 | 12 | 13 |
|---|---|---|---|---|---|---|---|---|---|---|---|
| 条数 | 60 | 53 | 26 | 23 | 14 | 11 | 3 | 2 | 1 | 1 | 1 |

**135/195 条接缝被撕开，最大错位 13 格** ⇒ 走廊断头、门洞错位、墙体裂开。
要修就得重拼布局（放弃 v3.13 冻结的 193 件定版），超出本次范围。
⇒ **整体刚性抬升是唯一不破坏产物的路**。

## 4. 设计决策

### DR-1 落位高度：`baseY = 占地自然高度的 75 分位数`

```
baseY = percentile75({ generateHeight(wx, wz, seed) : |wx−ax| ≤ 80, |wz−az| ≤ 77 })
```

`percentile75` 作为**独立纯函数**导出（喂已排序数组，返回 `arr[floor(0.75*(n−1))]`），
供单测直接验证，不依赖 `generateHeight`。

**8/8 seed 实测恒为 9**（因 FOREST 高度公式的值域与分位形状稳定）。
仍按分位数**派生计算**，不硬编码 9（换地形公式时自动跟随；冻结表钉住当前值）。

- 相对现状 floorY（−1 或 0）**抬升 9~10 格**。
- 塔顶世界 y = baseY + 20 = **29**（< WORLD_MAX_Y 96 ✓）。
- 产物底面世界 y = baseY − 12 = **−3**（> WORLD_MIN_Y −32 ✓）。
- **零裁切**。

⚠️ **`anchor.floorY` 语义变更**：v3.13 它是「占地最低自然高度 = 整形后地表」；
本设计改为 **`baseY`（结构地板层的世界 y）**，并**保留 `minH` 字段**供判据使用。
所有消费方（光栅化 / 瞬移 / 植被 / 单测）一律读新语义，不得各写一份。

### DR-2 地形：**自然起伏保留 + 接壤阶梯过渡**（用户 2026-11-18 追加裁定）

- **删除 `fillJungleFortressGround` 的削平/铺地表/填实三步**（该函数整体移除或改为空操作）。
- **删除 16 格「遇湿即止」缓坡带的插值逻辑**（`jungleFortressSurfaceYAt` 不再做插值）。
- 占地**内部**（非过渡带）地形恒等于 `generateHeight` ⇒ 自然起伏保留（相邻高差恒 ≤1）。
- **红线 1 零风险**：`ocean-mask.js` / `ocean.js` 不动（遮罩读自然高度；过渡带只抬不削、
  湿列零抬升 ⇒ 遮罩判据不受影响，见 DR-10）。

⚠️ **用户追加裁定（2026-11-18）**：「最终丛林要塞的地界和旁边的地图接壤的地方，
都要有一个接壤区域的阶梯过渡，不要出现陡峭的悬崖突变。」
⇒ **不能只做「地形一格不改」**：结构抬升后墙脚/墩顶高于周边自然地面 10~21 格，
接壤处会形成垂直悬崖。必须加 **DR-10 的阶梯过渡裙边**。

⚠️ **`jungleFortressSurfaceYAt` 保留但改语义**：返回**过渡带处理后的地面高度**
（内部 = `generateHeight`；过渡带 = DR-10 包络值），供植被与瞬移共用同一权威。
**不得删除函数**（v3.13 的「唯一权威」约束仍成立）。

⚠️ **`inJungleFortressTerraform` 语义改为「植被管理区」，范围保持「占地 + 16」不变**：
用户 v3.13b 裁定「过渡带也要有树」⇒ 植被让路/管理范围仍含 16 格外延。
墩只在占地内 ⇒ 撒布剔除用 `inJungleFortressFootprint`（占地）即足够。
两个判据分开：`inJungleFortressFootprint`（占地，撒布剔除）
与 `inJungleFortressTerraform`（占地+16，植被管理），后者名字保留但注释更新。

### DR-3 石墩：逐列从结构底面补到自然地表（`pillar_processor` 语义）

```
对每个含产物实心的列 (px, pz)：
  baseNy = 该列最低实心 ny
  baseWy = baseY + (baseNy − floorRow)
  h      = generateHeight(ax+px, az+pz, seed)
  若 baseWy − 1 > h：
    从 ny = baseNy−1 向下逐格写 mossy_stone，直到 wy ≤ h
```

**实测（8 seed）**：

| 量 | 均值 | 范围 |
|---|---|---|
| 墩格数 | **13601** | 12332~14491 |
| 墩列数 | **3471** | 3145~3708 |
| 单列最大墩高 | **22** | 21~22 |
| 最密 column 墩格 | **1152** | 861~1483 |
| 墩涉及 column 数 | 69 | 65~72 |
| 墩可见侧面 | 7478 | 6977~7827 |
| 墩顶点（×4） | 29911 | 27908~31308 |
| **reserved（×1.25，逐 seed 取整后均）** | **37389** | = opaque 容量 **0.87%** |

**墩的形态核对（全部实测）**：

- 墩格 **100% 落在「产物未覆盖」的位置**（与产物 air / 实心零重叠，8/8 seed）。
- 墩格 **0 格穿地下房间**（房间 air 在最低实心之上）。
- 墩顶面 **100% 被建筑实心盖住**（3471/3471 列）⇒ 从上方看不到墩顶，只见墩身。
- 墩底面 **100% 坐在自然地表上**（`carveCaves` 的 top = h−4 < h ⇒ 地表恒实心，**零洞穴风险**）。
- 墩列 **0 列完全孤立**：3157 列水平邻建筑列、314 列只邻其他墩列 ⇒ **是连续台基，不是柱林**。
- 墩高分布（seed 12345）：1 格 882 列 / 2 格 336 / 3 格 460 / 4 格 613 / … / 21 格 9 列。
- 墩格分类（8 seed 均）：**上层件（阳台/塔楼）下方 6819 格 + 地下基座下方 6782 格 = 13601**。
- 墩可见侧面占「墩+建筑」总可见侧面的 **20.8%** ⇒ 不会抢戏。

**材质选 `mossy_stone`**（建筑主材，30503/65702 = 46%）：与墙体同色 ⇒ 观感是
「建筑自己的基座加高」而不是「外来土墩」。`mossy_stone` 是 opaque box，
**零新增几何、零新增贴图**。

⚠️ **墩必须在光栅化之后写**（或之前写但只写产物未覆盖格）：
本设计选**光栅化之后**，且逐格判 `column.blocks[idx] === 0` 才写
⇒ 永不覆盖产物（含产物 air，保护房间内腔）。

⚠️ **墩格要纳入植被让位索引**：墩格的水平邻居有 8155 次是「产物未覆盖的空地」
⇒ 树冠会从旁边伸进墩格。`jungleFortressCells` 的 `cells` 索引必须**含墩格**
（否则 v3.13c 修好的「树叶被切割」会以「树叶穿墩」形态复发）。
墩格是运行期派生的（依赖 seed 与 baseY），故索引要在 GEN 里按锚点算一次并缓存。

### DR-4 地下房间漏底修补（洞穴兜底，最小改动）

不整形后，`carveCaves` 的洞可能正好在地下房间下方 ⇒ 房间地板漏空。
**实测两类形态（8 seed 合计）**：

| 形态 | 格数 |
|---|---|
| ① 地下房间 air 格正下方第一格是洞穴（且非产物格） | 5 |
| ② 房间地板（实心且上方是 air）正下方第一格是洞穴 | 18 |
| 两类合计（去重） | **23** |
| 迭代补到「补的格下方也是实心」后总计 | **74**（均 9/seed，max 49） |

**修法**：对每个「地下房间 air 格」与「房间地板格」，检查其正下方第一格：
若它既非产物实心、也非产物 air、且是洞穴空气 ⇒ 写 `stone`；
再对补的格迭代同样检查（实测 ≤9 轮收敛，seed 4242 最深）。

⚠️ **必须排除「下方是产物 air」**：那是房间内部竖井（正常），
不排除会多补 116 格（seed 4242 实测）把竖井填死。

⚠️ **不能用「逐列从最低格向下填到连续 2 格实心」的粗口径**：
实测那样要填 36026 格（均 4503/seed），是精确口径的 486 倍，
且会把房间下方的天然洞穴整片填实（超出「兜住地板」范围）。

### DR-5 观感指标（实测，8 seed 均值，作为验收冻结值）

| 指标 | 现状 | 新方案 | 口径 |

| 地下基座可见 | 0 / 30227（0%） | **13842（45.8%）** | 高于地表且水平四邻至少一侧地表低于它（逐 seed 41.7~48.7%） |

| 地上房间 air 被埋（dy>0） | 0 | **832** | 整列全埋 225 列（逐 seed 205~263） |
| 地形改动列数 | 24885（占地内被削） | **0** | 与 `generateHeight` 逐格比对 |
| 地形相邻高差 max | 0（压平） | **1**（自然） | 占地内 |
| GEN 写入格数 | ≥258081（占地削平 176843 + 产物 81238，不含铺地表与填实） | **94839**（墩 13601 + 产物 81238） | **降 ≥63%** |

**「地上墙被埋 9.7%」是有意保留的**：原版就是「低处埋、高处露」，
被埋的 3315 格里 dy0 地板层不算（那与地表齐平），真被埋的是 dy1~6 的墙脚
（实测分布 dy1:1055 / dy2:796 / dy3:550 / dy4:557 / dy5:255 / dy6:103）。
**地上实心整列全埋 718 列**（顶高 ≤3 格的矮墙/台阶 524 列 + 顶高 >3 格的房间 194 列）；
**地上房间 air 整列全埋 225 列**（两个口径不同：一列可能实心全埋但 air 不全埋）。

⚠️ **这不是缺陷，是用户要的「嵌入感」**。若用户实玩后觉得埋太多，
调 `baseY` 的分位数（p85 → 埋 2235 格 / 露基座 16100 / 墩 18152；p100 → 埋 0 / 露基座 25421，
但墩涨到 51933 格）。**分位数是唯一旋钮**，不动其他逻辑。

### DR-6 瞬移落点

落点仍是「占地东缘外 6 格、z 取锚点中线」（v3.13 口径不变）。
**y = 该列自然地表 + 1**（地形零改动 ⇒ 自然高度就是真实地表）。

实测 8 seed：落点 (x, y, z) 的 y 为 **5 或 6**（现状是 2~3）。
落点处**无结构、无墩**（缘外 6 格）⇒ 玩家站在自然地面上，
要塞地板比玩家高 **3~4 格** ⇒ 抬头看要塞，正是「宏伟」的观感。

⚠️ **用 baseY+1 会悬空 4~5 格**（8 seed 实测），必须用自然地表+1。

⚠️ **`tests/jungle-fortress.spec.mjs` 的冻结落点 y=3 必须改为 6**（seed 12345），
且断言文案从「整形后地表+1」改为「自然地表+1」。

- **密度/树种/高度判据全部不变**（仍转调 `rollVegetation(…,'FOREST',…)` + `jfTreeKept` 减半）。
- **地表口径改为自然高度**（`jungleFortressSurfaceYAt` 新语义）。
- **让位索引含墩格**（DR-3）。
- 空地列数：整形区（占地+16）内产物无实心列 **25590**（占地内 **14454**，含实心列 10510，

- 占地内空地列的自然 h 相对 baseY 的差分布（seed 12345）：
  −9:54 / −8:703 / −7:1539 / … / 0:1885 / +1:857 / … / +6:2

  ⇒ 土贴着外墙，与「埋墙」一致。

### DR-8 apply.js 层序

阶段 2.95 改为：

```
① rasterizeStructure('jungleFortress', wx, baseY - (floorRow-1), wz, …, false)
② fillJungleFortressPiers(column, anchor, seed, registry)   // 墩 + 漏底修补
```

⚠️ **顺序选「先光栅化后墩后裙边」**：墩守卫 `blocks[idx]===0` 读世界方块，
先光栅化能确保「产物已写入的格不被墩覆盖」。裙边只抬非建筑列，与墩/产物零重叠。
（实测墩格恒在产物未覆盖处且恒高于自然地表 ⇒ 先墩后光栅化也安全，

### DR-10 接壤阶梯过渡裙边（用户 2026-11-18 追加裁定，载荷性）

**问题**：结构抬升后，边缘墙脚基座顶高于周边自然地面 10~13 格（8 seed 实测 34 处墙脚），
墩顶最高高于自然地面 21 格。若不做过渡，接壤处就是垂直悬崖。

**方案**：以**边缘环（占地最外圈 628 列）的地面顶**为源，向**内外两侧**做
Lipschitz 阶梯包络（每向外/向内一步地面降 1 格），只抬不削：

```
源值 source(e) = 建筑列 ? baseTop(e)−1 : (pierTop(e) ?? nat(e))     // e ∈ 边缘环
过渡带 band = 占地内侧 R=12 格 ∪ 占地外侧 BW=22 格
T(x,z) = max( nat(x,z), max_{e∈边缘环} ( source(e) − dist4(e,(x,z)) ) )
         其中 dist4 为 4 邻域最短路，**建筑列/保护列/湿列不可穿越也不被抬**
建筑列地面恒 = nat（基座/墙脚可见性按 nat 判，裙边不盖建筑）
```

**三个屏障（缺一即静默退化）**：
- **建筑列**（`baseTop.has`）：不抬（裙边不盖建筑，基座照露）；但它是源。
- **保护列**（露出的地下房间/竖井 air 所在列，`prot`）：不抬（否则埋掉用户要的裸露）。
- **湿列**（`nat ≤ SEA_Y`）：不抬也不传播（防假水面，红线 1）。

**材质**：裙边是「自然地形阶梯」⇒ 顶面 `surfaceTypeOfBiome(getBiome(...))`（FOREST→grass），
下方 `dirt`（与周边 biome 一致，**不是** mossy_stone）。8/8 seed 裙边列 biome 恒 FOREST。

**实测（8 seed，R=12 / BW=22）**：

| 判据 | 实测 | 口径 |
|---|---|---|
| 过渡带内非建筑地面相邻高差 | **max 0（≥2 为 0）** | 带内非建筑非保护非湿列 |
| 过渡带内缝（带↔内部 nat） | **max 0（≥2 为 0）** | 带内缘与内部自然列 |
| 外侧地面相邻高差 | **max 1（≥2 为 0）** | 占地外非湿列 |
| 边缘墙脚基座顶→外侧地面 | **max 2** | 1 格台阶 + 建筑立面（非地形悬崖） |
| 建筑立面（相邻墙脚基座高差） | max 3 | 建筑自身，不算地形 |
| 基座可见率 | **45.8%（不降）** | 按 nat 判，裙边不盖建筑 |
| 露出地下 air 被埋 | **0** | 保护列零抬升 |
| 湿列被抬 / 保护列被抬 | **0 / 0** | 屏障生效 |
| 裙边填方 | 内 655 格/170 列 + 外 2317 格/557 列 = **2972 格** | 只抬不削 |
| 裙边最大抬升 / 实际带宽 | 11 格 / 11 格 | 外侧阶梯坡 |
| 裙边可见侧面 / 顶点 / reserved | 1922 / 7687 / **9609** | opaque 容量 0.22% |
| 瞬移落点 y | **5 或 6（不变）** | 落点在带外缘，裙边未抬到该处 |

⚠️ **为什么是「内外两侧」而不是「只外侧」**：只抬外侧时，内侧自然边缘列（nat=0）
紧邻外侧裙边（9~11）会形成 9~11 格沟槽（实测 8 seed 跨界 max 9~10）。
内侧 R=12 格缓坡把边缘自然列抬到与墙脚/外侧裙边平滑衔接，消除沟槽。
**内部非带列一律 nat** ⇒ 基座可见率不降（实测 45.8% 与无裙边时逐位相同）。

⚠️ **为什么 R=12 / BW=22**：最大源值抬升 11 格（墙脚基座顶−nat），每步降 1 ⇒
12 步内降到 nat（R=12 足够）；外侧同理 BW=22 留余量。实测 R=10 与 R=14 结果逐位相同
（带内突变都已 0），取 12 为冻结值。**换地形公式后若抬升 >12 需重标 R/BW**。

⚠️ **裙边格要纳入植被让位索引**（同墩格 DR-3）：裙边抬升列的地表变了，
树/草的落点 y 要用 `jungleFortressSurfaceYAt`（新语义 = 裙边后地面），不得用 nat。

⚠️ **`jungleFortressSurfaceYAt` 新语义 = T(x,z)**（裙边后地面），是植被/瞬移/单测的唯一权威。
裙边包络在 GEN 里按锚点算一次并缓存（WeakMap，同 `jungleFortressCells` 手法）。
