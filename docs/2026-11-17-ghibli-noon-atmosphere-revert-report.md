## 2. 三条硬约束（实测证据，重做时直接采信）

### 2.1 PCFSoftShadowMap 在 r185.1 WebGPU 上不可用 —— 已再次复现

同一 page 内只切 `renderer.shadowMap.type`，其余变量全冻结（均匀平台 + 柱，正俯视）：

| type | 影区 A | 开阔 B | 影区/基线 | 开阔/基线 | GPU 错误 |
|---|---|---|---|---|---|
| 3 VSM | 143.3 | 148.4 | 0.968 | 0.999 | 无 |
| 2 PCFSoft | 81.6 | 81.9 | **0.551** | **0.552** | `GPUValidationError: ShadowDepthTexture usage (TextureBinding\|RenderAttachment)` + `Invalid CommandBuffer` |
| 1 PCF | 81.6 | 81.9 | 0.551 | 0.552 | 同上 |

关键读数：**PCF 两档下开阔区与影区一起塌到同一个值** ⇒ 不是「阴影变软」而是「阴影整片失效」。
AGENTS.md 记的红线在 r185.1 仍然成立。

另测 `shadow.bias ∈ {0, −0.0005, −0.002}`：像素差 **≤0.1**。VSM 走 `compareFunction = null`，
bias 几乎无感 ⇒ **「调 shadow.bias 消接缝」这条路在本仓无效**。

### 2.2 `#88CCFF` / `#7C9A5E` 不能按原色相当乘数

本仓 `sunColor` / `ambientColor` 是**均值 ≈1 的相对乘数**，不是绝对灯色。
CPU 屏幕口径（`sunTermRGBFor` × `hemiFactorFor` × 基色 0.5 → ACES → sRGB）：

| 方案 | 背光面 ±X | 朝下面 −Y | 顶面 +Y |
|---|---|---|---|
| 现状（中性） | `129,129,129` | `108,108,108` | `206,206,206` |
| 环境 = `#88CCFF` 原色相（均值 1 → R 0.399 / B 1.622） | `71,130,166` **R−B −95** | `59,112,149` | `196,206,213` |
| 彩色半球（上 `#88CCFF` / 下 `#7C9A5E`） | `97,144,144` R−B −47 | `110,144,73` **R−B +37** | `153,206,223` R−B −70 |
| **保色相、幅度 0.15** | `124,131,138` **R−B −14** | `107,114,120` | `207,207,204` R−B +3 |

原色相会把石头变蓝砖、草地变蓝。幅度扫描（背光面 R−B）：**0.15 → −14 / 0.25 → −23 / 0.30 → −27**。
用户当时裁定「保色相、衰减幅度」，故取 0.15。

### 2.3 「太阳强度 1.4」在本仓没有对应的自由参数

`SUN_INTENSITY = (1 − SUN_AMBIENT) / NOON_SUN_Y`，是**不变式派生值**，
保证「正午顶面亮度 ≡ 1.0」这条零回归锚点。写成 1.4 会直接破坏该锚点。
1.4 是 three 受光管线（`MeshStandardNodeMaterial`）的灯强度口径，本仓是 unlit TSL，
等价表达只能落在「迎光/背光对比跨度」上，由曝光与色温共同决定。

同理，场景里的 `DirectionalLight` / 加 `HemisphereLight` **对体素世界零影响**——
它们只服务枪的 PBR 高光与阴影贴图。

## 3. 标定数据表（可复用）

### 3.1 太阳方位角（真游戏页，3×3×3 stone 立方体，同机位）

| 方向 | 方位 | 顶面 | +X 面 | +Z 面 |
|---|---|---|---|---|
| `[0, 0.8, 0.6]` | 0° | 85.6 | **62.4** | 108.5 |
| `[0.30, 0.80, 0.52]` | 29.98° | 97.3 | **89.5** | 103.3 |
| `[0.42, 0.76, 0.50]` | 40.03° | 101.3 | 98.9 | 101.9 |

- 方位 0° 时 x 分量恒零 ⇒ **±X 两面 N·L 完全相同**（62.4 vs 62.4），方块只有「亮/暗」两档。
- **40° 被否决**：三个可见面趋同（101.3 / 98.9 / 101.9），立体感反而消失。

### 3.2 正午曝光（vd=8 开阔地平视，噪声底 0，只改 exposure）

| exposure | 天空 lum | 远景 lum | 近景 lum | 整屏 lum | 高光削顶（三通道 ≥250） |
|---|---|---|---|---|---|
| 1.00 | 164.1 | 204.1 | 199.3 | 189.4 | 0% |
| **1.05** | 167.1 | 206.5 | 201.8 | **192.1** | 0% |
| 1.10 | 170.4 | 208.6 | 204.0 | 194.6 | 0% |
| 1.15 | 173.2 | 210.5 | 206.0 | 196.9 | 0% |

整屏只 **+2.7 luma**（1.0 → 1.05）。顶/背对比同步从 1.581 降到 1.512（1.15 档）。
**这解释了「差别不大」的一部分**：曝光这一档的观感增量本来就在噪声量级附近。

### 3.3 雾 tint 幅度（同上机位，曝光 1.05，只改 tintMix）

| tintMix | 远景 RGB | 远景 lum | 天空区 | 近景 |
|---|---|---|---|---|
| 0.0 | 200.3 / 205.9 / 209.8 | 205.0 | 逐位不变 | 逐位不变 |
| **0.5** | 202.3 / 207.4 / 210.1 | 206.5 | 逐位不变 | 逐位不变 |
| 1.0 | 203.7 / 208.4 / 210.4 | 207.5 | 逐位不变 | 逐位不变 |

**满档（0 → 1.0）总共只有 ΔR +3.4 / ΔG +2.5 / ΔB +0.6**。
这是「差别不大」的**主因之一**：正午默认走「雾色融入天空」，远景本来就已经接近天空地平线色
（R≈200），再朝 `#C9E9F6`（R=201）混色几乎没有空间。

### 3.4 VSM 半影软化（snow_block 均匀平台 + 2×2×8 柱，影子窗口内逐像素梯度）

| radius | 平均梯度 | **硬边像素占比（\|∇\|>8）** | 中梯度占比 | 影区最暗 / 开阔最亮 |
|---|---|---|---|---|
| 2.6 | 1.273 | **1.02%** | 47.92% | 157.3 / 228.3 |
| 4.5 | 1.199 | 0.16% | 46.83% | 157.3 / 228.3 |
| **6.5** | 1.173 | **0.03%** | 47.19% | 158.0 / 228.3 |
| 9 | 1.147 | 0.02% | 47.30% | 158.0 / 228.3 |
| 关阴影 | 0.879 | 0% | 37.59% | 214.3 / 228.3 |

硬边像素降到 1/34，而影区深度几乎不变（157.3 → 158.0）⇒ 是「摊开边缘」不是「冲淡阴影」。
**但注意**：硬边像素本来就只占 1%，所以这项改动的**整屏观感权重很低**——
这也是「差别不大」的第三个来源。

### 3.5 半球 0.6 → 0.65

CPU 屏幕口径（基色 0.5）：朝下面 108 → 113（**+4.6%**），顶面逐位不变。

## 5. 判据踩坑（重做时最省时间的部分）

1. **半影宽度不能用影区中心亮度量**：radius 2.6 / 4.5 / 6.5 三档中心读数差 **≤0.1**（零判别力）。
   必须量**边缘梯度**。我为此换了 5 版探针才拿到有判别力的口径。
2. **stone 贴图逐格明暗 131~169**，单条剖面采样时纹理噪声完全淹没半影信号
   （实测剖面 oscillate 159/164/142/167）。改用 `snow_block` 均匀材质 + 沿 x 平均 12 格才干净。
3. **顶面采样对相机俯角敏感**：26.5° 俯角下顶面屏幕压缩 `sin(26.5°)=0.447`，
   3 格深只占 38.5px，而每格 ≈28.7px ⇒ half=5 的窗口混进边缘 AO 与侧面，
   实测顶面 103 < +Z 面 109.5（**几何上不可能**，CPU 口径同基色下顶/+Z 恒 >1.08）。
   改 50.1° 俯角 + half=3 后顶面读到 155，判据才成立。
4. **改 radius 后必须走真实刷新源**：只置 `shadow.needsUpdate` 会被 ShadowScheduler 节流吐回，
   四个档位读到的是同一帧。要 `shadowScheduler.request()` + 等够 2s。
5. **「世界稳定」不能只看队列/section 数**：传送 +400 格后那些计数全程稳态（0/0/0），
   而地形还在长 ⇒ 噪声底实测 **12.93**。必须等**连续两帧逐像素相同**（`fog-color.spec` v2.57 同款）。
6. **改一个风格字段会连带打掉一批「零回归」断言**：本轮共 4 条单测 + 2 条 Tier 4 钉死
   「正午色温中性」，它们的语义应改成「平台段逐位取 noon 原值」+「morning 端仍中性」，
   而不是放宽阈值。

## 6. 若将来重做，建议的方向（未验证，仅基于本轮数据）

本轮观感增量小的三个量化原因：曝光 +2.7 luma、雾 tint 满档 ΔR 仅 +3.4、硬边像素本来就只占 1%。
**这三项都处在「测得出但看不出」的量级**。若要肉眼可辨的晴空风，可考虑的方向（都需要重新标定）：

- 加大 `ambientColor` 的冷色幅度（本轮保守取 0.15；0.25~0.30 实测背光 R−B −23~−27，仍在不饱和区间）；
- 提高直射/环境对比（动 `SHADOW_FLOOR` 会牵动 v1.70 的一整套标定，代价大）；
- 换天空盒素材本身（本轮完全没碰 `assets/sky/day`，而它是画面里面积最大的颜色来源）。

**注意**：前两条都会撞上既有冻结断言，需要按 §5.6 的口径重标而不是放宽。
